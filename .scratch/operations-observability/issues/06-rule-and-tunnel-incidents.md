# 06: 追踪配置、监听与隧道异常

**What to build:** 管理员从首页的规则异常直接进入对应故障，查看配置应用、监听失败或隧道证据异常的起因、影响规则和恢复结果，并区分修复、停用、删除或新配置替代。某条规则异常不会遮蔽同组其他规则的真实状态。

**Blocked by:** 03（追踪控制离线故障与恢复过程）。

**Status:** ready-for-human

**方案依据：** 已确认方案第 2、4、5、7 节，任务 1、3、4、5 中规则类故障相关部分。

- [x] 以对象 ID、规则 ID、配置版本和原因码识别同轮配置、监听或隧道异常，并接入现有故障列表、详情、时间线及节点、入口组、规则筛选。
- [x] 首页规则影响和详情使用票 01 的相同判断；监听应用失败定位到对应规则，隧道证据异常定位到依赖该出口组的规则，不把无关规则一起归为失败。
- [x] 展示期望配置版本、已确认版本及安全的逐规则错误摘要；旧配置、旧连接或过期握手只能作为历史证据，不覆盖当前判断。
- [x] 缺少新鲜握手或报告时说明证据缺失，不把未知当成已证明业务失败；已有新鲜失败证据不会被另一项未知状态抹掉。
- [x] 展示关联出口和必要证据，但不推测目标应用是否正常，也不新增业务探测、出口选择策略或自动处理动作。
- [x] 异常解除需要符合现有业务规则的新证据；停用、删除或更换规则入口、监听及目标配置导致原故障结束时，使用配置变更或新版本替代的结束方式，不写成业务恢复。
- [x] 异常解除后同一规则再次出现问题生成新故障；反复处理同一证据不产生副本，对象更名或删除后历史仍可读。
- [ ] 页面支持从故障定位现有规则和入口组详情；通过鉴权查询验证异常、恢复、停用、删除、版本替代、旧报告迟到及同组规则隔离，前端构建通过。
