# 03: 追踪控制离线故障与恢复过程

**What to build:** 管理员可从首页进入“故障”，查看一次控制连接中断或离线事故的发生、证据变化和恢复过程，并在面板重启后继续追查同一故障。本票一次交付最小完整的持久化故障列表、详情、分页查询、时间线、保留期和后台恢复机制，后续票只增加新的故障来源与阶段。

**Blocked by:** 01（首页按规则展示异常与证据）。

**Status:** ready-for-agent

**方案依据：** 已确认方案第 4、5、6、7 节，任务 3、5 中与故障基础路径相关的部分。

- [ ] “监控”下新增故障入口，首页离线或控制失联项可进入对应详情；展示相关节点、入口组、规则及逐项判断，控制失联不直接显示为业务中断。
- [ ] 故障列表支持按状态、节点和时间筛选并分页；详情与时间线具有独立的鉴权查询、分页和明确的不存在或非法条件响应。对象不属于本故障时不能误显示为关联对象。
- [ ] 持久化故障摘要、对象引用与名称快照、证据来源、业务 ID 和版本、时间线去重键及后台处理进度。模型可容纳同一故障的多个入口组分支，不要求先接入其他类型的故障来源。
- [ ] 区分首次观察到控制中断、按现有规则确认离线、国内检测证据和恢复上线；可靠发生时间与面板观察时间分别保留。短暂且缺少持久证据的过程不能补造成精确历史。
- [ ] 区分异常状态与处理状态；恢复需有符合现有业务规则的证据，超时不自动算恢复；支持异常解除、管理员操作结束、配置变更结束、新版本替代的结束语义。
- [ ] 后台整理独立于网页访问及业务动作执行。暂停或故障写入失败时显示整理延迟并可重试，已有入口切换和换 IP 不因等待新增展示数据而受阻。
- [ ] 重启后继续同一故障及处理进度；重复处理不增加副本，旧事件只能补充历史，不能推进过期版本或使当前故障错误恢复。恢复后新的离线事故生成新故障。
- [ ] 追加迁移保留原业务状态；升级时仅为仍存在的异常建立“升级时发现”的记录，不虚构历史，无法可靠关联的旧事件仍可在原始事件日志查看。
- [ ] 已结束故障沿用事件保留天数，未结束故障保留；清理分批进行并保留必要处理进度，不会重新生成已过期历史，且不删除动作、额度、授权或配置版本。
- [ ] 节点改名或正常删除后，历史仍凭名称快照可读且不阻碍删除；目标对象已不存在时，跳转入口明确显示不可用。
- [ ] 从 HTTP 集成场景验证创建、查询、筛选、恢复、重启、重复处理、乱序、旧库迁移、保留期和存储失败隔离；页面验证列表到详情、重新打开历史及错误状态，前端构建通过。
