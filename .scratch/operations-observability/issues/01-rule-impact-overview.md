# 01: 首页按规则展示异常与证据

**What to build:** 管理员打开概览即可区分哪些启用规则存在转发异常、哪些影响待确认，并查看证据来源、时间及相关入口。首页与侧栏使用同一份后端判断，不再各自拼装相互矛盾的统计。本票交付从现有状态读取、统一查询到首页展示的完整路径，必要的共享状态整理随功能完成，不单独开纯底座票。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**方案依据：** 已确认方案第 1、2、3、6 节，任务 1、2、5 中与规则影响概览相关的部分。

- [ ] 实施前核对当前业务模型与已确认范围；当前范围是已实现的主备入口组、直连和隧道规则。全部发布、单节点规则、观测模式不作为本票前置依赖；若届时已合入，先核对适配，不把新增模式误算为主备或静默标为正常；范围变化先更新原方案并确认。
- [ ] 首页从统一的鉴权查询获取异常规则数、影响待确认规则数及原因摘要；侧栏引用同一份数据，同一规则关联多个原因仍按规则 ID 只计一次。尚未接入的故障统计明确显示未采集，不伪装为零或全部正常。
- [ ] 当前配置下的监听或应用失败只影响对应规则；某条隧道规则缺少有效握手时不把同组其他规则一起判为失败。节点级错误无法归因时明确说明范围待确认。
- [ ] 展示“检测到转发异常”“影响待确认”“未发现转发异常”“未启用或待部署”等状态，附原因、证据时间和来源；未知或过期证据不能显示为未发现异常，也不能凭缓存版本或在线状态断言业务可用。
- [ ] 控制连接中断不直接等于业务中断；离线节点可能继续使用缓存转发。当前有效失败证据与缺测同时存在时，保留已知失败并说明缺测，不用未知状态抹掉失败。
- [ ] 停用规则不计入启用规则异常统计；空项目、没有启用规则、未安装节点、维护期间和未绑定受管记录均有准确说明。未绑定记录时按成员展示证据，不猜测管理员实际使用哪个入口。
- [ ] 查询返回生成时间和数据完整性；刷新失败后页面保留上次数据并醒目标记更新时间与读取失败；首屏失败不显示零异常。会话失效沿用现有登录处理。
- [ ] 单次概览批量读取状态，查询期间不发起外部检测或业务动作，不按节点逐个查询；保持现有检测阈值、配置版本及自动处理行为。
- [ ] 行为测试覆盖逐规则归因、规则去重、控制失联但缓存转发、过期与乱序证据、未绑定记录、停用与空项目、鉴权和读取失败；页面验证首页与侧栏一致、错误后保留旧值及相关对象跳转，前端构建通过。
