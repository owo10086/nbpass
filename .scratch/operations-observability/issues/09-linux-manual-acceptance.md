# 09: 完成真实 Linux 环境人工验收

**What to build:** 在真实 Linux 面板、入口与出口节点、测试 DNSPod 域名和客户端上验证完整运维路径，确认页面表达与实际节点、DNS 及连接行为一致。需要由具备测试环境和控制权限的人执行；本票完成之前不宣称真实部署验收通过。

**Blocked by:** 08（完成全链路、故障隔离与规模验收）。

**Status:** ready-for-human

**方案依据：** 已确认方案第 9、10 节，任务 6 的真实环境验收部分；遵循项目人工验收工单惯例。

- [ ] 使用 Linux amd64 与 systemd 的真实测试环境，准备主备入口组、直连与隧道规则、出口节点、有效国内检测点、测试 DNSPod 记录及可控的换 IP 接口。测试动作仅针对明确授权的测试节点和域名。
- [ ] 正常客户端转发时核对首页及规则证据；中断节点控制连接后验证缓存转发仍可能继续，页面显示控制异常或影响待确认，不宣告业务中断。
- [ ] 仅使备用节点不可用，确认首页显示冗余下降；仅使一条规则监听或隧道异常，确认影响不会扩大到同组无关规则。
- [ ] 在可控条件下触发或模拟现有被墙判定，逐步核对“判定 → 入口切换 → 换 IP → 复检 → 回切”的时间线、组分支及首页进度，并观察实际客户端连接与解析结果。
- [ ] 核对服务商已写入而部分解析器仍有旧地址时的展示；缺少国内覆盖及传播未确认时不显示已生效，也不推断已有 TCP 连接迁移。
- [ ] 测试结果未确认冻结、没有候选和手动切换，确认详情解释准确并能进入原有处理页面；未点击对应确认操作时，普通查看不会触发外部动作。
- [ ] 在故障过程中重启面板，确认原故障继续、历史不重复；验证对象改名或删除后的历史可读，并检查升级时发现的既有异常不包含虚构时间线。
- [ ] 通过真实浏览器核对首页、侧栏、筛选分页、详情、窄屏、会话失效和刷新失败；页面中的证据时间、状态和现有运维工具观察值一致。
- [ ] 验收结果追加到相关工单 Comments，注明测试版本、环境、通过或失败项；缺少换 IP 条件或其他真实环境能力时明确标为未验，保留本票未完成状态，不将模拟测试冒充真实验收。
