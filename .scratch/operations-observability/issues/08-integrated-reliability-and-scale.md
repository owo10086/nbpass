# 08: 完成全链路、故障隔离与规模验收

**What to build:** 管理员在各种故障来源接齐后，使用统一首页、故障列表和详情可靠完成定位、追查及处理跳转。本票验收跨来源组合、重启和存储失败下的实际行为，并在既定规模下证明新的运维展示不会拖慢或改变现有自动恢复流程。

**Blocked by:** 05（追踪换 IP、复检与回切）、06（追踪配置、监听与隧道异常）、07（追踪 DNS 异常与传播结果）。

**Status:** ready-for-agent

**方案依据：** 已确认方案全部验收场景及三个交付检查点，任务 6 的自动化与发布构建部分。

- [ ] 首页最终包含四项业务关注指标、当前异常与影响、自动处理进度、最近结束故障；节点在线数和启用规则数仍可作为辅助信息，侧栏与首页取值一致。
- [ ] 一个主故障关联多个入口组时，首页一个主项、详情多个分支；不把仅仅同一节点或相近时间的独立事故强行合并。同一规则和同一换 IP 动作在跨来源聚合中不重复计数。
- [ ] 覆盖并通过正式方案中的全部核心验收场景，重点组合被墙、备用故障、控制失联、DNS 延迟、配置变更及人工操作，核对异常状态、处理状态、结束方式和跳转一致。
- [ ] 通过后台暂停、故障写入失败、重启、事件重放和乱序验证可见的整理延迟及恢复；首页请求失败保留旧数据，不展示假正常，错误消除后可以恢复刷新。
- [ ] 验证升级初始化、对象改名或删除、已结束故障过期、未结束故障保留；历史清理后不重新生成已过期记录，原动作、额度、授权和配置版本不受清理影响。
- [ ] 使用 100 节点、1,000 条规则、10,000 条已结束故障验证分页、批量读取及后台整理；对照相同业务负载下的控制报告、配置写入和自动动作完成情况，修复由运维模块引入的阻塞或逐节点查询，不虚构未测的延迟保证。
- [ ] 验证所有新增接口鉴权、非法筛选和分页条件、对象不存在及查询失败；时间线仅含安全摘要，不泄露换 IP 请求头、凭据或第三方原始响应。
- [ ] 完成前端构建、完整 Go 静态检查与测试、Linux amd64 发布构建，核对实际内嵌前端资源；验证结果只追加到相关工单 Comments，不额外生成报告或日志。
- [ ] 核对桌面与窄屏下首页、列表、详情、长错误摘要、分页、筛选及对象跳转；原始事件日志和既有操作确认流程仍可使用。
- [ ] 必要的项目说明、正式方案和 Linux 验收条目与交付一致；仅在本轮测试及交付资料核对完成后统一一次中文文档提交，代码提交按功能拆分使用中文。
