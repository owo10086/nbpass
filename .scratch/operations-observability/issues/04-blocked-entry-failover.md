# 04: 追踪被墙判定与入口切换

**What to build:** 管理员能从同一故障详情追查节点被墙判定、入口组策略决策、候选选择及入口切换的实际进度；离线事故触发的切换也接到原故障，避免在原始事件日志中手工拼接。不具备候选或证据时，页面准确解释为什么等待以及现有策略实际采取了什么动作。

**Blocked by:** 02（展示主备冗余与发布进度）、03（追踪控制离线故障与恢复过程）。

**Status:** ready-for-human

**方案依据：** 已确认方案第 4、5、7 节，任务 4 中被墙与入口切换相关部分。

- [x] 同一节点故障可关联多个入口组，每个组保留自己的策略、候选、期望版本及切换分支；同组和跨组相关规则按规则 ID 去重。

- [x] 无有效国内检测点、检测结果未知、无就绪候选时，展示具体等待原因；“先切后换”无候选时准确说明现有退化策略，不能一律宣称不发起换 IP。
- [x] 管理员手动切换、策略变化或新的期望版本使旧流程失效时，保留原过程并标明结束方式，不宣告业务恢复，也不允许旧结果覆盖新状态。
