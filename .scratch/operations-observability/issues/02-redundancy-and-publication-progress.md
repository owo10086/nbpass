# 02: 展示主备冗余与发布进度

**What to build:** 管理员能在概览和入口组相关信息中看清当前转发侧证据、备用能力以及域名发布进度。活动入口未发现异常而备用不可用时，提示冗余下降；入口切换期间分别展示面板期望、服务商最后确认及解析观察，不把请求提交当成切换已生效。

**Blocked by:** 01（首页按规则展示异常与证据）。

**Status:** ready-for-agent

**方案依据：** 已确认方案第 2、3、7 节，任务 1、2、5 中与冗余和发布状态相关的部分。

- [ ] 首页显示冗余下降入口组数及相关原因，基于当前有效候选条件区分活动入口与备用成员；备用未就绪不直接算作当前规则转发失败。
- [ ] 单成员入口组是正常使用方式，不因没有配置备用成员而必然报冗余下降；已配置备用的组按实际有效备用能力判断，并说明维护、被墙、规则未就绪或国内可达证据缺失等原因。
- [ ] 切换过程中同时保留期望成员、期望版本、服务商最后确认的记录值及确认时间、当前解析观察；仅有新期望不能覆盖最后确认的发布事实，无法可靠关联到节点的记录值按地址展示而不猜测成员。
- [ ] 页面区分期望已变更、服务商已写入、结果未确认、传播中、已生效和传播未确认；展示现有业务模块确认的结果，不按等待时长或 TTL 自行宣告生效。
- [ ] 旧 IP 缓存宽限、部分路径仍返回旧地址、缺少国内采样及采样过期有各自说明；不推断已有 TCP 连接是否存活或已迁移。
- [ ] 快速连续切换及迟到的旧版本采样不会覆盖当前期望；无受管记录、尚未首次发布和面板恢复核对期间明确显示实际限制，不展示虚假的活动入口或已发布状态。
- [ ] 首页摘要可定位相关入口组和解析监控对象；保持原有配置及操作确认流程，不新增 DNS 写入者或变更候选、切换、回切阈值。
- [ ] 集成测试覆盖备用失败、单成员组、服务商请求超时、写入成功但传播未完成、没有国内覆盖、连续切换和旧结果迟到；页面核对各阶段文案与数据来源一致，前端构建通过。
