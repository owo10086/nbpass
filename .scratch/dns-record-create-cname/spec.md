# 受管记录：按名字绑定、面板新建、A/CNAME 可选

Status: ready-for-agent

术语以 `GLOSSARY.md`「受管记录」为准，决定见 `docs/adr/0008`（部分取代 `0007`）。参考面板做法见下文「参考」。DNSPod 接口为腾讯云 API 3.0（`internal/dnsprovider/dnspod.go`）。

## Problem Statement

绑定受管记录时只能从下拉框里选 DNSPod 上**已经存在的 A 记录**：

- 想用的名字还没有记录，就得先去 DNSPod 控制台手动建一条，再回面板选。
- 全部发布组每加一个成员，都要先手动建一条同名记录。
- 名字现在是 CNAME 的，下拉框里看不到，也没法让入口组用 CNAME 发布。

参考面板没有一家要求预建记录，nbpass 这块明显缺失。

## Solution

- 三处绑定入口（主备入口组、全部发布组成员、入口节点）统一为：选账号 → 选主域名 → **输入主机记录名**（下拉里列出已有同名记录作为补全）→ 选**记录类型**（A / CNAME；只有主备入口组可选 CNAME）。
- 面板按名字、类型、线路查找：没有就**新建**（暂停状态）；有一条就**接管**；有多条就让管理员选接管哪一条；同名但类型不同的，列出来经管理员确认后**改成所选类型再接管**。
- 新建记录固定用「默认」线路；接管已有记录时保留它原来的线路。
- 主备组选 CNAME 时，组记录 CNAME 到活动入口那个入口节点自己的受管记录（例如 `app` → `hk1.example.com`）；入口切换改 CNAME 目标，节点换 IP 只改节点自己的 A 记录。
- 面板依旧**不删除**任何记录。

## User Stories

1. 作为管理员，我给入口组绑定记录时直接输入 `app`，DNSPod 上没有这条记录，面板替我建好（暂停状态），首次发布时启用；我不用打开 DNSPod 控制台。
2. 作为管理员，我输入的名字在 DNSPod 已有一条同类型、同线路的记录时，面板直接接管它，绑定结果里显示它的当前值、TTL、启用状态。
3. 作为管理员，同名同类型有多条（多线路或同线路多条）时，面板列出来让我选接管哪一条，或者新建一条「默认」线路的记录。
4. 作为管理员，同名记录的类型和我选的不同（例如 `app` 现在是 CNAME，我选了 A），面板列出这条冲突记录的类型、值、线路，我确认后它被改成所选类型并接管；我不确认就不改任何东西。
5. 作为管理员，我给主备入口组选 CNAME：组记录指向活动入口节点自己的受管记录域名。入口切换时面板把 CNAME 改到新活动入口的节点记录域名；节点换 IP 时只更新节点记录，组的 CNAME 不动。
6. 作为管理员，主备组用 CNAME 时，没绑定节点记录（或节点记录还没首次发布、未启用）的成员不能成为活动入口，成员列表标注「缺节点记录」；首次发布要求首选入口满足这一条，否则拒绝并说明。
7. 作为管理员，主备 CNAME 组的活动入口所在节点，它的节点记录不能解绑或更换，界面提示先切走。
8. 作为管理员，全部发布组和入口节点的记录类型界面上只显示 A，并说明原因（CNAME 只能有一个值 / 节点记录要指向 IP）。
9. 作为管理员，给全部发布组加成员绑定记录时，主机记录名固定为组域名；有未被其他成员占用的同名同线路 A 记录时，我选接管哪一条或新建；没有时面板直接新建一条暂停的记录，按现有加回规则启用。
10. 作为管理员，解绑、更换绑定或删除绑定对象后，面板新建过的记录和接管的记录一样保持原状，界面提示「记录未删除，如不再使用请到 DNSPod 手动删除」。
11. 作为管理员，新建时网络超时等结果未知，面板不会重复建记录：它先读回同名记录核对，找到唯一一条匹配且未被认领的就认领；找不到或不唯一时提示我重新绑定，不自动再建。
12. 作为管理员，解析监控对 CNAME 组仍以活动入口节点的面板确认地址为期望（解析结果沿 CNAME 落到 IP）；记录核对另外比较 CNAME 目标，目标不符按现有偏差写回流程处理。

## Implementation Decisions

**服务商接口（`internal/dnsprovider`）**
- 新增 `CreateRecord(ctx, auth, domain, Record) (recordID string, err error)`：DNSPod `CreateRecord`，传 `SubDomain`、`RecordType`、`RecordLine="默认"`、`RecordLineId="0"`、`Value`、`TTL`、`Status="DISABLE"`；返回 `RecordId`。错误分类沿用 `call()`：明确拒绝与结果未知分开。
- `WriteRecord` 放开类型限制为 A 或 CNAME；改类型接管即一次 `ModifyRecord`，带上新类型、新值与原线路。CNAME 值统一写成不带末尾点的完整域名，比较时忽略末尾点和大小写。
- 新增按名字查找：复用 `listRecordPages(subDomain=名字)`，返回同名全部记录（各类型、各线路），供绑定决策使用。
- 上线前用真实账号验证两件事：`ModifyRecord` 能否直接改类型（A↔CNAME）；同名同线路已有 A 时新建 CNAME 的错误码（预期被拒），据此给出友好提示。

**绑定接口**
- 三个 PUT（`/api/entry-groups/{id}/managed-record`、`/members/{node}/managed-record`、`/api/nodes/{id}/managed-record`）请求体改为：`account_id`、`domain`、`name`、`type`（`A`/`CNAME`），可选 `record_id`（多条时指定接管哪条）、`convert_record_id`（确认改类型的那条）、`create: true`（多条时选择新建）。旧的仅 `record_id`/`line_id` 请求体不再接受，前端同步改。
- 决策顺序：
  1. 列出同名记录。
  2. 同类型候选恰好一条且未指定 → 接管。多条且未指定 `record_id`/`create` → 返回 409 和候选列表。
  3. 没有同类型候选：
     - 有异类型同名记录且未给 `convert_record_id` → 返回 409 和冲突列表。
     - 给了 `convert_record_id` → 改类型接管。
     - 都没有 → 新建。
  4. CNAME 额外要求同名同线路下除被转换那条外没有其他记录，否则 409 列出。
- 归属唯一性检查、`bindRecordTx`、解析监控登记、「已开始发布的主备组不能重新绑定」等现有约束保持不变；新建 / 改类型发生在事务提交前，失败则不落库。
- 新建在绑定请求内同步完成，不落库新建意图：结果未知时立即按名字读回，只认领本次之前不存在、且类型、线路、值都与请求一致的唯一一条；读不到或不唯一时让管理员刷新后重新绑定，面板不自动重发（重新绑定时那条记录会作为同名候选出现，可直接接管）。

**初始值**
- 主备组 A：首选入口的面板确认地址；CNAME：首选入口节点记录的完整域名（无则拒绝绑定 CNAME 并说明）。
- 全部发布成员：该成员的面板确认地址。
- 入口节点：面板确认的节点地址。
- 一律暂停创建；之后按各自现有的首次发布 / 加回规则启用。

**主备 CNAME 组的入口动作（协调器，ADR 0005）**
- 受管记录增加类型字段（迁移：现有记录为 `A`）。入口切换、回切、偏差写回对 CNAME 组写的是目标节点记录的完整域名。
- 候选资格增加：成员节点绑定了节点记录、已首次发布、已启用，且记录值等于面板确认地址。
- 换 IP 成功后只更新节点记录；组记录在 CNAME 模式下跳过地址同步。
- 节点记录解绑 / 更换：若该节点是某个 CNAME 组的活动入口，拒绝（409「请先把入口组切走」）。

**前端**
- `ManagedDNS.tsx`、`AllPublishDNS.tsx`、`NodeManagedRecord.tsx` 改为「主机记录名输入框（带已有记录补全）+ 类型单选」；409 候选 / 冲突以列表展示并提供「接管这条」「新建」「改成 A/CNAME 并接管」操作。
- 绑定结果显示记录是否由面板新建、类型、CNAME 目标。

## Testing Decisions

- `dnsprovider`：`tc3Server` 覆盖 `CreateRecord`（参数含 `Status=DISABLE`、默认线路）、改类型 `ModifyRecord`、CNAME 值归一化。
- `fakedns`：支持 `CreateRecord`、改类型、同名 CNAME 与其他记录共存时拒绝、新建超时（实际已建）。
- 集群验收（面板 HTTP）：
  - 没有记录 → 新建并首次发布启用。
  - 一条 → 接管；多条 → 409 后指定接管。
  - 异类型 → 409 后确认改类型。
  - 新建超时 → 读回认领、不重复建。
  - 全部发布加成员自动新建。
  - 主备 CNAME：切换改目标、换 IP 只改节点记录、缺节点记录的成员被跳过、活动入口节点记录不能解绑。
- 现有 `TestManagedDNS*`、`TestAllPublish*`、节点记录测试改用新请求体后全部通过。

## Out of Scope

- 删除记录（任何情况下都不删）。
- AAAA、MX、TXT 等其他类型；全部发布组和入口节点用 CNAME。
- 新建时选择非「默认」线路（需要时先在 DNSPod 建好再接管）。
- 已首次发布的主备组改记录类型（要换就新建组）。
- DNSPod 以外的服务商。

## 参考

|---|---|---|---|
| Forwardx | 输入完整域名，无则建；同名多条整组同步 | 只删多余，解绑不清理 | 旧版组配置：组域名 → 成员入口域名 |

| RelayX | 填域名，按节点上下线增减 IP | 下线移除 IP | 不做 |
