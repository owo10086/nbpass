# 入口组发布模式、单节点规则与观测模式

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，关键决定见 `docs/adr/0005`、`0006`、`0007`；参考 ZeroForwarder「服务器组」文档（https://www.zeroforwarder.com/docs/server-groups/）。v1 已实现的入口切换、回切、被墙策略、跨组换 IP 见 `.scratch/nbpass-v1/issues/24`、`25`、`27`、`31`、`32`。

## Problem Statement

现在入口组只有一种发布方式：受管记录只指向一个活动入口，其余成员闲置做备用。管理员有几台同等质量的入口时，没法让它们一起分摊流量，坏一台就要整组切换。

规则只能挂在入口组上，只有一台入口的线路也得先建一个单成员入口组。

自动入口切换、换 IP 一旦误判就会直接改 DNS、换掉 IP，新建的组没有办法先看看判断准不准再放开自动动作。

## Solution

- 入口组建组时选择发布模式：主备（现状不变）或全部发布。全部发布时，每个成员各绑定一条管理员在 DNSPod 预先建好的同名记录；健康成员的记录启用，异常成员的记录暂停（摘除），恢复后再启用（加回）；自动摘除不低于最少保留数。
- 转发规则的入口可以是单个入口节点或一个入口组。入口节点可选绑定一条受管记录，受控换 IP 后面板把它改成新 IP。
- 入口组增加观测模式开关：开启后该组的自动动作只记录"本来会做什么"并通知，不执行。

## User Stories

1. 作为管理员，我建入口组时选择主备或全部发布；建好后不能更改，界面说明要换模式就新建组再改规则入口。
2. 作为管理员，我给全部发布组的每个成员绑定一条已有的同名同线路 DNSPod A 记录，记录可以是暂停状态；成员没绑齐时该组不能发布。
3. 作为管理员，我手动首次发布全部发布组：当时健康的成员（在线、就绪、未被墙、不在维护中）记录写成其地址并启用；其余成员有面板确认的地址时写成其地址并暂停，没有时只确认暂停、保留服务商原值并提示"地址待确认"；没有一个健康成员时拒绝发布。首次发布前，组不做任何自动摘除、加回或启用。
4. 作为管理员，全部发布组的成员离线且国内检测点确认不可达、或被墙时，它的记录被自动暂停；未就绪不触发摘除。
5. 作为管理员，首次发布后处于暂停的成员（被摘除的、首次发布时不健康的、后来新增的）在线、就绪、未被墙、不在维护中、当前地址有有效国内连通证据，且连续 6 次 10 秒检查成功后，记录自动启用；记录地址、面板确认的地址和健康证据的地址必须一致，不一致时保持暂停并提示先同步地址。
6. 作为管理员，我能手动摘除某个成员，之后它不会被自动加回；我手动加回时立即启用它的记录并恢复自动规则（成员仍异常时界面先警示，随后可能被再次自动摘除）。
7. 作为管理员，我为全部发布组设置最少保留数（默认 1，最小 1）：自动摘除不会让启用记录少于它；超过成员数时按成员数算；不约束首次发布和手动操作，但任何操作都不能让全部发布组一条启用记录都不剩。
8. 作为管理员，全部发布组的成员被墙时先被摘除；节点开了换 IP 就换；新地址确认后该成员记录改为新地址并保持当时的启用或暂停状态；新 IP 复检通过并满足加回条件后才启用。
9. 作为管理员，我在入口组页看到每个成员记录的地址、启用或暂停、摘除原因、是否手动锁定，以及启用被服务商拒绝等异常。
10. 作为管理员，我建规则时可以直接选一个入口节点作为入口，不必建单成员入口组；直连和隧道规则都可以。
11. 作为管理员，同一节点上单节点规则和它所属入口组的规则共用监听端口空间，冲突、随机端口与环路检查都把两者算在一起。
12. 作为管理员，单节点规则的流量、连接数、隧道授权与凭据轮换和组规则一样正常工作；规则在入口节点和入口组之间改动时，流量累计不丢、旧入口授权按 ADR 0006 撤销。
13. 作为管理员，规则 JSON 导出包含单节点入口；旧格式文件仍能导入。
14. 作为管理员，我可以给入口节点绑定一条受管记录，首次发布时写入地址并启用；受控换 IP 成功后面板把记录改为新地址；节点地址在面板之外变化时只通知，我在节点页手动同步，同步覆盖该节点的节点级记录和它在各全部发布组的成员记录（各自保持启用或暂停状态）。
15. 作为管理员，承载单节点规则的入口节点开了换 IP 时，被墙后会自动换 IP，不需要属于任何入口组。
16. 作为管理员，我可以为入口组开启观测模式（新建组默认关闭）；开启期间该组的入口切换、回切、摘除、加回、偏差写回和因该组申请的换 IP 都只记录并通知"本来会做什么"。
17. 作为管理员，节点所属的任一入口组开着观测模式，该节点就不自动换 IP；手动操作及其后续 DNS 更新不受观测模式限制。
18. 作为管理员，解析监控对全部发布组以已发布成员地址集合为期望：没有集合外地址就算一致；摘除在所有路径都不再返回该地址后算生效，加回在任一路径返回该地址后算生效；被摘除成员的地址仍由其他启用成员发布时，摘除以服务商确认暂停为完成，并显示"该地址仍由其他成员发布"。
19. 作为管理员，备份恢复后，所有受管记录（入口组、全部发布成员、入口节点）都逐条核对身份、地址和启用状态后才放行自动动作。

## Implementation Decisions

### 受管记录模型（票 01）
- 受管记录的归属三选一：主备入口组、全部发布组的某个成员、入口节点。同一条远端记录以服务商、规范化域名和记录 ID 标识，全局只能有一个归属；账号只是访问凭据，账号或凭据别名不能绕过唯一性。
- 入口动作的对象从"入口组"改为"一条或多条受管记录"：每个动作逐条持久化记录身份、绑定代次、旧值和新值、旧新启用状态，以及每条的确认结果；组级期望版本保留，过时的自动动作按版本失效。动作部分成功时逐条记录，未确认的那条先读回核对，不把部分成功标成整组完成。
- 入口节点的记录用节点级期望版本，规则与组相同。
- DNSPod 接口新增暂停、启用；改值必须显式带上记录原来的状态（`Record.Modify` 省略 `status` 时默认启用）。绑定与读取允许暂停的记录。服务商明确拒绝（如 `500025` A 记录负载均衡超限）与结果未知分开处理：明确拒绝记为失败并通知、保留其他记录已成功的部分；结果未知先核对。
- 解绑、更换记录或删除节点、入口组时，旧记录保持原状并提示管理员；该记录有未完成动作时拒绝。成员移出全部发布组时先暂停它的记录、确认后再解绑；它是唯一启用记录时拒绝移出。
- 备份恢复核对与放行改为逐条记录；旧版本迁移保留未确认动作。

### 单节点入口（票 02、03）
- 转发规则的入口是"入口节点或入口组"二选一，数据库、API、导入都拒绝两者都填或都不填。凡是"规则的实际入口节点集合"都用同一个函数求出：同步、就绪、隧道授权与轮换、流量来源登记与连接数、随机端口、端口冲突、环路检查、节点删除引用。
- 规则 JSON 格式升到 2，新增单节点入口字段；导入同时接受格式 1（入口必为入口组）。
- 换 IP 的申请用途新增"单节点入口"：节点承载至少一条启用的单节点规则、开了换 IP、被墙。
- 节点的上报地址与面板确认的地址分开保存。面板确认的地址只有受控换 IP 成功与管理员手动同步会改；上报地址与它不一致时只通知。所有绑定该节点的记录（节点级记录、全部发布成员记录）都以面板确认的地址为期望；主备组仍按当前活动入口处理。
- 入口节点记录的首次发布由管理员触发：写入地址后用明确的启用步骤启用，启用失败或结果未知时不标为发布完成。

### 全部发布（票 04、05、06）
- 发布模式存在入口组上，创建后只读；已有入口组迁移为主备，被墙处理策略只对主备组有效。
- 摘除、加回、改地址都是对单条成员记录的动作，经协调器执行；同一组多个成员同时被判摘除时，按最少保留数在一个事务里决定哪些摘、哪些保留。
- 先启用后暂停：涉及多条记录的发布或状态调整，必须先确认至少一条目标记录已启用，才能暂停最后一条原有启用记录；未确认的启用不计入保底。目标记录全部启用失败或结果未知时，保留最后一条原有启用记录，显示发布失败或部分完成。
- 首次发布前组不做自动摘除、加回或启用；首次发布后所有暂停的成员（被摘除、首发时不健康、新增）都进入自动加回判定；新增成员须先完成绑定。手动锁定的成员除外。
- 加回复用首选入口回切的候选检查，不以时间流逝代替样本。
- 跨组换 IP（票 32）的切离屏障扩展到全部发布组：换 IP 前该成员在所有全部发布组中先被摘除；因最少保留数摘不掉时照常换 IP 并在事件中记录影响。新地址确认后所有绑定该节点的记录改为新地址、保持原启用状态。

### 观测模式（票 07）
- 开关存在入口组上。所有自动动作在提交、以及调用外部接口前的最后一步都复核观测状态。开启时：尚未调用外部接口的自动 DNS 动作作废并记事件；尚未下发给节点的自动换 IP 许可作废并释放额度；已经下发的许可不撤回，按可能已执行继续核对；已经调用外部接口的动作照常核对结果，不当作取消成功。
- 开启观测前已下发或已执行的自动换 IP，确认新地址后的地址同步属于原动作的收尾，照常执行并保持各记录原启用状态；该收尾不触发切换、摘除、加回或偏差写回。
- 观测期间产生的"本来会做的动作"写入事件日志并发 Telegram，不占换 IP 额度、不改期望版本。关闭后按当时状态重新判断，不重放。
- 手动操作（手动切换、手动摘除与加回、首次发布、手动换 IP、手动同步地址）及其后续 DNS 更新不受观测模式限制。

## Testing Decisions

- 行为通过测试台用面板 HTTP API、假 DNSPod、假换 IP 接口和真实节点验证，与 v1 票保持一致。假 DNSPod 必须模拟：暂停与启用、`Record.Modify` 省略状态时默认启用、启用超限拒绝、调用超时。
- 迁移测试覆盖已有入口组变为主备、已有规则入口变为入口组、已有受管记录与未确认动作完整保留。

## Out of Scope

- 自动加入脚本（组安装链接、模板继承）。
- 可调确认时长、入口互测、丢包或延迟阈值、自测异常轮数可调。
- 面板自动新建或删除 DNS 记录。
- 已有入口组切换发布模式。
- 节点地址在面板之外变化时自动改 DNS。
