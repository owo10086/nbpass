# nbpass v1 规格审查

审查日期：2026-11-08。主要对象：[spec.md](/Users/macmini/Documents/Aixiaoji/nbpass/.scratch/nbpass-v1/spec.md)。已核对术语表、ADR 0001—0006 和上一轮设计审查第六节；未读取仓库外项目，未修改已有文件或提交 Git。

结论：已确认的范围取舍和主要阈值基本一致，未发现用户故事重新纳入已后移功能。但下列状态契约和验收缺口补齐前，`ready-for-agent` 状态偏早。严重程度：高＝可能错误执行、扩大中断或突破权限；中＝无法明确实现或验收；低＝表达问题。以下只列仍未解决的部分。

## 必须修改

### M01｜节点配置版本不能直接充当跨节点授权版本【高；A、B】

**位置：**Implementation Decisions／配置编译器“生成每个节点的配置快照”、控制服务“单调版本号”；隧道服务端“每个新流核对……配置版本”；故事 44、45。

**问题：**入口与出口的配置版本独立递增，可能分别为 12 和 7；规格没有定义流里携带哪个版本、出口如何比较。无关配置更新也可能使正常规则被拒。故事 45 只要求“先下发”，尚不保证出口已经应用授权。

**建议补入：**“节点配置版本只用于该节点的同步确认。逐流授权使用规则 ID 与独立的授权代次，由出口核对入口归属和该代次允许的目标。入口启用新规则或新授权代次前，须收到拟使用出口已应用对应授权的确认；未确认的出口不进入该规则候选。无关配置版本变化不撤销未变更的授权。”

### M02｜部分应用失败与重启缓存的语义缺失【高；B】

**位置：**故事 19—22、32、34；控制服务“已应用版本与逐规则错误”；控制客户端“最近一次成功应用的配置快照”。

**问题：**一个监听失败时，其他规则是否已生效、已应用版本是否前进没有定义。如果实际部分应用、缓存却仍是旧的完整成功快照，重启可能复活已经删除的规则。故事 32 的三种同步状态也没有容纳故事 21 的“待确认”。

**建议补入：**“逐规则报告实际生效版本和错误；节点已应用版本仅在整个快照应用成功后推进。部分成功时持久化实际生效状态，尤其是停用、删除结果，重启不得恢复已撤销规则。逐成员同步状态为未同步、正常、同步失败、待确认；组汇总保留失败和待确认的成员明细，不将部分成功标为正常。”

### M03｜切换候选和恢复窗口尚无完整判据【高；A、B】

**位置：**故事 22、62、64、65；关键参数／入口回切；上一轮 C14、C19 已采纳部分。

**问题：**当前“就绪”只有配置、监听和握手条件，控制离线、维护中或已被墙的节点仍可能满足；同节点跨组时，也没有区分本组与其他组的监听失败。C14 要求的新鲜国内可达证据未落入规格。“连续成功 1 分钟”没有采样来源、频率和失效规则，不能直接用两分钟一轮的自测计算。

**建议补入：**“本地就绪按节点—入口组计算，要求本组全部启用规则已应用、监听成功、每条隧道规则至少一个获授权出口握手成功。自动切换候选还须在线、非维护中、非被墙，并具备未过期的国内可达证据；无证据标未知。回切连续成功窗口按明确的周期性候选检查累计，失败、未知或样本过期即中断，不以时间自然流逝代替成功样本。其他入口组的独立规则错误不直接否定本组就绪。”同时在参数表填写采样周期与证据期限。

### M04｜未知轮的计数、恢复与补判收尾未定义【高；B】

**位置：**故事 71—76、92、94；节点模块／自测；Testing Decisions 场景 3、4。

**问题：**“异常、异常、未知、异常”是否认定被墙不明确；无有效检测点、部分缺报时如何结束该轮未定义；换后 3 轮全未知也可能被实现成“无改善”。正常自测如何清除疑似被墙、被墙和暂停状态亦缺少转换规则。

**建议补入：**“每轮最终结果为正常、异常或未知；任一有效检测点成功则补判正常，零有效结果不能判异常，缺报或执行错误不能补作失败。未补成确定结果的未知轮中断连续异常计数；正常轮清零并解除被墙状态。换后最多执行 3 轮，任一正常即恢复；3 轮均为有效异常才记无改善，无正常但含未知时记待确认，不累计无改善。正常自测解除暂停并清零连续无改善次数。”补判还须规定截止时间和迟到结果处理。

### M05｜换 IP 的执行去重和“未确认”终态仍不完整【高；A、B】

**位置：**故事 88—94；配置编译器、换 IP 执行器“状态持久化”“最多 5 次”；上一轮 C02。

**问题：**尚未明确一次性动作与可重放配置快照分离，也未要求节点在调用前持久化执行标记。面板重发许可或节点在调用后崩溃，仍可能重复调用。五次查询均是旧 IP，不能证明商家稍后不会执行；两个查询源不一致时也没有结论规则。

**建议补入：**“换 IP 命令独立于配置快照，绑定动作 ID、节点、旧 IP 和许可期限。面板预占额度，节点调用前持久化该动作已开始；相同动作只恢复观察，不再次调用。旧 IP 预查失败时释放预占。调用后失联只继续观察、记录。查询源不一致、查询失败或观察到期仍不能确定结果时，动作保持结果未确认，冻结该节点后续自动换 IP，直至核对或人工处理；不得仅凭仍见旧 IP 自动重发。”

### M06｜DNS 阶段缺少完成条件，传播等待可能阻塞故障切换【高；A、B】

**位置：**故事 55—59、65、67—69、102—106；入口动作协调器、解析监控；上一轮 C15、C16。

**问题：**“已生效”由哪些路径、几次结果认定未定义；全部采样失败时可能永远“传播中”。同组串行队列若等传播完成才释放，会挡住故事 65 的再次故障切换。也未明确递归偏差是否足以触发写回，以及同一受管记录能否被两个组绑定。

**建议补入：**“同一 DNSPod 记录只能归属一个入口组，绑定时读回并展示当前记录，首次发布须显式确定活动入口。写回只依据 DNSPod 实际记录与当前期望不符，递归采样差异不直接触发写回。传播观察按期望版本独立运行，不阻塞新的故障切换；新动作使旧观察失效。明确驻留起点、参与收敛判定的路径集合、所需成功次数和最长观察期限；无采样记覆盖不足或采样失败，到期记传播未确认，不标已生效。”

### M07｜升级超时同时被定义为未确认和回滚【高；A、B】

**位置：**故事 121、122；节点模块／更新服务“未在期限内回连就绪则回滚”；Testing Decisions 场景 8；上一轮 C22。

**问题：**新版本地转发正常、仅面板失联时，故事要求未确认，更新器却必须回滚。维护状态到期后如何重新评估离线也没有定义。

**建议替换更新服务末句：**“候选启动失败或本地业务自检失败时回滚；本地就绪但控制确认超时，保留运行版本并记未确认，重连后核对任务 ID、进程实例、版本和实际产物。维护状态有独立期限，到期重新评估当前证据，不把维护期累计的离线时长直接当作新的故障确认。”明确升级会中断该进程承载的已有连接。

### M08｜C23 的隧道及缓存兼容要求未落入规格【高；A、B】

**位置：**故事 124；控制服务“控制协议版本独立于软件版本”；上一轮 C23。

**问题：**目前只保证新面板接受旧节点，未保证新入口与旧出口互通，也未保证新版写入缓存后旧二进制能回滚启动。

**建议补入：**“控制协议、隧道协议、能力集和本地状态格式分别声明兼容范围。至少保证当前版与上一版节点在滚动升级期间隧道互通；不支持的能力不得提前启用。更新前保留旧版可读的配置和状态，回滚恢复相匹配的状态，且不得恢复已撤销授权或丢失动作去重记录。”

### M09｜旧备份恢复无法仅靠查询节点和 DNS 保证安全【高；B、C】

**位置：**故事 127、129；备份与面板升级 CLI；Testing Decisions 场景 9。

**问题：**DNS 当前值不能还原最近 24 小时的换 IP 尝试；旧库的配置版本也可能低于节点缓存。仅“核对实际状态”既无法证明不绕过额度，也可能使新配置一直被节点当成旧版本拒绝。

**建议补入：**“恢复时与节点核对配置版本高水位、动作执行记录及额度记录，新配置版本必须高于已确认高水位。无法重建最近 24 小时尝试记录的节点，暂停自动换 IP，直至记录补齐或保护窗口安全结束；无法核对的节点及入口组继续暂停相关自动写操作。恢复同时清理旧登录会话和安装票据，并规定数据库迁移失败时恢复的程序、数据库和密钥范围。”

### M10｜关键参数表尚不足以实施和验收【中；B】

**位置：**关键参数；故事 8、10、15、42、85、88、102、122、132、134；上一轮 C10、C19、C28。

**问题：**表中多处仍引用没有数值的期限或上限，尤其“最长观察时长”本身没有值；实现者无法统一超时和资源行为。

**建议：**补齐以下参数的默认值、单位、可调范围及超限行为：会话空闲/绝对期限、登录限流与校验并发；安装票据和换 IP 许可有效期；控制活性检测与全量同步周期；单次探测超时、单轮期限、证据有效期、抖动和并发；新连接总尝试预算；换 IP HTTP 超时/响应大小；DNS 最长观察时间及其与旧 TTL、负缓存的关系；证书有效期/重叠期限/离线入口未确认的处理；升级就绪和维护期限；连接、待拨号、流和缓冲上限及空闲策略。模板变量另列名称、类型和允许位置，避免故事 83、84 只有“支持模板”的空接口。

### M11｜早期切片依赖尚未交付的组与 DNS 能力【中；D】

**位置：**Further Notes／切片 1、2、4、5、6；故事 27、28、55、99。

**问题：**直连规则先依赖入口组，但切片 1 未交代基础入口组；入口组又被故事 55 定义为绑定 DNSPod。单出口隧道依赖出口组，但切片 2 未交代固定成员出口组。切片 4 的自动入组域名监控依赖切片 5；被墙策略②没有明确归属。直连的基础资源限制也不能等切片 2 才出现。

**建议改写对应切片：**“切片 1 包含单成员基础入口组、尚未发布的 DNS 绑定状态及直连资源限制；切片 2 包含单成员出口组；切片 4 先验收手动域名只读监控；切片 5 增加多成员、DNS 发布、入口组域名自动监控和被墙策略②；切片 6 增加策略①、③及出口换 IP。”每片补一条通过 API 创建配置、实际 TCP 验证及关键失败场景的完成条件。

### M12｜唯一自动化接缝的覆盖范围被表述得过满【中；C】

**位置：**Testing Decisions“只通过面板 HTTP API……假外部服务……localhost TCP”；故事 1、4、5、13—15、108、119—127。

**问题：**该接缝能验收核心逻辑，无法证明安装脚本、真实 systemd 更新器、CLI 密码重置/面板升级、代理 HTTP/2 长流、文件权限和实际 OS 指标采集正确；若替换了 TLS 或更新器实现，更不能据此声称生产安全链路已通过。重启、磁盘满和更新器目前也没有测试台驱动能力。

**建议补入：**“保留进程内集群测试台作为唯一自动化接缝；真实 gRPC 编解码、TLS/WSS 和 yamux 应在台内运行。测试台支持保留磁盘的核心重建、持久化故障及更新服务外部接口替身。安装、CLI、真实 systemd 替换与回滚、代理长流和 TLS 部署、文件权限、OS 指标与前端列为 Linux 人工验收项，逐项写明操作和通过条件；替身通过不代表这些部署项通过。”不需要增加第二套自动化接缝或前端自动化测试。

### M13｜必测场景遗漏安全前提和资源失败路径【高；C】

**位置：**Testing Decisions／必须覆盖的场景；故事 11、12、15、16、31、36、45、88、132—134。

**问题：**现有 12 场景集中在容灾组合，尚不能证明安装票据、会话撤销、执行许可、规则变更及资源上限这些安全前提成立。

**建议补入必测场景：**票据过期与并发重复兑换；改密撤销会话、吊销 token 断开已有流、伪造代理头与跨源写入被拒；出口授权未应用时入口不提前接流；配置部分失败后重启不复活撤销规则；批量导入预检失败不写入、实际 bind 竞争显式报错；许可过期或重复投递不换 IP、关键动作持久化失败不调用外部接口；半关闭、取消和达到连接/缓冲上限时清理资源且控制服务继续响应。均通过原测试台的公开行为验收。

### M14｜换 IP HTTP 的已采纳安全条款仍有漏项【高；A、B】

**位置：**故事 83—86；换 IP 执行器“禁止跨主机重定向”；上一轮 C09。

**问题：**跨主机限制仍允许同主机 HTTPS 降级到 HTTP；公网带凭据请求使用 HTTPS、代理使用规则和内网显式授权的具体范围未写入。

**建议补入：**“公网携带凭据的换 IP 接口必须使用 HTTPS 并验证证书；拒绝向明文降级的重定向。代理须显式配置，不隐式继承环境代理。内网授权绑定具体端点，初次请求及每次重定向均校验实际目标，不能把一次授权解释为允许访问全部内网。”

### M15｜节点证据身份与更新器文件边界仍缺要求【高；A】

**位置：**控制服务“token 认证”；故事 120、节点模块／更新服务；上一轮 C08、C21。

**问题：**已认证节点能上报谁的状态、能提交哪些检测任务结果未明确；固定安装路径也没有覆盖符号链接替换及不受信任的暂存文件。

**建议补入：**“上报身份取自已认证控制会话，节点只能上报自身状态和分配给自身、尚有效的检测任务；消息自带身份不能覆盖认证身份。更新器验证任务来源和固定产物，不跟随不受信任的路径或符号链接，校验后至原子替换前防止产物被替换；密钥、缓存和更新暂存文件规定所属用户及最小读写权限。”

## 建议修改

### S01｜清理术语表 Avoid 用词【低；A】

**位置：**Problem Statement“TCP 端口转发”“入口挂了”；故事 52“目标挂了”。

**问题：**仍出现术语表避免使用的“端口转发”“挂了”。

**建议替换：**分别改为“TCP 流量转发”“入口离线”“目标不可达”。部署语境中的“明文后端”没有被用于指代目标，不算术语混用。

### S02｜补齐统计口径与容量验收基线【中；A、B】

**位置：**故事 37、38、108—111；流量计量、探针采集、资源限制；上一轮 C25、C28。

**问题：**已确定入口单侧计量，但上下行、隧道开销、分钟聚合和离线补报界限仍未落入；有资源上限不等于已定义预期容量。

**建议补入：**“规则按上下行业务字节分别累计，不计 WSS/yamux 开销；规则修改保持稳定 ID 与累计量连续。明确 CPU/速率采样间隔、分钟聚合方法、运行时长起点及离线流量补报期限；探针缺测保持缺失。”另列开发验收使用的并发、带宽和长连接时长基线，以及达到上限时的预期行为。

### S03｜补上角色、地址与控制链部署边界【中；A、B、F】

**位置：**故事 25、29、97；部署形态、配置编译器、换 IP 执行器；上一轮 C03、C06、C11、C20。

**问题：**NAT/多 IP 已排除，但两个出站查询源不能证明新地址可入站；角色重叠、自连、域名多 A 答案和人工地区覆盖后的自动识别规则仍未明确。C06 的控制端点独立于受管业务链路也未写入。

**建议：**区分出站观测 IP 与发布/隧道端点，过滤非公网或无效查询结果，发布前核对入站条件；无国内检测点时明确验证覆盖不足。说明是否允许节点兼任入口与出口，并拒绝会形成转发循环的配置；域名由实际拨目标的一侧解析，明确多 A 地址的尝试预算与私网目标授权。人工地区覆盖优先于自动识别。部署说明要求控制端点不依赖本面板管理的业务转发规则。

## 需要用户决定

### Q01｜跨组策略冲突时，节点级换 IP 的优先级【高；B、F】

**位置：**故事 77、81、95、96；入口动作协调器“换 IP 按节点串行”。

**问题：**允许跨组和共用额度已经确定；仍未确定一组要求仅切换、另一组要求换 IP、节点又兼任出口时谁能否决动作。“关联所有组”只解决记录关联，尚未解决授权和执行前屏障。

**建议决定：**节点级自动换 IP 开关作为总授权；“仅入口切换”表示本组不主动申请换 IP，不否决其他组或出口角色合法申请的节点级动作。动作执行前，可切离的组先完成切离；无就绪候选的组按既定退化或保留规则处理并提示影响。完成后各组按当时活动入口和期望版本更新，不能一律改回换 IP 节点。请确认这一优先级。

### Q02｜手动入口切换后，是否仍自动回首选入口【中；B】

**位置：**故事 64、66；被墙处理策略③“切回首选入口”。

**问题：**手动切到非首选成员后，可能两分钟后又被自动切回；同时进行的策略③也可能撤销管理员刚作的选择。

**建议决定：**v1 手动切换仍受既有自动回切规则管理，界面明确提示；手动操作提高期望版本，使旧策略③的切回请求失效。若用户需要长期固定，应另选“手动操作暂停自动回切，显式恢复”，两种语义需选定一种。

### Q03｜手动换 IP 是否允许突破保护限额【高；B】

**位置：**故事 93、94、98“明确看到它是否受限额约束”。

**问题：**规格只要求显示，没有给出手动动作究竟受哪些限制；不同实现可能绕过节点级保护。

**建议决定：**v1 手动换 IP 仍受冷却、滚动额度、进行中/未确认动作互斥约束；自动暂停可以由管理员先显式解除，但不因此清空额度。暂不提供强制突破限额。
