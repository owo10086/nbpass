# IX / 专线中转：专线地址、端口映射、转发链与出站 IP

Status: ready-for-agent（缓存策略 A 已定；各票仍按 Blocked by 推进）

参考：Zero Forwarder「IX 使用说明」https://www.zeroforwarder.com/docs/ix-guide/ （以及 /docs/jp-us-lan/、/docs/fwd-chain/、/docs/config/），Forwardx 的「主机入口地址 / 内网地址 + 按主机顺序建隧道」模型。决策记录见 `docs/adr/0009-ix-addresses-and-chains.md`。界面名称见 `GLOSSARY.md`（服务器 = 节点，转发端点 = 隧道出口，端点组 = 出口组，端口 = 规则）。

## 背景

IX / 专线场景：客户端 → 入口服务器 A →（专线 / 内网）→ 中转服务器 B →（可再经 C…）→ 目标。A、B 都能直接连面板，只有业务需要走专线。

现状（2026-11-12 只读调研）：A 已经能用管理员手填的 IPv4 内网地址经单跳转发连到 B（证书按内部名称校验，不受 IP 影响）。缺口：
- 一台服务器只有一个端点地址，所有入口共用；不能同时有「公网」和「专线」地址。
- B 换公网 IP（含手动换）会把手填的专线地址覆盖成新公网 IP。
- A 连的端口就是 B 本机监听端口，不能表达 NAT / 专线端口映射。
- 端点地址不能填域名。
- 没有多跳（A→B→C）。
- B 连目标时不能指定出站源 IP。

## 已定决策（2026-11-12 用户确认）

1. **模型按 Forwardx 思路**：地址挂在服务器上，路径按顺序选。不做 Zero Forwarder 的智能选择、固定前/后 N 跳、服务器级「使用转发端点作为传输」开关。
2. **服务器的端点地址**：
   - 「公网地址」：即现有端点地址，换 IP 时照旧自动更新。
   - 「专线地址」：可加多条，每条 = 名称（如「沪日 IX」）+ IPv4 或域名 + 对外端口（可空）。换 IP 永不改动专线地址。
   - 每个地址的「对外端口」留空 = 本机监听端口；填了即表示前一跳连这个端口，由运营商 / NAT 映射到本机监听端口（支持端口映射）。公网地址同样可填对外端口。
   - 域名由前一跳服务器解析，只用 IPv4。本次不做 IPv6、不做监听绑定 IP（仍监听全部 IPv4 地址）。
3. **端点组成员 = 服务器 + 用它的哪个地址**（公网或某条专线）。同一组里一台服务器只出现一次。现有成员迁移为「公网地址」，行为不变。
4. **转发链**：
   - 在「转发链管理」页保存：名称 + 按顺序排列的端点组（至少 2 跳）。可被多条端口复用；改链 = 所有引用它的端口一起改。
   - 端口转发模式变为：直连 / 单跳转发（选一个端点组，即一跳的链）/ 链式转发（选一条链）。
   - 路径：入口 → 第 1 组的一个成员 → 第 2 组的一个成员 → … → 目标。每台服务器只负责连下一跳：对下一跳组按主备顺序选健康成员、做健康检查和故障切换（沿用现有单跳的主备语义）。
   - 校验：同一台服务器在一条完整路径（入口 + 各跳所有成员）里不能出现两次；被端口引用的链不能删除；引用的端点组不能删除。
   - 每一跳只接受来自上一跳的连接、只连下一跳或该端口授权的最终目标（沿用现有逐对认证与目标授权）。
5. **出站源 IP**：服务器可选设置「出站 IP」（IPv4）。该服务器连接最终目标时（直连端口的入口、单跳 / 链的最后一跳）绑定此源地址；连接下一跳不绑定。不填 = 按系统路由（现状）。节点发现该地址不是本机地址时报应用错误，不静默回退。
6. **不做**：管理连接经中转（A、B 都能直连面板）、无法联网机器（Halo IX）的安装、UDP（下一个独立功能）、IPv6、智能选择 / 固定跳数、服务器级默认传输、监听绑定 IP。
7. **节点缓存回滚策略（A，2026-11-12 已定）**：新版使用新缓存写格式；真实旧读取代码/旧二进制必须明确拒绝加载新缓存，拒绝后停止转发，直到重连面板拿到自身能力范围内的配置。一次发布，不做过渡版。只有一个生产面板、服务器少、降级罕见，因此未选需要额外发布阶段的 B。接受离线回滚中断业务，不承诺旧版继续使用 IX 缓存转发。

   **原因**：`internal/node/config_store.go` 的 `json.Unmarshal` 忽略未知字段，`internal/forwarding/state.go` 的 Restore 会重算摘要；仅向格式 1 追加字段会使旧版丢 relay/源 IP 语义，可能越跳直拨或无绑定转发，在线能力门禁无法保护离线回滚。

   **格式与确定拒绝**：01 将 `internal/compatibility` 的 `StateCurrent` 从 1 升至 2，声明 `state_min=1,state_max=2,state_write=2`；新版读取器显式支持 1/2，不能继续用 `Version == StateCurrent` 作为唯一读条件。所有新写入（包括撤销检查点、普通规则）统一使用现有 JSON 外层整数 `version: 2`。保留同目录同文件 `config.enc`、现有 AEAD 附加数据 `nbpass-node-config-v1` 和原子写/同步/重命名流程，不另留可恢复的格式 1 副本、不双写。真实旧读取器在 `config_store.go:40` 严格要求 `cache.Version == StateCurrent(1)`，故即使 JSON 解码成功也会在 `engine.Restore` 前返回「节点配置缓存格式或身份不匹配」；依靠旧代码已有的版本比较即可拒绝，无需旧版认识任何新增字段。保留文件名还避免旧版退回遗留的格式 1 文件。

   **停止与恢复**：当前旧版 `internal/node/node.go:242` 遇缓存错误直接退出，defer 关闭 engine，尚未进入控制会话，不会自动重连。人工回滚时先停节点及更新器，成套替换为经核验的旧版节点/更新器，保留密钥/凭据，将不兼容 `config.enc` 原样隔离到非加载路径留存（含高水位与撤销证据），不得改写 version 为 1、恢复更早缓存或静默丢字段；随后旧版以空转发状态启动。控制不可达时业务仍停止，成功重连后只应用面板按旧能力过滤的当前快照。此人工恢复只用于不兼容格式回滚，不得成为写盘失败或普通缓存损坏的自动绕过；旧版无法离线恢复 IX 是 A 的既定代价。

   **发布边界**：旧 `internal/nodeupdate/install.go` 的 `CompatibleState` 检查要求候选写格式等于本地格式 1，不能用在线升级命令直接跨到 2。09 确认无未完成/未恢复更新事务后停节点及更新器，沿用现有同身份重新安装流程（面板重置 token 取新票据），用本次完整发行包替换并重启两者，保留 `node.key` 与同身份配置；不放宽旧更新器安全检查、不删除更新事务绕过恢复。新版读取旧格式时保留高水位、实际生效规则与撤销检查点，并原子写成 2；读 2 按 ADR 0006 离线恢复，未知格式仍拒绝。01–08 的中间构建只用于票间验收（含真实 02 节点 × 03 面板），不作为生产过渡版或回滚目标；格式 2 对应本次完整 IX 发布。

   **验收要求**：以实际生产回滚目标的真实旧读取代码/旧二进制为基线，在现有票中记录来源提交/二进制 SHA256，核对其格式检查与上述代码一致。让其读取新版实际写出的 relay-only grant、末跳/直连源 IP、撤销检查点缓存，断开控制，断言明确拒绝、无业务监听/下一跳/目标连接，无越跳、无源绑定丢失后转发、无授权复活；再验人工隔离后离线空启动仍不转发，重连只收能力内配置。新版读旧缓存、同版本离线恢复、跨格式重新安装也须验证。不能用新版模拟旧读取器或只检查版本声明/摘要/在线门禁；若实际回滚二进制没有此拒绝保证，必须阻断发布并报告，不得改选 B。

## 界面

- 转发端点页：每个端点显示公网地址和专线地址列表；编辑可增删专线地址、填对外端口。
- 端点组：添加成员时选「服务器 · 地址」（如「B · 公网」「B · 沪日 IX」）。
- 转发链管理（替换「规划中」占位页）：列表（名称、路径预览、引用端口数、各跳健康）+ 新建 / 编辑（名称、按顺序添加端点组、上下移）。
- 端口：转发模式三选一，「链式转发」时选链；端口列表与详情显示完整路径。
- 服务器编辑：「出站 IP」可选字段，带说明。
- 沿用 zf-ui 的界面规范（DESIGN.md）。

## 兼容与升级

- 迁移后现有端口、端点组的行为不变。
- 能力按实际执行语义拆分：02 只宣告 `ix_address_dialing`（域名/对外端口映射拨号），03 只新增宣告 `ix_member_identity`（成员地址身份、同服务器多地址会话/健康隔离）；04 宣告 `outbound_ipv4`，06c 统一宣告 `forward_chains`。废止原笼统的 `ix_addresses` 预留名，不用软件版本代替能力。专线成员或多地址隔离要求成员身份能力；域名/映射拨号另检查拨号能力，不因面板已到 03 就给纯公网域名/映射路径强加成员身份能力。
- 面板不得把新语义下发给不支持的执行节点。能力不足导致无完整可用路径时显示「整条阻塞（需升级服务器）」；仍有完整路径时显示「可运行但备用成员能力不足」，保留具体节点/地址/能力 blocker、组内原顺序，不把备用不足误报整条停运。备用升级后必须重新持久应用、确认，才加入候选；同节点其他端口照常同步。
- 遵守 ADR 0006 的配置版本与离线授权。

## 编译、恢复与运维约束

- **下游失败与预算**：逐流结果区分本边不可达、下游下一跳不可达、最终目标不可达、本地资源、配置/授权错误，并携带实际失败边/跳、rule/grant 代次与链内容指纹。B1→C 失败回到 A 时属于下游失败，不能判坏 A→B1。建流尚未成功且未转发业务字节时，上游按顺序尝试同组下一个已确认的健康成员；不跳组、不重放已建流业务。本边真实失败只计本边；资源/配置/授权错误保留归属并停止本次重试。
- **总超时**：单次建流端到端总预算为 `min(调用方剩余期限, 10 秒, 入口 DialTimeout)`；逐跳传递扣除本地耗时后的剩余预算，握手/解析/目标拨号及所有备用重试共享它，不能每跳或每次重试重置。各组每轮最多尝试 3 个不同成员，耗尽就失败；已建立流沿用空闲/资源限制。非对称可达 A→B1 好、B1→C 坏、B2→C 好时须转由 B2 成功，且 A→B1 健康不被污染。
- **健康与入口就绪**：按规则选中的 `(服务器, 地址)` 匹配证据，不沿用 `entry_readiness.go:309/319` 只按服务器 ID 合并的结果；端点配置摘要覆盖 node/address 身份、地址值、有效拨号端口、传输和 TLS 身份。02 提供仅公网场景的摘要回显，03 再增加地址身份；同 address_id 改地址/端口后，旧摘要样本丢弃。新鲜的本边握手只证明该边，不证明整链可用；06c 结合逐 grant 后续就绪证据判断完整路径。控制离线/证据过期保留未知或历史语义，不能等同专线业务中断。
- **监听与目标回环**：端口占用按实际监听者（入口业务监听、各跳本机隧道监听、检测端口）计算，relay 不虚构入口业务监听，对外端口不占本机端口。直连以入口、单跳以所有出口候选、链式以所有可能末跳作为目标拨号者，展开 127.0.0.1/localhost、本机地址和可静态证明的域名结果，再连到实际监听者构图；不能仍按入口解释末跳的本机目标。
- **历史规则与变更范围**：新增的「路径服务器不重复」校验只在本次变更影响的规则上执行，覆盖规则本身、被改链/端点组/服务器组的全部直接或间接引用（含停用规则与备用成员），导入预检与提交一致。全量编译仍按原语义编译未受影响的历史规则；无关保存、节点重连、授权确认引发的 `compileSnapshots` 不得因历史重复节点而失败。影响到历史规则的编辑须通过新校验；不迁移删除、不停用历史规则。既有监听冲突/目标回环检查保留。
- **operations/incidents（06c）**：各跳节点关联受影响端口，展示逐边失败、grant 应用/确认、能力 blocker；配置指纹包括 chain_id 及有序链内容/全部成员地址配置/目标，链 ID 不变但内容改变时旧事故按「新版本替代」结束，新证据进入新边界。停用/删除为「配置变更结束」；新鲜证据恢复才可记「异常解除」，过期/控制离线/读取失败不能记恢复。专线路径与公网被墙分开保留证据；只新增观察投影，外部动作仍由 ADR 0005 协调者执行。
- **部署交付（09）**：逐边记录前驱能访问的后继地址、对外端口→本机监听映射与 TCP 放行并人工验证；对外端口同号于本机业务端口可接受，实际隧道监听冲突必须拒绝。在 docs 补逐边步骤，保留 `docs/deploy-linux.md` 的 NAT/多 IP 不启用自动换 IP 边界。

## 验收

- `npm --prefix web run build`、前端测试、`GOFLAGS=-timeout=30m make test` 通过。
- 集成测试（clusterharness）覆盖：A→B（专线地址 + 对外端口映射）→目标；A→B→C→目标及再多一跳；逐跳主备/全坏/恢复、非对称可达与端到端总预算；换公网 IP 保留专线；源 IP 与非本机错误；旧节点收包断言、02 版节点 × 03 版面板（纯公网域名/映射可用、成员身份语义被拦、备用升级重新确认）。
- 健康/校验回归：双地址一好一坏、同 address_id 改地址后迟到旧样本丢弃；单跳/链式末跳回环正反例；中间节点监听冲突拒绝、外部端口与本机业务端口同号接受；历史重复节点不阻塞无关保存/重连/授权确认。
- 服务器组入口（06c/08/09）：主备组与全部发布组分别接同一条链，覆盖仅 A1 专线不可达、后跳全坏、恢复、控制离线；逐成员判断就绪，核对 DNS 动作、换 IP 归属和 ADR 0005 协调者去重。仅 A1 失败不能排除 A2；后跳全坏不能盲目切入口/换入口公网 IP；单纯控制离线不推断缓存业务中断。
- operations/incidents 覆盖中间/末跳节点反查受影响端口、逐边/grant/blocker、同链 ID 内容变化的历史边界与结束语义；缓存旧读取行为按已定决策 7（A）的公共矩阵验证。
- 本机 http 回环面板逐页检查新界面（编排者做浏览器验收）。
