# 转发规则：按 `#` 分隔文本批量导入

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准（转发规则、入口、入口节点、入口组、端点组、转发链、直连）。本功能不新增术语，不需要 ADR。

## Problem Statement

现在批量导入转发规则只能粘贴或上传 `{"format_version":3,"rules":[…]}` JSON，每条都要写入口 ID、`kind`、端点组 / 转发链 ID 等字段。管理员手上常见的是一行一条的简单清单，例如：

```
zx香港#33311#hka.4441234.xyz#3400
```

把这种清单转成 JSON 很麻烦，也容易出错。

## Solution

在现有「批量导入端口转发」弹窗（`web/src/RulesTransfer.tsx`，按钮「导入 JSON」所在处）里增加「文本导入」页签，与现有 JSON 导入并列：

- 文本框每行一条：`规则名#监听端口#目标地址#目标端口`。
- 入口、链路形态、是否允许私网目标在弹窗里**整批统一选一次**；想导入到不同入口就分批导入。
- 沿用现有「整体预检 → 确认导入」流程和整批原子语义：任一行有误整批不保存。

## User Stories

1. 作为管理员，我在规则页打开批量导入弹窗，切到「文本导入」，选一个入口节点或入口组，选直连，粘贴多行 `名#端口#目标#端口`，点整体预检后逐行看到结果，全部通过后确认导入，规则全部新增并启用。
2. 作为管理员，我选「单跳」并选一个端点组（或选「链式」并选一条转发链），整批规则都按这个链路形态创建。
3. 作为管理员，某一行格式错（段数不是 4、端口非数字或越界、名称为空），预检直接告诉我「第 N 行」哪里错，不发请求、不保存任何规则。
4. 作为管理员，某一行与已有规则端口冲突、目标地址不合法或是私网而我没勾「允许私网目标」，服务端预检报错时我能看到对应的**原文行号**和原因；整批不保存。
5. 作为管理员，空行会被跳过，不计入条数，也不影响其他行的行号显示（行号按原文行号）。
6. 作为管理员，目标是私网地址时，我勾选弹窗里的「允许私网目标」（默认不勾）后整批导入。

## 格式规则（定案）

- 分隔符只认**半角 `#`**；全角 `＃` 当普通字符（于是该行段数不对而报错）。
- 每行按 `#` 拆分后必须**正好 4 段**；规则名不能含 `#`。
- 每段去首尾空白；整行去空白后为空则跳过。不支持注释行（以 `#` 开头的行会因名称为空 / 段数不对报错）。
- 规则名：必填，最长 200 字节（UTF-8），允许与已有规则同名。
- 监听端口：**必填**，整数 1–65535。文本导入不支持自动分配（自动分配仅单条新建保留）。
- 目标地址、目标端口：校验沿用服务端现有规则（IPv4 或域名，不支持 IPv6；端口 1–65535）。前端只做段数、端口数字范围、名称非空 / 长度的本地校验，地址合法性交给服务端预检。
- 有效行数 1–500，与现有 JSON 导入上限一致；0 行时禁用预检。

## 整批共用选项（弹窗中选一次）

- 入口：入口节点或入口组（二选一，复用规则新建表单的选项来源）。
- 链路形态：直连 / 单跳（选端点组）/ 链式（选转发链）。
- 允许私网目标：复选框，默认关。
- 导入后规则一律 `enabled: true`；只做新增（`mode: create`），不支持覆盖。

## Implementation Decisions

- **后端不改。** 前端把文本转成现有 format_version 3 的 JSON 规则数组，调用现有 `POST /api/rules/import/preflight` 与 `POST /api/rules/import`（`mode=create`），见 `internal/panel/rules_json.go`、`internal/panel/forwarding_api.go`。每条规则：`name`、`listen_port`、`target_address`、`target_port`、`target_family:"ipv4"`、`allow_private`、`enabled:true`，加上所选入口（`entry_node_id` 或 `entry_group_id`）与链路字段（直连 `kind:"direct"`；单跳 `kind:"tunnel"`+`exit_group_id`；链式 `kind:"tunnel"`+`chain_id`）。字段形状以现有导出 / 导入 JSON 为准。
- 新增纯数据模块（例如 `web/src/RuleTextImport.ts`）：`parseRuleText(text) → { rows: [{line, name, listen_port, target_address, target_port}], errors: [{line, message}] }` 与 `buildRuleImportPayload(rows, shared) → format 3 对象`。保留「数组下标 → 原文行号」映射，把服务端预检返回的逐条结果按下标映射回行号展示。
- UI 放在 `RulesTransfer.tsx` 现有弹窗内（页签或分段切换），沿用现有预检结果展示与「预检通过才可确认」逻辑；切换输入或共用选项后需重新预检。
- 测试：纯模块用 `node:test` 写 `web/src/RuleTextImport.test.mjs`（风格同 `RulesData.test.mjs`），覆盖：正常多行、空行跳过与行号、全角 `＃`、段数 3/5、名称为空 / 超 200 字节、端口 0 / 65536 / 非数字 / 空、首尾空白、0 行、501 行、三种链路形态与两种入口生成的 payload、私网勾选透传。

## Out of Scope

- 文本导出（导出仍为 JSON）。
- 每行单独指定入口或链路形态。
- 按端口覆盖已有规则。
- 文本导入中的监听端口自动分配。
- 服务端新增文本格式接口。
