# 增加日间模式

## 确认与授权

用户已确认本方案全部推荐选项，要求不扩大范围。本轮保存方案；修改代码和执行实施仍需用户另行明确授权。

## 目标与范围

为现有 nbpass 面板增加日间模式，保留夜间模式，并提供跟随系统的选择。覆盖首次设置、登录、加载状态、全部后台页面、侧栏、弹窗、抽屉及原生日期时间输入框，兼顾桌面和手机。

布局、信息密度及业务操作沿用当前设计。主题偏好属于浏览器外观设置，不涉及账户同步、后端接口或数据库变更。

## 术语

| 术语 | 含义 |
| --- | --- |
| 日间模式 | 使用浅色背景和深色文字的界面外观，与当前时间无关。 |
| 夜间模式 | 现有深色背景和浅色文字的界面外观。 |
| 跟随系统 | 根据设备的系统外观设置选择日间或夜间，并实时响应系统外观变化；不是按时间切换。 |
| 主题偏好 | 管理员在日间、夜间、跟随系统三个选项中的选择。 |
| 生效主题 | 界面实际显示的日间或夜间外观；跟随系统时由系统外观决定。 |

本需求的界面术语集中记录于本方案，不新增独立术语文档。

## 已确认行为

1. 提供「日间 / 夜间 / 跟随系统」三个选项。首次访问、尚未保存偏好时，默认跟随系统。
2. 日间采用浅灰页面底色、白色卡片与侧栏、深色文字，保留橙色强调色。状态色需适配浅色背景，使成功、警告、错误等信息清晰可辨。
3. 后台顶栏右侧提供独立主题菜单；登录和首次设置页右上角也提供入口。桌面和手机均能操作，菜单明确标识当前主题偏好。
4. 选择后即时生效，无需刷新；切换不清空表单、不关闭业务弹窗、不改变当前页面。
5. 偏好只保存在当前浏览器，刷新、重新打开和退出登录后均保留。不同设备或不同浏览器分别设置。
6. 同一浏览器、同一站点的多个标签页同步主题偏好。
7. 跟随系统时，系统外观变化会实时更新界面；手动选择日间或夜间时，系统变化不覆盖用户选择。

## 实现方向

- 继续以 `web/src/theme.ts` 作为颜色值的唯一来源，在现有主题配置基础上提供日间和夜间两组配色；CSS 变量与 Ant Design 配置使用同一生效主题。
- 在根层管理主题偏好，使用浏览器本地存储保存选择，通过系统配色监听和存储变更事件处理系统变化与标签页同步。
- 初次渲染前确定并应用生效主题，避免刷新时先显示另一种主题；本地存储不可用时，本页仍可切换，按默认规则初始化。
- 调整 `web/src/main.tsx` 的根主题配置及未登录入口，调整 `web/src/AppShell.tsx` 的后台入口；复用同一切换控件。
- 将 `web/src/style.css` 和 `web/src/OtherPages.css` 中固定的深色 `color-scheme` 改为随生效主题变化，并同步浏览器的 `theme-color`。
- 实施时同步更新 `DESIGN.md` 中仅支持深色主题的描述，保持统一颜色来源的现有约束。

## 验收标准

- 首次访问跟随系统；三个选项均可切换，并正确显示当前选择。
- 登录、首次设置及全部后台页面的背景、文字、边框、表格、状态标签和浮层在两种主题下清晰可读。
- 原生日期时间输入框与界面主题一致；刷新进入页面时主题一致。
- 刷新、重新打开和退出登录后保留所选偏好；同一站点的其他标签页同步更新。
- 系统外观改变仅影响选择了跟随系统的界面。
- 桌面和手机均可使用主题入口；切换后当前页面、未提交表单和已打开业务弹窗保持可用。
- 实施后运行前端现有测试及类型检查与构建，检查上述外观和交互场景；不为本需求引入新的测试框架。

## 范围边界

不新增外观设置页面、自定义配色、定时切换、账户级同步或业务功能调整。不为可逆的主题选择另建 ADR，也不额外生成工单、审查报告或总结文件。
