# nbpass v1 规格

Status: ready-for-agent

术语以 `GLOSSARY.md` 为准，关键决定见 `docs/adr/0001`—`0006`，设计审查及其处理结果见 `.scratch/review/design-review.md`（第六节）。

## Problem Statement

管理员手上有一批分布在国内外的服务器，用来做 TCP 流量转发（直连或经加密隧道到出口再到目标）。现有的面板要么只管转发、不管被墙，要么被墙检测、换 IP、改 DNS 靠几套互不相干的脚本完成：

- IP 被墙后要手动发现、手动调商家接口换 IP、手动改域名解析、手动改其他节点里记的出口地址，期间业务中断。
- 入口离线或被墙，没有自动把域名切到备用入口、恢复后再切回的能力；自己写的脚本之间还会互相覆盖解析记录。
- 出口故障时没有就近切换，面板一断线节点就停摆或行为不可知。
- 域名解析被改动、被污染、迟迟不生效时没人知道。
- 节点的资源、在线状态、规则流量要分别去不同地方看，升级节点要逐台登录。

管理员需要一个自己完全掌控的面板，把转发、故障切换、被墙处理、解析监控和节点运维放在一处，并且在面板断线、外部接口超时、检测结果不确定时，行为仍然可预期、可解释。

## Solution

一个 Go 单二进制的面板（内嵌 React + AntD 前端，SQLite 存储）加上 Go 节点程序：

- 节点主动通过 gRPC 双向流连接面板，接收带版本号的配置快照并回报已应用版本；与面板失联时按缓存配置继续转发。
- 转发规则绑定在入口组上，链路形态为直连或隧道；隧道使用 WSS（面板为每个出口生成自签证书）+ yamux，出口按出口组主备选择，故障时入口节点本地切换出口。
- 节点自测判断自身是否被墙，入口组按被墙处理策略自动换 IP、入口切换或两者结合；所有改动受管记录的动作由面板的一个协调器排队执行（DNSPod）。
- 国内检测点为离线确认和自测结果未知时的被墙确认提供证据。
- 解析监控从多条路径持续核对域名解析，自动修正受管记录偏差，其余异常只通知。
- 探针提供资源监控和曲线，事件日志记录一切，Telegram 推送关键事件。
- 面板内置同版本节点程序，可一键升级单个节点并自动回滚。

## User Stories

### 安装、登录与面板安全

1. 作为管理员，我想用一条命令在 Linux amd64 服务器上安装面板并注册为 systemd 服务，以便快速部署。
2. 作为管理员，我想让面板的网页端口和节点控制端口分开监听，以便分别放在不同的反向代理规则后面。
3. 作为管理员，我想让面板只提供 HTTP、由我自己的反向代理负责 HTTPS，以便沿用已有的证书管理方式。
4. 作为管理员，我想在文档里看到网页端口和 gRPC 控制端口的反向代理示例（含 HTTP/2 长流超时与保活），以便节点不会因为代理配置不当而周期性"假离线"。
5. 作为管理员，我想让节点只通过经过 TLS 验证的地址连接控制端口、证书校验失败时绝不降级为明文，以便节点 token 和配置不被窃听。
6. 作为管理员，我想首次打开面板时设置管理员密码，以便面板不会带着默认密码暴露在公网。
7. 作为管理员，我想用密码登录面板，以便只有我能管理节点。
8. 作为管理员，我想让连续输错密码的来源被限流，以便防止暴力破解。
9. 作为管理员，我想在设置里配置受信任的反向代理地址，以便限流按真实来源 IP 计算，而不会被伪造的转发头绕过或把我自己锁在外面。
10. 作为管理员，我想让登录会话有空闲超时和绝对期限，以便忘记退出也不会长期有效。
11. 作为管理员，我想修改密码后所有旧会话立即失效，以便怀疑泄露时可以一键止损。
12. 作为管理员，我想让所有写操作都有同源校验，以便别的网站无法借我的登录状态改 DNS 或升级节点。
13. 作为管理员，我想在服务器本机用命令行重置管理员密码，以便忘记密码时能恢复。

### 节点接入与状态

14. 作为管理员，我想在面板里添加节点并得到一条安装命令，以便在节点服务器上一键安装节点程序。
15. 作为管理员，我想让安装命令只携带短期一次性的安装票据、安装时换取长期节点 token，以便安装命令出现在 Shell 历史或截图里也不会长期有效。
16. 作为管理员，我想重置或吊销某个节点的 token 时，它已建立的控制连接也被断开，以便被盗的节点凭据立即失去控制权。
17. 作为管理员，我想在节点列表看到每个节点的在线、离线、维护中状态，以便掌握全局。
18. 作为管理员，我想让节点与面板失联超过 90 秒才判为离线、面板刚启动的 90 秒内不判离线，以便面板自己重启不会引发误判。
19. 作为管理员，我想看到每个节点的期望配置版本和已应用配置版本，以便知道我的改动有没有真正生效。
20. 作为管理员，我想看到节点应用配置时的逐规则错误（例如端口被占用），以便快速定位问题。
21. 作为管理员，我想让离线节点的配置状态显示"待确认"而不是"正常"，以便不被过时的状态误导。
22. 作为管理员，我想按"节点 × 入口组"看到是否就绪（本组全部启用规则已应用、监听成功、每条隧道规则至少一个出口握手成功），以便区分"在线"和"真的能接本组流量"；其他入口组的规则错误不影响本组就绪。
23. 作为管理员，我想让面板依据 ip2region 离线库自动识别节点地区，以便中国大陆节点自动承担国内检测点角色。
24. 作为管理员，我想手动覆盖某个节点的地区或关闭它的国内检测点角色，以便处理识别错误或不想让它参与检测。
25. 作为管理员，我想在节点 IP 变化后自动重新识别地区，以便检测点角色保持正确。
26. 作为管理员，我想删除节点时看到它还被哪些规则、入口组、出口组引用，以便不会留下悬空配置。

### 转发规则

27. 作为管理员，我想创建一条直连规则（入口组上的监听端口 → 一个目标），以便最简单地转发流量。
28. 作为管理员，我想创建一条隧道规则（入口组上的监听端口 → 出口组 → 一个目标），以便经加密隧道从出口访问目标。
29. 作为管理员，我想目标既可以填 IPv4 也可以填域名，隧道规则的域名在出口一侧解析，以便访问只有出口能解析或能到达的地址。
30. 作为管理员，我想选择随机端口，让面板为该规则挑一个在入口组所有成员上都空闲的端口，以便省去手动查找。
31. 作为管理员，我想在保存规则时检查每个成员节点上的端口冲突（其他规则、隧道监听、检测端口），冲突时明确提示是哪个节点哪个端口，以便同一节点加入多个入口组也不会撞端口。
32. 作为管理员，我想看到每条规则的同步状态（未同步、正常、同步失败、待确认），并能展开看到每个成员节点的情况；只要有成员失败或待确认，汇总就不显示正常，以便发现部分成员没生效的问题。
33. 作为管理员，我想启用、停用、修改、删除规则，以便管理转发。
34. 作为管理员，我想删除或停用规则后，在线入口立即关闭监听和已有连接，出口不再接受该规则的新流并断开已有流，以便撤销真正生效。
35. 作为管理员，我想把规则批量导出为带版本号的 JSON、默认不包含任何秘密，以便备份和迁移。
36. 作为管理员，我想批量导入 JSON 规则时先整体预检（引用、端口冲突、格式），明确新增还是覆盖，全部通过才写入，以便不会出现导入一半的状态。
37. 作为管理员，我想看到每条规则的累计流量和当前连接数，以便了解使用情况。
38. 作为管理员，我想让规则流量只在入口一侧计量、节点重启或重传不造成重复计算或负增量，以便数字可信。

### 隧道与出口

39. 作为管理员，我想让面板为每个出口节点自动生成自签证书，以便不需要自己申请证书。
40. 作为管理员，我想让入口只信任该出口的这张证书、不使用系统根证书、绝不跳过校验，以便中间人无法冒充出口。
41. 作为管理员，我想让出口证书使用不随 IP 变化的身份名称，以便出口换 IP 后证书仍然有效。
42. 作为管理员，我想让出口证书轮换时新旧证书短期重叠、等入口确认后再撤下旧证书，以便轮换不中断业务。
43. 作为管理员，我想让每对入口—出口有独立的隧道凭据、并且只在 TLS 建立后才发送，以便凭据不在明文中出现。
44. 作为管理员，我想让出口对每个新业务流核对入口身份、规则、授权目标，只拨这条规则的那个目标，以便被盗的入口不能把出口当成任意代理。
45. 作为管理员，我想新增隧道规则时先下发出口授权、再启用入口监听，以便新规则上线时不会出现一段全部被拒的窗口。
46. 作为管理员，我想把多个出口节点组成出口组并按主备顺序排列，以便主出口故障时自动用备出口。
47. 作为管理员，我想让入口每 5 秒通过真实隧道握手探测各出口，连续 3 次失败判为故障，以便及时发现出口问题。
48. 作为管理员，我想让入口连出口的真实拨号失败立即把该出口判为故障，以便不等探测周期。
49. 作为管理员，我想让故障出口连续成功 60 秒后才重新作为主出口接新连接，以便避免抖动。
50. 作为管理员，我想让出口切换只影响新连接、不迁移已有连接，以便行为可预期。
51. 作为管理员，我想让出口组全部不可用时新连接直接失败，而不是绕过隧道直连目标，以便流量永远不走我没批准的路径。
52. 作为管理员，我想区分"出口到不了"和"出口到不了目标"，以便某个目标不可达不会把整个出口判为故障、把其他规则也切走。
53. 作为管理员，我想让业务数据已经发出后发生的失败直接结束这条连接、不换出口重放，以便不产生重复的业务操作。
54. 作为管理员，我想让节点与面板失联时出口探测和出口切换照常运行，以便面板故障不影响转发容灾。

### 入口组、入口切换与 DNS

55. 作为管理员，我想创建入口组、给它绑定一个域名和一条 DNSPod 受管记录，以便对外用一个域名提供服务。
56. 作为管理员，我想让受管记录唯一绑定 DNSPod 账号、域名、记录 ID 和线路，以便面板只改这一条记录、不动别的记录。
57. 作为管理员，我想在绑定时被拒绝不支持的配置（非 A 记录、多线路），并被告知同名下存在的其他 A/AAAA 记录可能造成的影响，以便知道自动管理的边界。
58. 作为管理员，我想给入口组成员排序，第一位是首选入口，以便明确正常时由谁接流量。
59. 作为管理员，我想看到入口组当前的活动入口、受管记录当前值、各解析路径的观察值，以便区分"面板选了谁"和"用户实际解析到谁"。
60. 作为管理员，我想在活动入口离线 90 秒后，由面板请国内检测点确认它确实连不上，再自动切到一个就绪的成员，以便入口宕机时业务自动恢复。
61. 作为管理员，我想在没有可用国内检测点时，入口离线只通知、不自动切换，以便不会因为面板自己的网络问题误切。
62. 作为管理员，我想让入口切换只切到就绪的成员，以便不会切到一个监听没起来的节点上。
63. 作为管理员，我想在没有就绪候选时保留最后的解析、停止切换并通知，以便不会删掉记录导致负缓存。
64. 作为管理员，我想首选入口恢复后连续成功 1 分钟、且当前活动入口已驻留满 2 分钟才自动切回，以便避免来回抖动。
65. 作为管理员，我想在真实故障发生时打断驻留保护立即切走，以便驻留规则不会拖延故障处理。
66. 作为管理员，我想手动把活动入口切到指定成员，并且手动操作也走同一个协调器排队，以便手动和自动不会互相覆盖。
66a. 作为管理员，我想手动切到非首选成员后，该入口组暂停自动回切、界面显示"自动回切已暂停"，直到我手动恢复；故障切换仍然生效，进行中的策略③切回因我的手动操作而作废，以便维护期间不会被自动切回。
67. 作为管理员，我想让 DNS 写入超时时记为"结果未确认"、先读回记录核对再决定，以便不会重复写或写错。
68. 作为管理员，我想让面板重启后先核对 DNSPod 上的实际记录再继续未完成的动作，以便崩溃不会留下错误的解析。
69. 作为管理员，我想看到每次入口切换的进度（期望已变更、服务商已写入、传播中、已生效），以便知道切换到了哪一步。

### 被墙检测与处理

70. 作为管理员，我想为每个节点单独开启自测，以便只对需要的节点检测被墙。
71. 作为管理员，我想让自测每 2 分钟一轮、TCP 连接 4 个国内站点的 443 端口、至少 3 个连不上算一轮异常，以便与我验证过的 ipc.sh 行为一致。
72. 作为管理员，我想让任一站点域名解析失败时该轮记为未知、不当作异常，以便本机 DNS 故障不触发换 IP。
73. 作为管理员，我想让自测结果未知的那一轮由国内检测点补判（所有有效检测点都连不上该节点的检测端口才记异常），以便自测不可用时仍有证据来源。
74. 作为管理员，我想让连续 3 轮异常就认定被墙，以便快速响应。
75. 作为管理员，我想看到被墙认定依据的是自测还是检测点补判、每轮的原始结果和时间，以便判断可信度。
76. 作为管理员，我想让国内检测点只有在本轮先连通国内对照站点时结果才有效、不检测自己，以便网络异常的检测点不会误导判断。
77. 作为管理员，我想为每个入口组选择被墙处理策略：仅换 IP、仅入口切换，或先切到备用入口再换 IP、复检通过后切回，以便按业务需要应对。
78. 作为管理员，我想在策略③没有就绪备用入口时自动退化为仅换 IP，以便仍然有恢复手段。
79. 作为管理员，我想在策略③换 IP 失败或额度用尽时留在备用入口并通知，以便业务不受影响、我来处理。
80. 作为管理员，我想在策略②没有就绪候选时保持现状并通知，而不是隐式改为换 IP，以便行为符合我选择的策略。
81. 作为管理员，我想为出口节点也可选开启被墙处理（换 IP 后自动更新各入口记录的出口地址），以便出口被墙时也能自动恢复。
82. 作为管理员，我想看到出口换 IP 后哪些入口已应用新地址、哪些已经握手成功，以便知道恢复进度。

### 换 IP

83. 作为管理员，我想为每个节点配置一个自定义换 IP HTTP 接口（URL、方法、请求头、请求体，支持模板变量），以便对接任意商家。
84. 作为管理员，我想让模板变量按所在位置（URL、JSON、请求头）正确编码，以便变量内容不会破坏请求结构。
85. 作为管理员，我想让携带凭据的公网换 IP 接口必须使用 HTTPS 并校验证书，禁止跨主机重定向和降级到 HTTP 的重定向，有超时和响应大小上限，访问内网地址需对具体端点显式授权，以便凭据不会被带到别处。
86. 作为管理员，我想让换 IP 凭据只下发给执行它的那个节点，日志和通知里的凭据全部脱敏，以便凭据不扩散。
87. 作为管理员，我想让换 IP 由被墙节点自己调用，以便接口只需对该节点开放。
88. 作为管理员，我想让节点只有在面板发出、仍在有效期内的执行许可、且控制连接在线时才调用换 IP，以便节点离线时绝不自行换 IP。
89. 作为管理员，我想让换 IP 前先查询并记录当前公网 IPv4、查询失败则取消且不占额度，以便有可比较的旧值。
90. 作为管理员，我想只有观察到公网 IPv4 确实变化才算换成（接口 2xx 不算），以便不会误报成功。
91. 作为管理员，我想让接口超时记为"结果未确认"、先查询公网 IP 核对而不是立即重发，以便不会连续释放可用地址。
92. 作为管理员，我想让新 IP 用自测复检、最多 3 轮、任一轮通过即算恢复，以便与 ipc.sh 一致。
93. 作为管理员，我想让换 IP 受 30 分钟冷却、滚动 1 小时最多 1 次、滚动 24 小时最多 3 次限制，按尝试计数、跨重启保存、按节点共用，以便不会因为误判把 IP 换光。
94. 作为管理员，我想让连续 2 次换后仍无改善时暂停自动换 IP 并通知，直到我手动解除或后续自测恢复正常，以便止损。

## Implementation Decisions

### 部署形态

- 面板：单个 Go 二进制，内嵌前端构建产物；网页 HTTP 端口与 gRPC 控制端口分开；只提供 HTTP，HTTPS 由反向代理承担。gRPC 控制端口只允许经 TLS 代理对外，明文后端只能绑定本机回环或明确的可信网络。部署说明要求控制端点不依赖本面板自己管理的转发规则，以免入口故障同时切断控制链路。
- 节点：单个 Go 二进制 + 独立的 systemd 更新服务。目标平台 linux amd64 + systemd；macOS 只用于开发。
- 仅 TCP、仅 IPv4；数据模型中地址字段与地址族分开存放，为 IPv6 留余地。
- 存储：SQLite（WAL）。可扩展的枚举现在就在模型中定义：隧道传输类型（v1 仅 WSS）、出口策略（v1 仅主备）、DNS 服务商（v1 仅 DNSPod）。
- 节点可以同时兼任入口和出口；配置编译器拒绝会形成转发循环的配置（例如规则目标指向本规则自己的入口监听）。
- v1 只支持"一个节点一个可直接入站的公网 IPv4"：区分出站观测 IP 与对外发布地址（受管记录、隧道端点），查询结果为非公网或无效地址时丢弃；检测到 NAT 或多 IP 迹象时该节点不启用自动换 IP。

### 面板模块

- **认证与会话**：成熟的加盐慢哈希存储密码，限制并发校验；可撤销会话（空闲超时 + 绝对期限），改密码撤销全部会话；Cookie 为 HttpOnly、Secure、SameSite；写请求做同源校验；按配置的受信任代理解析来源 IP 后限流；提供本机 CLI 重置密码。
- **控制服务（ADR 0001、0006）**：
  - gRPC 双向流，节点主动连接、token 认证（面板只存 token 哈希），同一节点同一时刻只允许一个控制会话；每轮交换重新核对 token，吊销后断开流。
  - 上报身份只取自已认证的控制会话：节点只能上报自身状态和分配给自己、仍在有效期内的检测任务结果，消息中自带的身份字段不能覆盖认证身份。
  - 面板即时推送配置快照，另有定时全量同步。配置快照带单调版本号和摘要；旧流、旧版本、旧进程实例的报告不得覆盖新状态；删除通过完整快照收敛。
  - **部分应用语义**：节点逐规则报告实际生效的规则版本和错误；节点"已应用版本"只在整个快照全部应用成功后推进。部分成功时节点持久化实际生效状态（特别是停用、删除的结果），重启不得恢复已撤销的规则。逐成员同步状态为未同步、正常、同步失败、待确认；入口组汇总保留失败和待确认的成员明细，不把部分成功标为正常。
  - **版本兼容**：控制协议版本、隧道协议版本、能力集、节点本地状态格式分别声明兼容范围，与软件版本独立。至少保证当前版与上一版节点在滚动升级期间控制可连、隧道互通；对端不支持的能力不提前启用。
- **配置编译器**：
  - 从数据库生成每个节点的配置快照（入口规则、出口授权、出口组、自测参数、检测任务、换 IP 模板、探针参数）。
  - 端口冲突校验（规则监听、隧道监听、检测端口）；随机端口按规则选一次并校验所有成员；节点实际 bind 失败以逐规则错误显式上报。
  - **授权代次**：节点配置版本只用于该节点的同步确认，不用于跨节点授权。每条隧道规则有独立的授权代次；出口按"规则 ID + 授权代次"核对入口归属和允许的目标。入口启用新规则或新授权代次前，必须先收到该出口已应用对应授权的确认；未确认的出口不进入该规则的候选。无关的配置版本变化不撤销未变更的授权。
- **入口动作协调器（ADR 0005）**：
  - 每个入口组一个串行执行队列，维护期望版本、期望活动入口和进行中的动作；入口切换、回切、策略③、换 IP 后的记录更新、受管记录偏差写回、手动操作都提交到这里。
  - 每个外部动作先持久化（动作 ID、旧值、新值、额度占用）再执行；分阶段持久化"期望已变更 / 服务商已写入 / 传播中 / 已生效（或传播未确认）"；迟到结果核对动作 ID 和版本后才生效；超时记"结果未确认"，先读回核对；面板重启后先核对外部实际状态再续做。
  - **传播观察不阻塞队列**：写入 DNSPod 成功即释放队列，传播观察按期望版本独立运行；新的动作使旧观察失效，因此传播期间仍可立即执行新的故障切换。驻留计时从受管记录写入成功的时刻开始。
  - **受管记录归属**：同一 DNSPod 记录只能归属一个入口组；绑定时读回并展示当前记录值，首次发布须由管理员显式确定活动入口。写回只依据 DNSPod 上的实际记录与当前期望不符，递归解析的差异不直接触发写回。
  - **手动切换**：手动切到非首选成员后，该入口组进入"自动回切已暂停"，直到管理员手动恢复；故障切换照常执行。手动操作提高期望版本，使进行中的策略③切回请求失效。
  - **跨组换 IP**：换 IP 按节点串行。节点开启自动换 IP 是总授权；任一入口组（策略①或③）或该节点的出口角色需要时即可申请，"仅入口切换"只表示本组不申请、不否决他组。执行前，有就绪候选的相关入口组先完成切离；没有就绪候选的组按各自的退化或保留规则处理并在事件中记录影响。完成后各组按当时的活动入口与期望版本更新，而不是一律改回该节点。
- **判定汇总**：
  - 汇总节点自测轮结果、国内检测点任务结果、控制连接活性，给出疑似被墙、被墙、离线、就绪等状态。
  - **自测轮的最终结果**只有正常、异常、未知三种：
    - 自测未知的轮次请求检测点补判，补判有截止时间，截止后到达的结果作废。任一有效检测点连上记正常；全部有效检测点都连不上记异常；零个有效结果、缺报或执行错误都不能补成异常，该轮保持未知。
    - 连续 3 个异常轮认定被墙；未知轮中断连续异常计数（不累计也不算正常）；正常轮清零计数，并解除疑似被墙和被墙状态。
    - 检测点任务每轮固定检测点集合、目标 IP 与端口、配置版本；换 IP 后旧地址的迟到样本作废。
  - **就绪**按"节点 × 入口组"计算：本组全部启用规则已应用、监听成功、每条隧道规则至少一个获授权出口握手成功。其他入口组的规则错误不影响本组就绪。
  - **自动切换候选**除就绪外还须：控制在线、不在维护中、未被墙，并且有未过期的国内可达证据（最近一次正常自测轮或检测点成功）；没有证据时标"未知"，不作候选。
  - **回切窗口**按周期性的候选检查累计：每次检查首选入口都满足候选条件才算一次成功；任何一次失败、未知或样本过期都会中断窗口，不以时间流逝代替成功样本。
- **换 IP 授权**：维护节点级额度状态（冷却、滚动窗口计数、连续无改善次数、暂停、冻结），不受保留期清理影响；签发有期限的执行许可。自动换 IP 受全部限额约束；手动换 IP 不受冷却和次数限制，但与进行中或结果未确认的换 IP 互斥，且次数计入额度。
- **DNS 服务商接口**：抽象"读取记录 / 写入记录"，v1 实现 DNSPod，只支持 DNS-only A 记录、单一线路；受管记录唯一绑定账号、域名、记录 ID、线路；发现同名的非受管 A/AAAA 记录时提示影响，不删除。
- **解析监控**：
  - 调度检测点与面板 DoH 查询，按"路径 + 期望版本"计连续异常；旧记录 TTL 内的旧值不算污染；只向协调器上报偏差。
  - **生效判定**：入口切换后，参与判定的路径为当前有效的国内检测点路径和面板 DoH 路径。每条有采样的路径在本期望版本下连续 2 次返回期望值，且其中至少有一条国内路径，即记"已生效"。没有采样的路径记"覆盖不足"或"采样失败"；到最长观察时间仍未满足时记"传播未确认"并通知，不标已生效。
- **探针存储**：实时值 + 分钟聚合（平均值与最大值），缺测保持缺失。
- **事件与通知**：事件日志（含节点补报，按事件 ID 去重）；Telegram 异步投递队列，记录失败、重试、过期，同一事故合并。
- **升级管理**：内置同版本节点程序；生成绑定任务 ID、版本、平台、大小、SHA256 的清单，经已验证的 TLS 下发；跟踪升级任务（下载、校验、切换、回连、就绪、回滚、未确认）；把节点置为有期限的维护中。维护期到期后重新评估当前证据，维护期内累计的离线时长不直接当作新的故障确认。
- **保留期清理**：分批执行、不长时间阻塞；只清理历史，不碰额度、动作、版本和累计计数。
- **备份与面板升级 CLI**：
  - 一致性在线备份后再执行迁移；迁移失败时恢复的范围（程序、数据库、密钥文件）写进 CLI 输出与文档。
  - **从旧备份恢复**：恢复后自动写操作全部暂停，并清理所有登录会话和安装票据。节点重连时上报自己的配置版本高水位和动作执行记录，面板据此把新配置版本抬到高于已确认的高水位。无法重建最近 24 小时换 IP 尝试记录的节点，暂停自动换 IP，直到记录补齐或 24 小时保护窗口过去；无法核对的节点及其入口组继续暂停相关的自动写操作。
- **秘密存储**：可验证的随机 token 只存哈希；需要再次下发的秘密（隧道凭据、换 IP 凭据、DNSPod 与 Telegram 凭据）用本机密钥文件加密存储；界面不回显完整秘密，导出默认不含秘密。密钥文件、数据库、节点缓存与更新暂存目录规定所属用户和最小读写权限。

### 节点模块

- **控制客户端与本地缓存**：持久化实际生效的配置状态（含版本和逐规则生效结果）；启动先加载缓存再连接面板；断线后保留配置、持续重连。离线时：继续转发，出口探测与出口切换照常，自测照常记录，但不执行换 IP、不改 DNS。
- **转发引擎（入口）**：
  - 直连规则直接拨目标；隧道规则按出口组主备选择出口。
  - 出口健康：每 5 秒真实隧道握手探测，连续 3 次失败判故障，入口→出口的真实拨号失败立即判故障，连续成功 60 秒恢复。
  - 故障归属分四类：入口→出口、出口→目标、本地资源、配置/授权；只有入口→出口故障影响出口健康。
  - 只在尚未交付业务数据前换候选；每个新连接对实际出口去重并受总尝试预算约束；全部不可用则失败，不退回直连；已有连接不迁移。
  - 目标为域名时，由实际拨目标的一侧解析（直连为入口，隧道为出口）；多个 A 记录在尝试预算内依次尝试；私网目标需在规则上显式允许。
- **隧道服务端（出口）**：WSS（自签证书，稳定身份名称）+ yamux；TLS 建立后校验入口—出口凭据；每个新流按"规则 ID + 授权代次"核对入口身份和授权目标，只拨授权目标；已有流每秒复查授权，撤销后断开。
- **自测**：每 2 分钟一轮（带抖动），4 个可配置国内站点 TCP 443，至少 3 个失败为异常轮，任一站点解析失败为未知轮；未知轮请求面板安排检测点补判。
- **国内检测点执行器**：本轮先连对照站点，成功后才对被测节点的检测端口发起 TCP 连接；上报原始结果；不接受检测自己的任务。另执行解析监控的国内 DNS 查询。
- **检测端口**：节点固定监听的检测端口，参与端口冲突校验。
- **换 IP 执行器**：
  - 换 IP 命令独立于配置快照，绑定动作 ID、节点、旧 IP 和许可期限；同一动作 ID 只调用一次接口，重复投递只恢复观察。
  - 持有有效许可且控制连接在线时才执行。先用两个查询源查公网 IPv4；查询失败则取消，面板释放预占的额度。
  - 调用前持久化"动作已开始"，再调用模板化 HTTP 请求：
    - 模板变量按上下文编码；不经 Shell；有超时和响应大小上限。
    - 公网带凭据的接口必须用 HTTPS 并校验证书；拒绝跨主机重定向和降级到 HTTP 的重定向。
    - 代理必须显式配置，不继承环境变量中的代理。
    - 内网目标需对具体端点显式授权，首次请求和每次重定向都校验实际目标地址。
  - 调用后每 60 秒查询公网 IP、最多 5 次，等待出现与旧值不同的有效公网 IPv4。两个查询源结果不一致、查询失败或观察到期仍无法确定时，动作保持"结果未确认"，该节点后续的自动换 IP 冻结，直到核对清楚或管理员手动解除；不得仅凭仍看到旧 IP 就自动重发。调用后与面板失联只继续观察和记录。
  - IP 变化后按自测复检，最多 3 轮，任一正常轮即"已恢复"。3 轮均为有效异常才记一次"无改善"；没有正常轮但含未知轮时记"待确认"，不累计无改善。之后的正常自测轮解除"无改善暂停"并清零连续无改善次数。
  - 所有阶段上报给面板并持久化。
- **探针采集**：CPU、内存、磁盘、网卡收发速率、连接数（业务、隧道、系统分开）、运行时长（从节点进程启动起算）。
- **流量计量**：规则流量只在入口计量，上行、下行业务字节分别累计，不计 WSS/yamux 开销；累计计数带节点进程实例标识和序号，面板去重，重启不产生负增量；规则修改保持规则 ID 不变、累计量连续。
- **本地事件队列**：有界持久队列，离线期间存关键事件，重连后补报，溢出时标记缺口。
- **资源限制**：节点/规则并发、待拨号数、yamux 流数、缓冲总量上限；握手、拨号、空闲超时；正确处理半关闭与取消。直连规则同样受这些限制。
- **更新服务**：
  - 独立 systemd 服务，只接受面板任务指向的固定产物与固定安装路径；不跟随不受信任的路径或符号链接；从校验完成到原子替换之间防止产物被替换。
  - 下载、校验 SHA256、自检后再替换并重启；更新前保留旧版可读的配置和状态。
  - 新版本启动失败或本地业务自检失败时回滚，并恢复相匹配的状态，但不恢复已撤销的授权、不丢失换 IP 动作的去重记录。
  - 新版本本地就绪、只是控制确认超时，则保留新版本并记"未确认"；重连后核对任务 ID、进程实例、版本和实际产物。

### 被墙处理策略状态（按入口组）

- ① 仅换 IP：被墙节点按额度规则换 IP；协调器更新受管记录。
- ② 仅入口切换：切到就绪的候选成员；没有候选成员时保持现状并通知。
- ③ 先切后换再切回：切到就绪的备用成员 → 原节点换 IP → 新 IP 复检恢复 → 按回切规则切回首选入口（自动回切已暂停时不切回）。没有就绪的备用成员时退化为①；换 IP 失败、受限、待确认或冻结时留在备用成员并通知。
- 出口被墙处理（按出口节点可选）：换 IP 后由面板更新所有相关入口里的出口地址，并分别展示"已应用"和"已握手"。

## Testing Decisions

- **唯一的自动化接缝：进程内集群测试台。** 一个测试进程内启动真实的面板核心和多个真实的节点核心，真实的 gRPC 编解码、TLS/WSS 和 yamux 都在台内运行。测试台注入：
  - 可快进的时钟：所有定时器、超时、冷却、滚动窗口都走它。
  - 模拟网络：可以断开节点到面板的控制链路、让某个节点 IP 对"国内"不可达、让某条入口→出口链路故障、让目标不可达。
  - 外部服务的假实现：DNSPod、换 IP HTTP 接口、公网 IP 查询、国内自测站点与对照站点、DNS 解析器与 DoH、Telegram、ip2region。
  - 生命周期能力：保留磁盘重建面板或节点核心（模拟重启与崩溃）、注入持久化故障（磁盘满、写失败），以及更新服务外部接口的替身。
- **测试的写法**：只通过面板 HTTP API 操作和断言，再加上假外部服务记录下来的调用与状态（例如 DNSPod 上的记录值、换 IP 接口被调用的次数）。转发流量走 localhost 真实 TCP，用于验证流量真的通了、断了、切了。
- **好测试的标准**：只断言外部可观察的行为（API 返回的状态、DNS 记录、通知内容、连接能否建立、流量计数），不断言内部结构、调用顺序或私有状态；重构内部实现不应导致测试失败。为了让测试台可行，所有外部依赖（时钟、拨号与监听、HTTP 客户端、DNS 服务商、解析器、通知、文件系统持久化）必须经由可注入的接口进入面板和节点核心。
- **前端不写自动化测试**，以手动验收为主。界面展示的状态都由 API 直接给出，前端不自行推算，因此 API 测试即覆盖状态逻辑。
- **测试台覆盖不到的部分，列为 Linux 人工验收项**。每项都要写明操作步骤和通过条件；测试台里的替身通过，不代表这些部署项通过：
  - 安装脚本与安装票据的实际兑换
  - 面板 CLI（密码重置、升级、备份恢复）
  - 真实 systemd 更新服务的替换与回滚
  - 反向代理下的 HTTP/2 长流与 TLS 部署
  - 文件权限
  - 操作系统指标采集
  - 前端界面
  - 容量基线：1000 个并发连接、100 Mbps 持续吞吐、24 小时长连接，以及达到资源上限时连接被拒、控制服务仍然响应
- **必须覆盖的场景**：
  1. DNS 写入成功但响应丢失，随后面板重启；迟到的旧解析采样不能把记录改回旧入口。
  2. 换 IP 已执行但 HTTP 超时，节点重启或控制断开；同一动作不再调用接口，重连后恢复对同一动作的观察；结果无法确定时冻结后续自动换 IP。
  3. 策略③切到备用成员后，新 IP 复检始终异常：留在备用成员，记无改善，达到 2 次后暂停并通知。复检全部未知时记待确认，不累计无改善。
  4. 自测轮未知，同时检测点集合在一轮中变化、缺报、检测点自身网络异常：补判结果符合三态规则，未知轮中断连续计数。
  5. 全部入口被墙、全部出口故障、同节点属于多个入口组时换 IP：不发生无限动作，不直连，额度共用，可切离的组先切离。
  6. 旧 TTL 较长、同名残留 AAAA、DNSPod 返回成功但递归解析仍是旧值：不误报污染，不改非受管记录；传播期间发生新故障能立即再切换。
  7. 出口换 IP 时部分入口离线，同时轮换证书或凭据：应用进度如实展示，重连后收敛。
  8. 单节点升级时新版本启动失败、自检失败、面板失联：前两者回滚，后者记未确认、不回滚；维护中不触发切换，维护期满后重新评估。
  9. 离线期间事件与流量重传、节点计数重置、历史清理、从旧备份恢复：不重复计数，不绕过额度，不盲目改 DNS，新配置版本高于节点高水位。
  10. 错误的节点身份、错证书、越权目标、被撤销后的已有流、离线期间删除的规则在重连后不复活；节点无法冒充其他节点上报检测结果。
  11. 面板重启 90 秒宽限内不判离线；入口离线但没有国内检测点时只通知、不切换。
  12. 回切抖动：首选入口恢复不足 1 分钟、驻留不足 2 分钟时不回切，真实故障打断驻留；手动切换后不自动回切，手动恢复后才回切。
  13. 安装票据过期、并发重复兑换；改密码撤销会话；吊销 token 断开已有控制流；伪造代理头和跨源写入被拒。
  14. 出口授权未确认时，入口不把该出口作为新规则的候选。
  15. 配置部分应用失败后重启，已撤销的规则不复活；批量导入预检失败时不写入任何数据；实际 bind 冲突显式报错。
  16. 许可过期或重复投递时不换 IP；关键动作持久化失败时不调用外部接口；手动换 IP 不受限额约束，但与进行中的换 IP 互斥。
  17. TCP 半关闭、连接取消、达到连接或缓冲上限时资源被清理，控制服务继续响应。
- **现有先例**：仓库尚无代码，测试台本身是第一块要建的基础设施，随切片 1 一起交付。

## Out of Scope

- **后移到 v1 之后（ADR 0003，模型和接口现在就预留）**：itdog 全国拨测（含地图）；WS + 预共享密钥隧道传输；最小连接数出口策略与后备出口组；批量升级；Cloudflare 等第二家 DNS 服务商。
- **不做**：UDP、IPv6 转发、多跳链路、PROXY protocol、限速、IP 黑白名单、两步验证、多用户、arm64、面板内置 HTTPS、目标主备与目标切换、NAT 或多 IP 节点的自动换 IP、第三方拨测结果驱动自动动作（ADR 0002）、节点自己改 DNS、离线授权到期、手动换 IP 以外的限额突破。
- 前端自动化测试。

## Further Notes

- **交付顺序**：每个切片都可独立验收。完成条件是：通过 API 创建配置，用真实 TCP 验证转发，并通过本切片对应的必测场景。
  1. **可管理的直连**：认证会话、SQLite、节点安装与控制流、配置版本与部分应用语义、单成员基础入口组（DNS 绑定处于"未发布"状态）、直连规则、端口冲突、同步状态、直连资源限制，以及集群测试台。
  2. **单出口隧道**：WSS 自签证书、入口—出口凭据、授权代次与逐流授权、yamux、单成员出口组、流量与连接数统计、隧道资源上限。
  3. **节点本地容灾**：出口组多成员主备、真实握手探测、故障归属、失联下继续切换。
  4. **只观察的运维**：探针与分钟曲线、自测、国内检测点与补判、离线判定、事件日志、Telegram，以及手动添加域名的只读解析监控。
  5. **受控入口发布**：入口组多成员、DNSPod 受管记录、入口动作协调器、入口切换与回切、手动切换与暂停回切、入口组域名自动加入解析监控、受管记录偏差写回、被墙策略②。
  6. **自动换 IP**：执行许可、额度与冻结、手动换 IP、被墙策略①，再联动策略③、跨组换 IP 和出口被墙处理。
  7. **运维补齐**：单节点升级与回滚、版本兼容、面板 CLI 升级与备份恢复、保留期设置、规则 JSON 导入导出、随机端口。
- 被墙判定以自测为主是用户有意的取舍（ADR 0004）：本机出站故障会被误当成被墙，只封入站的情况会漏判；靠换 IP 的冷却、限额和无改善暂停兜底，界面要如实标注证据来源。
