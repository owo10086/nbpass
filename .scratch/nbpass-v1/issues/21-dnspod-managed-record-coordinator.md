# 21: DNSPod 受管记录绑定与入口动作协调器

**What to build:** 管理员为入口组绑定域名和一条 DNSPod 受管记录，记录唯一绑定账号、域名、记录 ID 和线路，DNSPod 凭据加密存储。绑定时面板读回并展示当前记录值，拒绝非 A 记录和多线路，提示同名其他 A/AAAA 记录可能造成的影响。首次发布须由管理员显式确定活动入口，经入口动作协调器写入。协调器为每个入口组维护一个串行队列：外部动作先持久化动作 ID、旧值、新值再执行，分阶段记录"期望已变更 / 服务商已写入"；写入超时记"结果未确认"，先读回核对再决定；面板重启后先核对 DNSPod 上的实际记录，再继续未完成的动作。DNS 服务商接口抽象为"读取记录 / 写入记录"，v1 实现 DNSPod。

- [x] 非 A 记录、多线路被拒；同名存在其他 A/AAAA 记录时给出提示，不删除
- [x] 首次发布后，假 DNSPod 上的记录值为活动入口 IP，TTL 60 秒；其他记录不变
- [x] DNSPod 写入成功但响应丢失时，动作为结果未确认，读回核对后完成，不重复写

- **模型与迁移**：追加迁移 **8**，新增 `dns_accounts`、`managed_records`、`entry_publications`、`entry_actions`。受管记录保存账号、DNSPod 主域名、记录 ID、子域名和线路 ID；唯一约束采用 `provider + 规范化主域名 + record_id`，比账号内唯一更严格，避免同账号不同 Token/本地账号别名重复接管同一记录。域名支持 IDNA 规范化。发布后不再允许重新绑定；未完成动作阻止删除入口组，活动成员不能直接移除。**未使用 protobuf 字段号，70–79 保留。**
- **账号与秘密**：`POST /api/dns-accounts` 接收 `{name,token_id,token}`；`GET /api/dns-accounts` 仅返回账号 ID、名称、服务商与 configured。Token ID 和 Token 一并进入已有 AES-256-GCM 秘密存储，秘密名称为 `dnspod.<account_id>`；数据库账号表不保存凭据。面板状态、动作和事件只使用固定安全摘要，不存第三方原始错误、请求或响应。物理测试正向确认密文已进入 WAL/主库，并检查两者不含 Token ID/Token 明文，重开后仍能解密。
- **绑定 API 与校验**：`GET/PUT /api/entry-groups/{id}/managed-record`，PUT 接收 `{account_id,domain,record_id,line_id}`；domain 是 DNSPod 主域名，记录的子域名由服务商读回。只支持启用、DNS-only、IPv4 值的 A 记录；拒绝非 A、代理、安全中心 `use_aqb=yes`、线路不匹配及同名 A/AAAA 多线路。绑定读回当前值、原 TTL、完整同名列表，返回 `warnings` 提示其他 A/AAAA 可能分散流量或走 IPv6，不删除任何记录，绑定本身不写 DNS。
- **DNS 服务商边界**：新增 `internal/dnsprovider.Provider` 的 `ReadRecord/WriteRecord` 接口与 `Dependencies.DNSProvider`；默认实现为 DNSPod HTTPS API Token 适配器，调用 `Record.Info`、分页 `Record.List`、`Record.Modify`，只改绑定记录。读取必须覆盖完整同名列表，核对 Info/List 中受管记录的一致性；未见受管记录、分页不完整或超过上限时停止。默认不继承环境代理，拒绝重定向，响应上限 2 MiB；一次完整调用期限为注入时钟的 **10 秒**。核对了 DNSPod 官方 `get-record-info`、`record-list`、`modify-records` 文档，未调用真实账号。
- **首次发布与地址决定**：`POST /api/entry-groups/{id}/publish` 接收 `{active_node_id,ipv4,confirm_inbound:true}`，成功返回 202 和持久化动作；活动入口须是本组成员，IPv4 须是单个有效公网地址，重复首次发布返回 409。票 17 的 `public_ipv4` 仅是出站观测，因此不直接拿它发布；管理员必须明确提供并确认可直接入站的 IPv4，发布端点独立保存在入口组期望中。就绪/自动候选由票 23 接续，本票不以确认按钮宣称入站探测已通过。
- **协调器与恢复**：每组一条持久化串行队列，保存动作 ID、期望版本、活动入口、旧值/原 TTL、新值、开始写入标记、阶段和写入确认时间。提交动作、更新期望与记录事件同一事务完成；提交或开始标记持久化失败均不调用服务商写入。每次执行先读实际记录，再落盘开始标记，然后只写该 A 记录及 TTL **60 秒**。阶段为“期望已变更 / 结果未确认 / 服务商已写入”；任何写入错误按未确认处理，**5 秒**后先读回，已是新值且 TTL 正确时完成原动作，不重复写。读回失败或绑定属性变化时停写等待核对；已尝试动作若实际值既非旧值也非新值，保持未确认，不擅自覆盖第三方改动。重启只恢复未完成动作，并先读回再续做。写入确认时间作为驻留计时的保守起点；响应丢失时无法还原服务商实际提交时刻。
- **版本与生命周期**：`GET /api/entry-groups/{id}/publication` 用同一只读事务返回期望、当前动作和写入时间；`GET /api/entry-groups/{id}/actions` 返回最近 100 个动作。动作结果按动作 ID/版本更新，只有仍是当前动作时才推进组级状态，旧结果不改新期望。各组独立执行，不持有全局控制锁等待外部服务；成功即释放队列，空队列安全回收 worker，面板关闭取消并等待在途调用。传播观察及换 IP 额度不在本票范围，不将“服务商已写入”标为递归解析已生效。
- **界面**：入口组新增“受管记录与发布”弹窗；支持添加 DNSPod 账号、绑定并读回值/TTL、同名记录提示、明确选择活动入口、确认可入站 IPv4 后首次发布，以及查看期望版本、活动入口、动作 ID、阶段、旧/新值和写入时间。账号保存或关闭弹窗会清空凭据表单；完成写入后刷新服务商最近确认值。
- **测试台与 TDD**：新增可注入的 `clusterharness.DNSPod` 假服务和 `PersistenceFaults`（真实 SQLite 的 INSERT/UPDATE 故障，认证与读取不受影响）。新增 **13 个 HTTP 测试台顶层场景 + 1 个存储物理场景**；HTTP 场景覆盖唯一归属与账号别名、非 A/多线路、其他记录保留、首次显式确认、公网地址/成员校验、TTL 60、响应丢失读回、写入中重建、三处持久化失败、凭据脱敏、注入时钟超时、并发首次发布只接收一次、跨组执行隔离、绑定后服务商属性变化、编辑已发布入口组状态，以及真实适配器的 HTTPS 请求、分页和安全代理拒绝。业务操作及断言均通过面板 HTTP API 和假外部服务，真实节点代码用于 DNS 主要场景；独立白盒只检查加密存储物理属性。账号/绑定/发布接口最初 404，真实适配器最初 502，删除在途组、编辑发布状态及安全代理漏检均先观察失败再修正。
