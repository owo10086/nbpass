# 36: 面板命令行升级、备份与从旧备份恢复

**What to build:** 面板命令行升级前先做一致性的在线 SQLite 备份，再执行迁移；迁移失败时 CLI 输出与文档写明恢复范围（程序、数据库、密钥文件），备份附带恢复所需的密钥说明。从旧备份恢复后，自动写操作全部暂停，并清理所有登录会话和安装票据。节点重连时上报配置版本高水位和动作执行记录，面板把新配置版本抬到高于高水位。无法重建最近 24 小时换 IP 尝试记录的节点暂停自动换 IP，直到记录补齐或 24 小时保护窗口过去；无法核对的节点及其入口组继续暂停相关的自动写操作。

**Blocked by:** 22, 30

**Status:** ready-for-human

**Refs:** 规格用户故事 126、127；必测场景 9（恢复部分）；规格「备份与面板升级 CLI」

- [x] 恢复后下发的配置版本高于节点高水位，节点接受
- [x] 恢复前的会话和安装票据失效
- [x] 节点上报的换 IP 动作记录用于重建额度，不能重建的节点暂停自动换 IP

## Comments

2026-11-09 实施记录（分支 `ticket/36`，仅在指定工作目录实施；未创建工作树，未修改 docs/ 或其他票）：

- **CLI 与备份**：新增 `backup -data-dir <源目录> -backup-dir <新备份目录> [-program <程序>]`、`upgrade -data-dir <源目录> -backup-dir <新备份目录> -program <已安装旧程序>`、`restore -backup-dir <备份目录> -data-dir <新的不存在目录>`。备份用 SQLite `VACUUM INTO` 生成包含已提交 WAL 的一致性快照，不迁移源库、不启动后台任务；备份包含 `panel.db`、`panel.key`、`nbpass`、SHA256 清单与中文 `RECOVERY.md`。目录 0700，数据 0600，程序 0700；升级必须先停服务，与正常进程共用数据锁，备份完成才执行事务迁移。
- **回退范围与程序兼容**：升级不替换旧程序；迁移失败时事务回滚，原数据库、原密钥和原程序仍保留，直接重启原服务，不重复同一失败迁移。备份中的旧程序仅配未迁移的原数据库和原密钥用于原地回退；从旧快照执行 `restore` 后，应使用执行恢复的兼容程序启动，不能用旧二进制打开已迁移数据库。恢复先校验摘要及数据库加密哨兵，在暂存目录中迁移、设置保护并撤销凭据，再原子发布新目录；拒绝覆盖现有目录。
- **恢复保护与核对**：恢复时撤销全部登录会话和安装票据，清除旧配置确认、旧在线状态和当前自测判定，保留历史；旧自测补报不能触发当前自动决策。新增认证、同源保护的 `GET /api/recovery` 与 `POST /api/recovery/reconcile {"confirm":true}`。采用显式、按节点和入口组核对后放行；无法核对的成员使相关入口组继续暂停。DNSPod 核对只读，采用能唯一对应已核对成员的实际记录、提高期望版本并封存旧队列，不重放旧 DNS 写入；已放行组不会被重复核对干扰。
- **配置高水位与动作恢复**：只有活性报告可消费恢复证据，其他独立报告不推进恢复。未收到高水位时不发旧快照；首次报告后生成 `max(面板期望版本,节点高水位)+1` 的新配置及摘要。节点持久化动作尝试时间和日志覆盖起点，补报完整动作进度；当前动作即使超过 24 小时仍单独补报，可沿用原核对/解除接口。正常额度与恢复记录按动作 ID 去重统计，重复补报不重复计数，手动解除不清额度。未知动作、未核对节点或入口组均不能签发新许可，旧授权永不重放。
- **24 小时保护与歧义决定**：旧节点日志缺乏时间证据时从本次升级起保守计算覆盖；截断动作报告时同步缩小覆盖，采用节点采样时间作为截止，不能用接收时间跨越缺口。最近 24 小时历史无法重建时暂停自动换 IP，记录补齐或恢复满 24 小时才解除这项保护；节点/组未核对与未知动作的门禁仍有效。管理员手动换 IP 可绕过“仅历史不足”，仍受其他恢复门禁。可信的较新当前动作可封存旧快照待办，明确原结果未知、额度保留；未知签发配置的复检只记待确认，不伪造恢复成功。恢复后新建资源不继承旧恢复名单，但加入未核对旧组仍受组门禁。
- **迁移与协议**：按任务明确的第 22 版基线追加 **迁移 23 `recoveryMigration`**，增加恢复状态、节点/组核对和恢复额度账本；父级通用规则现提及其他并行迁移，合并时由维护者重排本票版本。只用分配号段内的 **200–204**：`NodeReport.recovery=200`；`RecoveryReport.high_water=200,history_since=201,actions=202,observed_at=203,current=204`；`RecoveryRotation.action_id=200,attempted_at=201,state=202,progress=203`。已运行 `make proto` 生成 Go 文件。
