# 15: 事件日志与节点离线补报

**What to build:** 面板有统一的事件日志，先记录节点上线、同步失败等事件，后续票继续添加事件类型。节点有有界持久化本地事件队列：离线期间存关键事件，重连后补报，面板按事件 ID 去重，溢出时标记缺口。

**Blocked by:** 02

**Status:** ready-for-human

**Refs:** 规格用户故事 112、113；规格「事件与通知」「本地事件队列」

- [x] 事件日志可按节点、类型、时间筛选
- [x] 节点失联期间产生的事件在重连后出现在日志中，重复投递不重复
- [x] 节点重启后尚未补报的事件不丢失
- [x] 本地队列溢出时日志显示缺口；最多补报 24 小时
- [x] 以上行为由测试台通过面板 HTTP API 验证
- [ ] 事件日志页（人工验收）

## Comments

2026-11-09 实施记录（仅当前 `ticket/15` 工作目录；未修改 docs/ 或其他票，未推送、合并或切换分支）：

- **面板存储与查询**：新增迁移 **3**，表 `events` 及节点/类型/发生时间索引；迁移 SQL 独立放在 `internal/panel/events.go`，现有迁移列表仅追加引用。认证后的 `GET /api/events` 支持 `node_id`、`type`、`from`、`to`，时间使用 RFC3339，按发生时间筛选且包含两端。结果按入库序号倒序；`limit` 默认 100、上限 1000，使用 `before` 与响应的 `next_before` 分页。返回发生时间、收到时间、节点、来源、事件 ID、配置版本、安全摘要和缺口详情。
- **统一事件入口**：`internal/eventlog.Event` 定义事件契约；类型允许扩展，消息限制 2048 字节。`Panel.RecordEvent(ctx, nodeID, event)` 为面板生产者入口，空 ID/时间由面板补齐；`EventQueue.Record(ctx, type, message, revision)` 为节点生产者入口。真实控制会话首个有效报告记录 `node_online`，真实节点进程启动记录 `node_started`；同步失败测试经真实节点生产者写入 `sync_failed`。票 02 基线没有规则同步执行器，实际逐规则失败由票 03/04 调用上述入口，不在本票实现同步引擎。调用者只能提交安全摘要，不提交凭据、请求头或第三方原始响应。
- **协议与去重**：控制协议仍为版本 1，新增 `NodeReport.events = 15`、`PanelMessage.acknowledged_event_ids = 15`，并新增 `Event`/`EventGap` 消息；生成的 `internal/controlpb/control.pb.go` 已更新。每批最多 16 条，保留既有 64 KiB gRPC 消息上限；整批事务提交后才确认，节点将确认持久化后才删除。满批且有确认进展时立即发送下一批，其余沿用 10 秒活性周期，旧面板不确认时也不会忙循环。去重键为“已认证节点 + 来源 + 事件 ID”，避免节点之间或节点与面板事件之间互相占用 ID；消息自带节点身份不能覆盖会话身份。面板重启后去重仍有效。
- **持久队列与物理边界**：新增 `node.EventStore`、`OpenEventQueue`、可注入的 `Dependencies.Events`；标准 `FileStore` 自动启用持久队列。自定义凭据 Store 如需启用同样能力，须实现 `EventStore` 或显式注入队列。待发区默认最多 4096 条且序列化事件总量不超过 4 MiB，另预留最多 16 条持久化在途事件及至多 4 条缺口摘要；整个队列始终有界。容量不足淘汰最老的待发事件，在途事件等待确认，避免将已交付事件误报为缺失。待发缺口按原因合并，发出后冻结，后续新缺口单独累计，确认旧批次不会删除新缺口。
- **磁盘保证**：`events.enc` 与凭据复用本机密钥，使用独立 AES-GCM 关联数据；目录 0700，密钥和事件文件 0600，拒绝符号链接和不安全权限。使用临时文件、文件同步、原子替换和目录同步；写失败不发布新的内存状态，确认落盘失败保留原批次供重传。损坏密文会报错，不静默清空历史。事件文件读取另有 8 MiB 硬上限。
- **歧义决定**：24 小时按事件发生时间计算，恰好 24 小时允许补报，超过则删除内容并留下 `expired` 缺口；容量淘汰记 `overflow`，均含数量与起止时间。缺口属于丢失历史的摘要，即使描述的时间更早也保留补报，避免整段历史消失而无提示。面板再次校验补报期限，拒收内容过期的报告并以缺口摘要替代；超过面板时钟 5 分钟的未来事件拒收。事件 ID 去重限定节点和来源；列表按入库顺序稳定分页，同时保留发生时间供追查。以上补齐未明确的工程细节，无需修改规格。
- **页面**：新增 `web/src/Events.tsx`，主导航增加事件日志；支持节点、类型、起止时间筛选、刷新、继续加载，展示发生/收到时间、配置版本，以及醒目的溢出/过期缺口和缺失数量；空结果、加载错误和会话过期沿用既有约定。
- **测试与审查**：新增 6 个 HTTP 测试台场景，使用真实节点、真实 TLS/gRPC 和真实加密文件队列。业务断言仅通过面板 HTTP API，节点事件生产者及网络故障作为环境驱动；覆盖筛选/认证、离线重启、确认落盘失败后的重投与面板重启去重、溢出、24 小时精确边界、40 条跨批次补报和游标不重叠。另新增 4 个包内物理测试覆盖字节上限、权限/加密/损坏检测、冻结缺口、写入/确认失败、并发生产者和在途确认。首轮 HTTP 用例以缺少 API 的 404 失败，审查发现的在途缺口误报也先用回归复现再修复；只读复核无剩余阻塞问题。原双节点离线测试在大幅快进时钟后继续推进重试时钟，避免只等待真实传输而冻结重连；生产活性期限保持既有约定。
