# 08: 单成员出口组上的隧道规则

**What to build:** 管理员把一个出口节点放进出口组，创建隧道规则（入口组监听端口 → 出口组 → 目标）。面板为出口生成身份名称稳定的自签证书，入口只信任这张证书；每对入口—出口有独立的隧道凭据，只在 TLS 建立后发送。入口经 WSS + yamux 把流量交给出口，出口解析域名目标并拨号。

**Blocked by:** 03

**Status:** ready-for-human

**Refs:** 规格用户故事 28、29（隧道部分）、39、40、41、43、51（单出口）；规格「隧道服务端（出口）」

- [x] 出口证书由面板生成，有效期 5 年，身份名称不随 IP 变化
- [x] 入口不使用系统根证书、绝不跳过校验；出示错误证书的出口握手失败
- [x] 入口—出口凭据按对生成、加密存储、只在 TLS 建立后发送；错误凭据被拒
- [x] 隧道规则的域名目标由出口解析
- [x] 测试台用真实 TCP 验证：流量经入口 → WSS/yamux → 出口 → 目标到达
- [x] 唯一出口不可用时新连接失败，不直连目标
- [ ] 出口组、隧道规则编辑界面（人工验收）

## Comments

2026-11-09 实施记录（分支 `ticket/08`，仅修改当前工作目录；未创建工作树、未修改 docs/ 或其他票）：

- **链路与协议**：沿用票 03 的 `forwarding.Rule`、完整 `ConfigSnapshot`、`mutateForwarding/compileSnapshots` 和 `Engine.Apply`，增加 `kind:"tunnel"`、单成员出口组及节点级 WSS 出口配置。入口 → 标准 RFC6455 WSS → yamux → 出口 → TCP 目标全程使用真实实现；依赖固定为 `github.com/coder/websocket v1.8.15`、`github.com/hashicorp/yamux v0.1.2`。每对入口—出口复用一个会话，同一出口跨规则/出口组共享；控制失联后已有进程继续转发。隧道协议独立为版本 1，使用 `/nbpass/tunnel/v1` 和 `nbpass.tunnel.v1` 子协议，认证及逐流消息均用最多 4096 字节的长度帧，精确消费控制消息，不吞业务数据。
- **证书与凭据**：面板为每出口独立生成 P-256 自签证书，DNS SAN 为随机稳定身份 `exit-<hex>.nbpass.internal`，有效期恰为 5 年，不绑定 IP；更换地址/端口或重启面板保留原证书。入口从空的 `x509.NewCertPool` 建立该出口专用信任，执行正常有效期、签名、名称校验，并精确核对叶证书 DER；没有系统根、跳过校验或明文降级。WSS/TLS 验证完成后才在加密数据帧发送入口身份与节点对凭据，不把秘密放在 URL 或 HTTP 头。每对入口—出口使用独立随机 256 位凭据，出口常量时间比较，错误凭据拒绝。
- **数据面与后续授权接缝**：每流只提交规则 ID，出口从自身 `TunnelGrant` 配置取得允许的目标，按认证入口归属匹配，域名由出口解析；沿用票 03 的 IPv4、多 A 地址预算及逐地址私网许可。唯一出口不可达则关闭业务连接，不退回直连。无关规则/名称改动保留会话和连接，目标变更/入口停用撤销旧入口监听与连接；端点变更淘汰该出口的旧会话。节点探针分别报告逻辑业务连接与 WSS/yamux 载体连接，出口也计逻辑流；兼任入口和出口时按节点身份去重本机入口已计量的业务。规则累计流量仍由票 10 接续。
- **存储与迁移**：追加迁移 **8**（基线最后为 7），新增 `tunnel_exits`、`exit_groups`、有序 `exit_group_members`、`tunnel_pairs`，为规则增加 `exit_group_id`，为 `node_snapshots` 增加 `encrypted` 标记。出口私钥和节点对凭据使用既有 AES-256-GCM 本机密钥加密，并以出口/节点对身份作关联数据。因为快照也包含秘密，新增/变更的完整快照整体加密并绑定节点 ID；兼容读取旧版不含秘密的明文快照，版本和摘要语义保持票 03 约定。私钥只下发相应出口，入口只收到自己相关的节点对凭据与出口证书；无关节点不收到这些秘密，管理 API 不返回完整秘密。同步上报仍复用既有独立配置报告及失败事件，不改变活性、探针或事件的隔离。
- **protobuf**：只使用分配的字段号 **40–59**：`ConfigSnapshot.exit_groups=40/tunnel_server=41`，`ForwardRule.exit_group_id=40`；新 `TunnelEndpoint` 使用 40–47，`ExitGroup` 使用 40–42，`TunnelPeer`、`TunnelGrant` 使用 40–41，`TunnelServer` 使用 40–46。新增隧道规则、WSS 传输、主备策略枚举值均为 40；控制协议版本保持 1。生成源码通过 `make proto` 获得，未手改 `control.pb.go`。
- **管理 API 与页面**：新增 `GET /api/tunnel-exits`、`PUT /api/nodes/{id}/tunnel`（`address`、`listen_port`、`transport:"wss"`）；新增 `GET/POST /api/exit-groups`、`PUT/DELETE /api/exit-groups/{id}`（`name`、`members:[node_id]`、`strategy:"primary_backup"`）。出口组只接收已配置 WSS 的单成员，仍被任意规则引用时删除返回 409。规则沿用 `/api/rules`，隧道须指定有效 `exit_group_id`，直连不使用出口组。沿用管理员认证、严格 JSON、同源写入及错误响应。新增出口组页面及出口地址/监听端口编辑弹窗；规则页面可选直连/隧道、指定出口组并展示链路。
- **歧义决定与范围**：出口端点由管理员明确配置可入站的 IPv4，不把票 17 的出站公网 IP 观测值默认为可入站地址；允许管理员明确配置私网/回环出口端点以支持受信网络及测试，目标私网许可仍单独检查。票 09 接续独立授权代次、出口应用确认门禁及已有流每秒复查，本票只预留最小逐流身份/规则/固定目标接缝，不拿节点 revision 当跨节点授权。因此初次配置传播期间尚不能承诺授权确认后才开入口监听。票 11 接续可调流容量、强制 reset 与完整取消清理；当前 yamux 的 `Close` 是写半关闭，包装只额外解除本地读阻塞，不能宣称已完成远端流立即回收；库默认 5 分钟半关闭期限也须由票 11 调整。握手已加 3 秒、目标/逐流建连 10 秒基本期限，但不替代票 11 的完整资源验收。节点重启离线缓存由票 04 接续，证书轮换、多出口健康及主备切换按后续票实施。没有阻塞票 08 的开放问题。
