# 13: 出口证书与隧道凭据轮换

**What to build:** 管理员可以轮换出口证书和入口—出口隧道凭据。轮换时新旧并存，所有相关入口确认后撤下旧的，最长重叠 7 天；到期仍有入口未确认时保留旧证书并提示，不强行撤下。离线入口重连后收敛。

**Status:** ready-for-human

## Comments

2026-11-09 实施记录（分支 `ticket/13`；仅在当前工作目录实施，未创建工作树、未修改 docs/ 或其他票）：

- **轮换流程**：沿用票 08 的专用自签信任、加密存储、完整配置快照和票 09 的独立配置成功报告。支持 `certificate`、`credentials`、`both` 三种管理员操作。持久化阶段为 `preparing`（出口保留旧证书并接受新旧凭据）→ `distributing`（出口准备已确认，入口使用新凭据并信任新旧两张精确叶证书）→ `activating`（所有当前相关入口确认，出口切换新证书、拒绝旧凭据的新会话与新流）→ `cleaning`（出口撤旧已确认，等待入口清理旧证书信任）→ `complete`。每次证书轮换生成新 P-256 密钥和 5 年自签证书，保留原稳定 SAN；仅轮换证书不更换凭据，仅轮换凭据不更换证书。
- **确认与恢复**：业务变更、确认记录及后续快照仍在同一事务内编译、提交，再通知控制流。只接受当前认证节点、当前会话/进程、当前期望 revision 与精确摘要的完整成功、撤销落盘确认；探针、事件、活性、自测、DNS、流量及换 IP 进度均不推进轮换。重复确认不制造版本，旧/超前/失败/错误摘要报告均不能推进。状态跨面板重启保留；离线入口不因时间自然流逝被视为确认，重连应用最新快照后继续收敛。轮换不改规则授权代次，新增规则继续遵守票 09 的出口授权确认门禁。
- **不中断与撤旧语义**：仅有轮换标识的证书/凭据变化保留入口监听；入口为新流改用新载体，旧载体由引用计数等待已有流结束后回收。出口通过 TLS 握手时读取当前证书更新身份，不重启监听或关闭 WSS/yamux。已通过认证的业务流继续按当前入口归属、规则、授权代次及目标每秒原子复查；轮换凭据不撤销这些流，删除/停用/换代仍撤销。每个新流继续校验会话凭据，旧载体也不能绕过；轮换期间已取旧载体、尚未授权的拨号若失败，只在配置确有更新且尚未交付数据时、同一次 10 秒预算内使用当前载体重试一次。无轮换标识的普通配置变化保留票 08/09 原有撤销与缓存语义。
- **期限与展示**：7 天从管理员发起时间计算，恰满 7 天且仍未完成即在进度 API/页面显示提示，不强制撤掉未确认入口需要的旧材料。出口已撤旧但入口清理尚未确认时显示独立 `cleaning` 阶段和相应提示，不能提前显示完成。页面按入口展示名称、确认状态及当前控制连接是否连接，并每 5 秒刷新；控制连接未连接不等于票 02 的 90 秒离线判定。提示通过轮换页面提供，不新增 Telegram 或定时任务。
- **关联变更与兼容决定**：只要求当前启用隧道规则实际关联的入口确认，不让已解除关联的历史节点对阻塞；在所有阶段清理已解除关联的确认参与者。凭据轮换激活时作废未参与的历史节点对，重新关联会生成全新凭据，不能复活旧凭据。准备/分发阶段可加入支持轮换的入口，仍由票 09 门禁先确认其出口授权；撤旧及清理阶段暂时拒绝新增关联入口（409），等待当前轮换完成，避免已发出的撤旧快照绕过新增入口确认。旧节点缺少能力字段按 0，发起轮换要求出口与所有相关入口声明版本 1；进行中拒绝不支持轮换的相关替代进程，不把新能力提前下发给旧版本。未发起轮换时原有滚动互通路径保持。
- **管理 API**：新增 `POST /api/nodes/{id}/tunnel/rotation`（`{kind:"certificate"|"credentials"|"both"}`，202；进行中重复发起返回 409）及 `GET /api/nodes/{id}/tunnel/rotation`。状态包含阶段、开始/期限、逐入口确认、当前待确认数量、超期提示与出口是否已撤旧；管理 API 不回显私钥或节点对凭据。沿用管理员认证、同源写入、严格 JSON 和错误响应。出口组页增加轮换按钮、操作确认和进度弹窗。
