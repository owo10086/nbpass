# 34: 维护中状态与单节点一键升级、回滚

**What to build:** 节点列表标出版本与面板不一致的节点。管理员一键升级单个节点到面板内置的同版本程序：面板生成绑定任务 ID、版本、平台、大小、SHA256 的清单，经已验证的 TLS 下发；独立的更新服务只接受固定产物和固定安装路径，下载、校验、自检后再替换并重启，新版本启动失败或本地业务自检失败时回滚。升级中的节点进入有期限（10 分钟）的维护中，期间离线不触发入口切换和换 IP；到期后按当前证据重新评估。

- **任务与清单**：新增 `POST /api/nodes/{id}/upgrade`、`GET /api/nodes/{id}/upgrade`。只向在线且声明更新服务可达的单节点签发任务；拒绝重复任务及进行中/未确认的换 IP 动作。任务 ID、目标版本、`linux/amd64`、大小和 SHA256 一起持久化，任务创建与 10 分钟维护状态在同一事务提交。节点列表增加面板版本、版本不一致标记、更新能力和最近任务。任务资源位于 `/node-upgrades/{task}/manifest|artifact`，只接受该执行节点的当前 Bearer token，任务结束或维护期满后拒绝获取，当前内嵌产物与清单不符也拒绝分发。
- **独立更新服务**：新增 `internal/nodeupdate`；固定 HTTPS 面板源与固定任务资源，校验证书，拒绝重定向、任意下载地址、安装路径、命令、额外 JSON 字段。完整比较控制任务与 HTTPS 权威清单，再核对下载大小、SHA256、候选程序自检返回的版本和平台。安装器只允许 `/usr/local/bin/nbpass-node`，检查父目录与文件，拒绝符号链接及非普通文件。候选与备份在 root 所有、0700 的 `/usr/local/bin/.nbpass-update` 中生成；候选自检后再次核对内容，然后原子替换。正式程序和回滚程序显式设为 0755，避免 systemd 的 UMask=0077 导致普通节点用户无法执行。
- **服务权限与安装**：`cmd/nbpass-node` 增加 `-update-check` 与 `-update-service -update-origin ...`，同一构建以独立不可变副本安装为 `/usr/local/libexec/nbpass-update`，运行独立的 `nbpass-update.service`；节点重启不影响更新器。节点 unit 使用普通账户 `nbpass-node`，仅保留监听低端口所需的 `CAP_NET_BIND_SERVICE`；更新器为 root，通过 root:nbpass-node、0660 的固定 Unix socket 接收清单。更新服务和安装暂存均在节点用户不可写的目录中，安装暂存不会随节点数据目录 chown。更新器只读取节点 runtime 健康目录，避免 systemd 重建目录造成旧挂载或首次安装路径不存在的问题。现有节点需重跑安装命令以安装服务；有专用 CA 的部署需为更新服务设置相应 `-ca-file`。
- **自检、替换与回滚**：下载、校验和候选自检先完成，再持久化备份和安装事务、替换并重启。3 分钟内检查新进程本地规则、检测监听及每条隧道规则的本进程授权握手；缓存中的成功结果不能代替新检查。健康记录绑定 systemd MainPID、版本、运行中程序 SHA256 和新鲜时间。启动或本地业务检查失败均恢复旧程序并重启。安装事务可在更新服务重启时恢复，回滚通过备份副本安装，旧服务暂时启动失败或回滚中断后仍可再次恢复。更新服务退出先等待当前任务/回滚结束。
- **安全状态保留**：不对可变节点数据目录做旧快照覆盖；配置缓存、撤权检查点、凭据、本机密钥、事件/流量与换 IP 日志均保留当前状态。由当前缓存格式直接供旧程序重建，从而不会复活升级开始后已撤销的规则，也不会清除换 IP 动作与额度证据。跨版本状态格式兼容范围仍由票 35 补齐，不宣称支持任意旧程序降级。
