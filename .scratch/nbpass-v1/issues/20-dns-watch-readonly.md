# 20: 手动添加域名的只读解析监控

**What to build:** 管理员手动添加任意域名进行解析监控，期望 IP 可选。国内检测点向国内公共 DNS 查询，面板本机用 DoH 查询作对照，解析器列表可配置。每 5 分钟查询一次，记录解析变化历史、变化次数和出现过的不同 IP 数。有期望值时，同一路径对同一期望连续 3 次不符才判异常；疑似污染、解析失败只通知，不触发任何写操作。

**Status:** ready-for-human

## Comments

2026-11-09 实施记录（仅当前 `ticket/20` 工作目录；沿用既有分支，不创建工作树，不修改 docs/ 或其他票）：

- **实现与只读边界**：新增 `internal/dnswatch` 共享模型及面板 `dns_watch*` 文件，手工域名支持 IDNA、小写与去尾点规范化、重复拒绝和可选期望 IPv4 集合。提供 `GET/POST /api/dns-watches`、`GET/PUT/DELETE /api/dns-watches/{id}`；PUT 只修改期望，域名不可原地改名。监控不调用 DNS 服务商、入口动作协调器、切换或换 IP；异常只经 `Panel.RecordEvent` 与 `Panel.QueueTelegram`。相同持续状态不重复告警，异常状态改变后重新记录；事件与通知各有持久化待处理进度和独立扫描窗口，通知失败或积压超过 32 条不阻断事件与采样。
- **解析器与调度**：`GET/PUT /api/settings/dns-watch` 配置全局 1–8 个解析器，至少保留一个面板 DoH；国内 DNS 使用公共 IPv4 的 53 端口，DoH 使用不带凭据、查询参数或片段的 HTTPS 地址。默认国内 DNS 为 `223.5.5.5:53`、`119.29.29.29:53`，DoH 为 `https://cloudflare-dns.com/dns-query`。新增及设置/期望改变后开始新一轮，平时每 5 分钟调度，后台检查粒度 1 秒；每个执行位置最多 4 项并行，排队不消耗期限，认领后 30 秒内收结果，每次外部查询期限 10 秒，均走注入时钟。快进和延误不补造遗漏轮次。国内资格沿用票 17：有效地区为中国大陆、角色未关闭、当前连接支持 DNS 采样、真实活性未过期且非维护；旧节点不支持新能力时不派发，不伪造覆盖。无有效国内路径显示“国内覆盖缺失”，有节点但仅配置 DoH 时同样显示缺失。
- **协议与隔离**：控制协议仍为 1，`NodeReport.dns_watch_only=100`、`dns_watch_results=101`、`dns_watch_capable=102`；`PanelMessage.dns_watch_tasks=100`。新消息 `DNSWatchTask` 字段为 `task_id=100/domain=101/resolver=102/expires_at=103/expected_version=104/round=105`；`DNSWatchResult` 为 `task_id=100/ips=101/failed=102`，全部位于 **100–109**。仅修改 proto 后运行 `make proto` 生成 Go，未手改生成源码。任务独立于配置快照发送；结果只消费 DNS 载荷，不更新活性、配置确认、探针、节点 IP 或事件/ACK。结果绑定认证节点、进程实例、任务 ID、期望版本和轮次，过期、重复、已撤销资格、旧版本及旧设置结果不生效；断流取消本流查询，结果不跨流迁移。
- **真实解析与注入**：面板、节点均通过 `DNSWatchLookup func(context.Context,string,dnswatch.Resolver)([]string,error)` 注入，测试台默认替换，验收不访问公网。生产国内 DNS 直接构造绝对域名 A 报文，绕过 hosts、系统 DNS 和 search/ndots；UDP 截断回退 TCP。DoH 使用 RFC 8484 POST，不继承环境代理、不跟随重定向、响应上限 64 KiB；核对响应 ID、问题、类型与 Class，名称比较不区分大小写。只读取问题及 CNAME 链的 A，AAAA 和无关答案不进入样本。外部原始错误和响应不进入事件或通知。
- **比对、历史与歧义决定**：期望 IP 是允许集合，只要本次非空 A 集合全部位于允许集合即符合，不要求一次返回全部期望地址。无期望时仅观察，仍报告采样失败。按“检测点/面板 + 解析器 + 期望版本”累计连续证据，失败、缺轮、角色缺失或期望改变中断计数；连续 3 次不符记“期望不符”，同时其他有效路径命中期望才记“疑似污染”。首次成功只建基线；后续成功地址集合变化按路径累计一次变化，顺序或重复不算变化；失败保留成功基线并记失败历史，不增加变化次数。不同 IP 数是所有路径成功地址的去重总数。详情返回每路径观察值、连续计数、采样时间和最近 100 条历史，支持 `before` 游标；统计与历史跨面板重建保留。解析监控只支持 A，不把 AAAA 当作污染证据。手工域名没有切换旧 TTL 窗口。
- **复用与后续票**：`dnswatch.Resolver`、`Expectation`、`Progress.Observe` 与规范化地址集合可由票 26 复用；期望模型含版本、旧 IP 集合及旧 TTL 截止接缝，命中窗口内旧值不累计异常。持久样本按监控 ID、路径、期望版本和轮次组织，配置修订与监控任务互不推进。票 26 可在同一 panel 包接入入口组期望、30 秒传播调度及连续命中计数，权威记录偏差仍须调用票 21 的唯一协调器，递归样本不得直接写 DNS。本票未实现入口组自动纳管、传播生效判定或写回。
