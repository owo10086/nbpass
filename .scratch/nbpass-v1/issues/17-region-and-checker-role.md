# 17: 地区识别与国内检测点角色

**What to build:** 面板依据 ip2region 离线库识别节点地区，中国大陆节点默认承担国内检测点角色。管理员可手动覆盖地区或关闭某节点的检测点角色。节点 IP 变化后自动重新识别地区。

**Blocked by:** 02

**Status:** ready-for-human

**Refs:** 规格用户故事 23、24、25

- [x] 中国大陆节点自动成为国内检测点，其他地区不是
- [x] 管理员覆盖的地区优先于自动识别；IP 变化后不被自动结果改写
- [x] 关闭检测点角色后，该节点不再承担检测点
- [x] 节点上报的 IP 变化后自动重新识别地区
- [x] 测试台使用假 ip2region；以上行为由测试台通过面板 HTTP API 验证
- [ ] 节点列表显示地区与检测点角色（人工验收）

## Comments

2026-11-09 实施记录（仅在 `ticket/17` 当前工作目录实施；未修改 docs/ 或其他票）：

- **实现与离线库**：新增 `internal/ipregion`，面板 CLI 加载内嵌 ip2region IPv4 库并经 `Dependencies.RegionLookup` 注入真实面板核心。Go 绑定和数据固定于上游提交 `6a276cc7c4f9`（绑定版本 `v0.0.0-20261028042204-6a276cc7c4f9`），随包保留上游许可；数据 SHA-256 为 `46249ad1b33bcaa4cc37475b93746cec2b00acffc3316cc4f56167ac821ea2ad`。识别在本机完成，依据国家码并排除港澳台判断中国大陆，每次查询使用独立 searcher、共享只读数据。
- **节点 IP 与兼容**：真实节点通过可注入的 `node.Dependencies.PublicIPv4` 查询出站公网 IPv4，默认 HTTPS `https://api.ipify.org`，不继承环境代理、不跟随重定向。每次 10 秒活性周期前查询，期限 5 秒、响应上限 64 字节，期限使用注入时钟；查询失败、非法/保留/非公网地址或 IPv6 不改写最后有效观测，也不阻止活性。`NodeReport.public_ipv4` 使用 protobuf **字段号 17**，协议版本仍为 1；旧节点未上报该字段时不清空已知 IP。该地址只代表出站观测，不证明可直接入站，不更新业务端点、DNS 或触发换 IP。
- **存储与规则**：在基线迁移 1、2 后新增 **迁移版本 3**，建立独立 `node_regions` 表，不修改旧迁移；合并其他并行票时须统一迁移顺序和编号。自动地区、人工覆盖及关闭开关分别持久化。有效地区为人工覆盖优先；中国大陆且未关闭开关才具有国内检测点角色。IP 改变只更新自动结果，不改人工覆盖或关闭开关；识别失败时自动地区为“未知”、不自动承担角色，同一 IP 后续报告可重试识别。旧节点和待接入节点默认为未知。
- **HTTP API 与界面**：`GET /api/nodes` 新增 `public_ipv4`、`region`、`automatic_region`（地区对象为 `{name, mainland_china}`）、`region_source`（`auto/manual`）、`domestic_checker`、`checker_disabled` 和面板生成的 `checker_label`。`PUT /api/nodes/{id}/region` 接收地区对象，JSON `null` 恢复最新自动地区；`PUT /api/nodes/{id}/checker` 接收 `{"enabled":true/false}`，开启仅解除人工关闭，仍受大陆地区条件约束。沿用管理员认证、同源写入、严格 JSON 与错误状态约定。节点列表展示地区、来源、IP、角色，新增“地区与检测点”弹窗；所有角色状态由 API 给出。
- **歧义决定与范围**：人工覆盖允许明确填写地区名和是否中国大陆，不从自由文本猜测角色；恢复自动地区不重开已关闭的角色。角色属于节点资格，在线、维护、同轮对照站点、排除自己等实际任务有效性由后续检测调度票处理；本票不实现检测任务、判墙、DNS 或换 IP。无阻塞实施的开放问题；公网查询依赖第三方可达性和离线库精度，均保留未知/人工覆盖路径。
- **TDD 与验收**：新增 7 个顶层测试台场景；真实节点、protobuf/gRPC/TLS 与面板核心均运行，业务操作与断言只走面板 HTTP API。主要验收使用假 ip2region 和假公网 IP 查询；另通过同一 HTTP 边界验证真实内嵌库对大陆、美国、香港、澳门、台湾地址的分类。覆盖 IP 变化、覆盖优先与恢复自动、关闭开关跨报告/变化/重启保存、查询失败/响应超限/地址校验/超时，以及管理 API 门禁和错误输入。初始地区字段缺失、地区/角色管理 API 缺失、离线适配器返回未知、无效查询覆盖有效 IP、查询无超时均观察到对应 red 后实现并转绿。

人工验收清单（尚未执行，保留上述人工复选框未勾选）：

1. 合并后执行 `make build`，通过可信 HTTPS 代理登录面板，接入中国大陆和非大陆 Linux amd64 节点；确认地区、IP、自动识别来源与国内检测点角色展示正确，港澳台不自动成为国内检测点，桌面和窄屏可使用新增弹窗。
2. 在大陆节点点击“地区与检测点”，手动改为非大陆地区并保存，确认显示人工覆盖且不承担角色；改变真实节点公网 IPv4，等待后续报告，确认自动识别值更新而人工地区不变。关闭手动覆盖后，恢复当前自动识别值。
3. 将大陆节点的“允许承担国内检测点角色”关闭，确认列表显示已关闭；重启面板、重启节点及更换 IP 后仍保持关闭。再次开启后，只在有效地区为中国大陆时恢复角色。
4. 在真实 Linux 节点验证公网查询源的 TLS 可达性；临时阻断查询源，确认活性继续、最后有效 IP 保留，首次查询一直失败的新节点显示未知且不承担角色。恢复访问后应更新地区。此项不证明地址可入站、全国可达或实际检测执行成功。
