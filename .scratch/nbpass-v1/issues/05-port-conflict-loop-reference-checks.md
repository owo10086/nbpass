# 05: 端口冲突、转发循环与删除引用校验

**What to build:** 保存规则时，面板逐个成员节点检查监听端口冲突（其他规则、隧道监听、检测端口），冲突时指明哪个节点的哪个端口；同一节点加入多个入口组时也不会撞端口。配置编译器拒绝会形成转发循环的配置。删除节点时列出它还被哪些规则、入口组、出口组引用。

**Blocked by:** 03

**Status:** ready-for-human

**Refs:** 规格用户故事 26、31；规格「部署形态」（转发循环）「配置编译器」「检测端口」

- [x] 同一节点属于两个入口组，两组规则使用同一监听端口时保存被拒，提示具体节点和端口
- [x] 节点的隧道监听端口和固定检测端口参与冲突校验（这两个端口先在模型中定义，即使对应功能尚未实现）
- [x] 规则目标指向本规则自己的入口监听等循环配置被拒
- [x] 删除仍被引用的节点时返回引用清单，不留下悬空配置
- [x] 以上行为由测试台通过面板 HTTP API 验证
- [ ] 冲突与引用提示界面（人工验收）

## Comments

2026-11-09 实施记录（分支 `ticket/05`，仅当前工作目录；未创建工作树、未修改 docs/ 或其他票）：

- **统一配置校验**：在 `compileSnapshots` 生成快照前调用 `forwarding.ValidateConfiguration`，按每个实际成员节点汇总所有入口组的启用监听。规则创建、修改、重新启用、入口组成员修改及节点保留端口修改共用同一事务边界；冲突返回 HTTP 409、`code:port_conflict` 与结构化 `listeners`，文字包含节点名称/ID、具体端口及占用者。失败回滚业务记录、成员关系和期望配置版本；并发保存同一端口只有一项成功。不把规则自身无变化更新判成冲突。
- **端口模型与迁移**：追加迁移 **8**（`listenerPortsMigration`），向 `nodes` 增加 `tunnel_listen_port`、`check_port`，数据库约束范围为 1–65535，默认分别为 **18443 / 18080**。`forwarding.NodeListenerPorts` 定义同名字段；`GET/PUT /api/nodes/{id}/listener-ports` 读取和整体设置，服务端校验两类服务及规则之间的冲突，配置重启后保留。两项服务尚未实现，端口现在即预留；本票不实际监听、不下发未实现的服务配置，单改预留端口不会伪造节点应用版本。**protobuf 未改动，30–39 号段未使用**。
- **循环校验**：对“节点 × 启用规则”建立有向图，拒绝本规则自连、同节点多条规则成环，以及目标指向其他已知节点 IPv4 的跨节点循环；错误返回 `code:forwarding_loop`、节点/端口/规则路径。识别整个 127.0.0.0/8、规范化后的 localhost、当前可解析域名别名及多 A 结果；仍遵守目标的私网许可。`Dependencies.LookupIPv4` 注入外部解析器，默认使用面板的 IPv4 解析器；测试台默认禁用外网解析，域名用例注入确定答案。只对目标端口可能接入已有规则监听的域名解析，并对整次配置事务共享 **2 秒**解析预算。
- **静态校验边界**：循环检查利用当前已知的节点观测 IPv4 和面板此刻的 DNS 结果，只把观测地址用于保守识别目标，不将其当成已验证发布地址。地址未知、解析失败或预算耗尽时仅检查能证明的图；无法保证面板与实际入口的 DNS 视图一致，也无法保证未来 DNS/IP 变化后的运行路径。后续入口发布/隧道票应把实际服务端点及真正拨目标的节点接入同一图。DNS 解析当前仍位于配置事务和控制锁内，有需要时可能使控制/API 延迟最多约 2 秒；这是已记录的非阻断改进点，未为本票引入新的协调器或异步配置状态。
- **节点引用与删除**：新增 `GET /api/nodes/{id}/references` 和 `DELETE /api/nodes/{id}`。引用清单为 `{kind,id,name}`，包括入口组以及经入口组引用节点的所有规则（停用规则也包含），去重并稳定排序；有引用时 DELETE 返回 HTTP 409、`code:node_referenced` 和完整 `references`，不删关联业务配置。无引用时在同一事务中清理安装票据、旧进程记录、探针、地区及节点快照并删除节点；提交成功才撤销活动流和已鉴权待首报告的流，旧 token 与未兑换票据都不能重新接入。删除失败全部回滚，事件历史保留，数据库外键继续兜底防止悬空引用。
- **出口组最小接缝**：基线尚无出口组，未提前创建其迁移、管理 API 或隧道功能。引用查询兼容 `exit_groups(id,name)`、`exit_group_members(group_id,node_id)`；若已有 `forward_rules.exit_group_id`，同时列出经出口组引用该节点的规则。不存在上述表/字段时不查询。测试只建立后续关系的 SQLite 夹具，删除拒绝与引用结果仍由面板 HTTP API 断言；后续票采用不同表结构时需调整该查询接缝。
- **界面**：节点操作新增“监听端口”和“删除”。前者提示两项端口目前预留并显示具体冲突；后者先读取引用清单，列出规则/入口组/出口组及可复制 ID，有引用时禁用确认删除。服务端在真正删除时仍重新检查，以覆盖预览后的并发变化。`APIError` 保留结构化错误，处理迟到的 409 清单；规则保存冲突沿用已有规则弹窗内的错误提示。
- **TDD 与复核**：新增 **10 个 HTTP 测试台场景**及 **1 个含 3 子场景的物理传输回归**。覆盖跨组冲突、不同节点可复用端口、成员修改回滚、停用/启用、保留端口修改与持久化、自连/间接/跨节点/域名多 A 环路、引用清单、删除及凭据失效、出口关系兼容、存储故障回滚、并发冲突、认证与同源保护。初轮观察到重复监听/循环返回 201、缺少 API 返回 404 的 RED；域名用例临时忽略解析结果后再次确认 RED，再恢复 GREEN。慢 HTTP 响应的三项回归先稳定复现凭据吊销被阻塞，修复为 `commitForwarding/removeNode` 返回、事务和控制锁释放后才写响应，引用 GET 也在写出前结束读事务。只读独立审查及修复复核未发现剩余必须修复项，未额外生成审查文件。
- **最终验证**：`env -u FORCE_COLOR make test` 全绿（npm ci、TypeScript/Vite、节点包构建、go vet、全仓 go test）；修复后重新运行 `go test -race ./... -count=1` 全绿。面板与节点分别使用 `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath` 交叉编译成功，`file` 确认为静态链接 x86-64 ELF；`git diff --check` 通过。Vite 延续已有 AntD 大于 500 kB 的非阻断提示。人工页面、Linux 部署及真实代理验收未执行。
- **歧义决定**：停用规则不占实际监听，重新启用时统一校验，但仍阻止删除其引用节点；预留端口无论服务是否启用都占用；规格没有给出服务端口号，选用上述默认值并允许按节点调整为稳定值。保留现阶段入口组单成员限制，不实现多成员发布、隧道、检测执行器或随机端口。开放限制为上述静态地址/DNS 边界及后续出口组接缝，界面与真实部署仍待人工验收。
- **生成产物**：本票需要合并后重新生成前端。提交前按并行规则还原 `web/dist`、`internal/nodebundle`，并移除本轮新增的未跟踪 dist 文件；合并后请运行 `make build`。未修改节点执行器或控制协议，本票不单独依赖新的节点二进制行为。

人工验收清单（以下待执行，不以自动化通过代替）：

1. 合并后 `make build`，经可信 HTTPS 代理登录。将一个真实节点加入两个单成员入口组，分别保存同一监听端口的启用规则；第二次应留在编辑弹窗，明确显示节点名称/ID、端口及冲突规则，失败不能新增规则或推进期望版本。
2. 在节点“监听端口”查看默认 18443/18080；分别尝试规则占用这两个端口、把预留端口改成已有规则端口、把两项预留端口设为相同值，均应提示冲突并保留原值。改成空闲端口后刷新、重启仍保留。此项不代表隧道/检测服务已实际监听。
3. 创建目标指向自身 localhost/127.0.0.1 且端口等于监听端口的规则，应提示循环及节点/端口路径；再用可控域名 A 指向节点已知 IPv4 验证域名路径，确保与实际入口 DNS 视图一致。已知规则成环不得保存。
4. 点击被引用节点的“删除”，应显示入口组和转发规则清单，包含停用规则且不能确认删除。移除引用后重新打开，确认删除应移除节点并使旧安装票据/token 失效。出口组真实界面及其管理 API 待票 08 接入后按相同清单复验。
5. 桌面与窄屏检查两个新增弹窗、长名称/ID、冲突文字换行、表格滚动、加载失败和会话失效；预览后并发新增引用时，服务端 409 应更新引用清单而不误删节点。

后续扩展点：复用 `NodeListenerPorts`、统一编译事务与 `ValidateConfiguration`，将实际服务端点和隧道目标执行节点纳入校验；按上述出口关系接缝扩展引用查询。后续开始实际下发服务端口时，应纳入配置快照与 revision，不通过活性/探针/事件报告相互推进状态。
