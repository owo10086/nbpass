# 26: 入口组域名解析监控、传播观察与偏差写回

**What to build:** 入口组域名自动加入解析监控，以活动入口为期望值。入口切换后每 30 秒查询，展示"传播中 / 已生效 / 传播未确认"：每条有采样的路径在本期望版本下连续 2 次命中期望值、且其中至少一条国内路径，才记已生效；最长观察时间取"旧记录 TTL × 2"与 10 分钟中的较大者，最多 1 小时。传播观察不阻塞协调器队列，新动作使旧观察失效。DNSPod 上的实际记录与期望不符时由协调器写回；递归解析的差异不触发写回；旧记录 TTL 内的旧值不算污染。

**Blocked by:** 20, 24

**Status:** ready-for-agent

**Refs:** 规格用户故事 59（观察值部分）、69（后两个阶段）、99、102、103、105、106；必测场景 1（迟到采样部分）、6；规格「解析监控·生效判定」「入口动作协调器·传播观察不阻塞队列」

- [ ] 有人在假 DNSPod 上改了受管记录时，协调器写回
- [ ] DNSPod 记录正确但递归解析仍返回旧值时不写回，旧 TTL 内不报污染
- [ ] 传播观察期间发生新的故障切换时立即执行，旧观察失效
- [ ] 迟到的旧解析采样不会把记录改回旧入口
- [ ] 到最长观察时间仍未满足时记"传播未确认"并通知，不标已生效
- [ ] 同名残留 AAAA 记录不被修改，也不误报污染
- [ ] 以上行为由测试台通过面板 HTTP API、假 DNSPod 与假解析器验证
- [ ] 入口组详情显示各解析路径的观察值和切换进度（人工验收）
