# 38: 规则 JSON 导入导出与随机端口

**What to build:** 管理员可把规则批量导出为带格式版本号的 JSON，默认不含任何秘密；批量导入时先整体预检（引用、端口冲突、格式），明确是新增还是覆盖，全部通过才写入。创建规则时可选随机端口，由面板挑一个在入口组所有成员上都空闲的端口。

**Blocked by:** 05, 09

**Status:** ready-for-human

**Refs:** 规格用户故事 30、35、36；必测场景 15（导入部分）

- [x] 导出的 JSON 带格式版本号，不含任何秘密
- [x] 导入预检任一失败时不写入任何数据，并逐条给出原因
- [x] 导入明确区分新增与覆盖
- [x] 随机端口只选一次，在所有成员上都空闲（含隧道监听和检测端口）

## Comments

2026-11-09 实施记录（分支 `ticket/38`，基线 `e7958e2`；仅本工作目录，未创建工作树、未修改 docs/ 或其他票）：

- **规则 JSON 与导出**：新增 `GET /api/rules/export`，默认导出全部规则，重复查询参数 `id` 可选择规则；选中不存在的 ID 返回 404。文档格式为 `{"format_version":1,"rules":[规则定义]}`，只从 `forwarding.Rule` 序列化白名单业务字段，不从同步视图或节点快照导出，不含控制 token、安装票据、隧道凭据/私钥、DNS/Telegram/换 IP 秘密、授权代次、统计或运行状态。引用使用稳定的入口组/出口组 ID，不同时导入节点或组。
- **整体预检与原子提交**：新增 `POST /api/rules/import/preflight` 与 `POST /api/rules/import`，请求为 `{"mode":"create|overwrite","document":上述文档}`。两者先在同一控制锁与数据库事务中解析每条规则、校验格式和引用、构造最终规则集合、检查全部成员端口及静态循环；确认接口重新执行完整预检。预检成功还暂存并编译完整配置，随后回滚，既不推进 revision、发布授权，也不通知节点；确认成功才原子提交业务、配置快照、授权代次及流量来源并通知控制连接。后行存储失败也完整回滚前行。保存后各节点的实际应用状态仍由既有独立配置报告确认，不把导入成功当成同步成功。
- **新增/覆盖语义**：`create` 总是分配新 ID，忽略文件中的源 ID；`overwrite` 要求每条 ID 已存在，只更新这些规则，不隐式新增、不删除未导入规则。任何模式均拒绝批内重复的非空源 ID；覆盖保留规则 ID，沿用已有累计量与授权高水位。校验整批最终状态，允许两条规则合法交换端口。预检生成的新增 ID 不预留，确认时重新分配；页面不把预检 ID 当成已保存对象。
- **格式与错误归属**：格式版本仅支持 1；每次请求上限 1 MiB、每批 1–500 条。严格拒绝未知字段、无效类型、缺失或 null 必填项、不支持版本、重复键及大小写映射重复键、过深嵌套和尾随 JSON；键比较沿用 Go JSON 解码的 Unicode 简单折叠，包含 long s、Kelvin 字符等映射。文档整体语法错误返回 400；可解析规则的格式、引用、端口与循环错误按从 1 开始的 `results.index` 返回，整批返回 `valid:false` 与未写入说明。普通保存和批量预检共用完整监听冲突收集及强连通分量环路校验，三条同端口和共享规则在不同成员上的多个环均不会漏标。每行仅保留首处简短原因、最多两条相关监听引用，并用 `conflict_count` 告知相关端点数，避免大批冲突产生平方大小的响应。整次聚合静态校验共用一次 2 秒 DNS 预算，保留原有当前 DNS/观测 IPv4 的保守证明边界。
- **随机端口**：普通 `POST /api/rules` 新增 `random_port:true`，此时监听端口须省略或为 0；同时手填端口或编辑时重新随机均返回 400。在创建事务内对入口组所有成员的启用规则（含其他入口组）、预留隧道端口、检测端口及实际 WSS 监听端口取占用并集，从 **1024–65535** 的共同空闲集合随机选定一个具体值；该值随规则持久化，编译、同步、重连和重启均不再抽取。并发创建串行检查，不能选到同一启用端口；无共同空闲端口返回 409。停用规则沿用票 05 的不占监听语义，重新启用时仍重新校验。
- **多成员最小接缝与范围决定**：当前基线入口组保存仍限制单成员，但本票必须经 HTTP 验证全部成员。将现有有序成员保存开放为 1–64 个，逐个检查存在性、拒绝空值与重复、保留成员顺序；移除活动入口仍须先通过入口动作完成切换。编辑页面同步保留全部成员，防止单选编辑丢失其他成员。仅补规则分发和校验所需接缝，不实现自动切换、就绪候选或新发布策略。面板所谓“空闲”指当前配置没有占用，无法预知节点上其他进程或保存后的 OS bind 竞争；实际监听失败继续逐规则上报，不自动换端口。端口冲突规则已足以拒绝整批，其其他成员上的潜在循环可能在修正端口后下一次预检才显露。
- **页面**：规则表支持选择导出或导出全部 JSON；导入弹窗支持选文件/粘贴、明确新增或覆盖、先整体预检、逐行原因/冲突数量及确认导入。文件原始 JSON 保留至服务端校验，避免浏览器解析后折叠重复键；修改内容或模式清除旧预检，提交失败保留错误与源内容。创建规则可打开随机端口，保存后显示最终端口，编辑仍使用固定端口；沿用认证/会话失效和同源保护。刷新会剔除已删除的导出选择。
- **TDD 与独立复核**：新增 **13 个 HTTP 测试台顶层场景**（JSON 11、随机端口 2），业务断言只经面板 API，运行真实面板、SQLite、节点、TLS/gRPC，直连及隧道另经真实 TCP/WSS/yamux 验证。多节点共享测试主机时仅注入监听绑定隔离，各节点仍运行真实同步代码。覆盖导出白名单/选择/认证、新增/覆盖/持久化、预检不写、逐行聚合、版本/格式/重复 ID/重复键、端口交换、预检后冲突重验、批内冲突/环路、跨成员共享环路、存储失败回滚、隧道新建及覆盖的出口确认门禁、同源保护，以及随机端口全部成员避让、并发和重启不重选。缺少 API、随机参数/多成员被拒均先 RED；独立只读审查发现的三条同端口漏标、冲突证据复制增长、共享规则多环和大小写重复键均补回归先 RED 后 GREEN。最后补充 Unicode 等价字段回归，先观察到重复字段误返回 200，再统一简单折叠规则并转 GREEN；只读增量复核确认折叠与 Go 解码一致、不修改字段值，核心修复无剩余必须修复项。未额外创建审查或执行报告。

人工验收清单（以下尚未执行；首部界面项保留未勾选）：

1. 合并后 `make build`，经生产 HTTPS 代理登录；在桌面和窄屏检查规则表选择、导出全部/所选、导入文件与粘贴弹窗、加载与错误换行、分页及会话失效。下载 JSON 后重新选入，确认可解析、版本为 1、仅含所选规则定义，无任何凭据或运行状态。
2. 在 JSON 中分别制造不存在的入口组/出口组、非法端口/字段类型和三条同端口规则；整体预检应逐行报错，合法首行也不得保存，节点期望版本不变。确认重复键（含大小写混写）、不支持版本、缺必填项、超大文件不能导入；修改内容或模式后必须重新预检。
3. 选择新增，明确新 ID 与原规则无关、原规则保留；跨面板迁移先准备节点与组并在 JSON 中替换组 ID。选择覆盖须使用存在的规则 ID，确认只更新指定规则、不创建未知 ID 或删除未列入规则。预检通过后由另一会话抢占端口，再确认应整批拒绝。
4. 接入两个真实 Linux 节点，加入同一入口组；在其中一员的其他入口组占用端口，并设置隧道预留/实际监听、检测端口。创建随机端口规则，核对各成员监听同一最终端口，且避开全部配置占用；刷新、控制重连及面板/节点重启后保持该端口。外部进程抢占所选端口时应报告同步失败，不悄悄另选端口。
5. 导入直连规则后通过真实 TCP 验证目标可达；导入或覆盖隧道目标时，阻断出口配置确认应保持入口门禁，恢复确认后才允许新业务。保存成功与各成员同步状态应分开显示，离线成员保留待确认。
6. 编辑多成员入口组并保存，确认成员与顺序完整保留；尝试重复成员、不存在的第二成员或移除当前活动入口时应拒绝并保留原配置。真实 Linux 防火墙、OS 端口竞争、生产代理和页面视觉仍需人工核验，不以测试台通过代替。

后续扩展点：沿用 `storeRule`、`commitForwarding/compileSnapshots` 和 `ConfigurationErrors` 接入将来的规则字段；更新格式版本或显式迁移旧格式，不能把隧道秘密或只读视图字段加入规则导出。后续多成员/就绪票沿用有序成员及逐成员同步，不把随机分配或预检当成实际监听确认。
