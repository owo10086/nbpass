# 24: 活动入口离线时自动切换

**What to build:** 活动入口离线（90 秒）后，面板请国内检测点确认它确实连不上，确认后由协调器切到一个候选成员。没有可用国内检测点时只通知、不切换；没有候选时保留最后的解析、停止切换并通知，不删除记录。切换写入事件日志并发 Telegram 通知，通知失败不阻塞切换。

**Blocked by:** 16, 22, 23

**Status:** ready-for-human

**Refs:** 规格用户故事 60、61、63、114（切换部分）；必测场景 11；ADR 0005

- [x] 活动入口控制链路断开且检测点连不上它时，假 DNSPod 记录改为候选成员
- [x] 面板与该节点断开、但检测点能连上它时不切换
- [x] 没有可用国内检测点时只通知，不切换
- [x] 没有候选时记录不变，并通知
- [x] 假 Telegram 失败不阻塞切换
- [x] 以上行为由测试台通过面板 HTTP API 与假 DNSPod 验证

## Comments

2026-11-09 实施记录（分支 `ticket/24`；仅在指定目录工作，未创建工作树、未修改 docs/ 或其他票）：

- **离线确认**：沿用票 16 的离线事故、严格超过 90 秒的判定及面板启动宽限。后台为已发布入口组的活动入口创建独立确认轮次，冻结事故、期望版本、目标 IPv4、检测端口、配置版本、国内检测点集合与 60 秒截止时间。复用票 19 的任务传输、身份核验、原始证据校验和真实节点执行器；不创建自测轮次，不推进自测计数、配置确认或控制活性。任一有效检测点连上即不切换；固定集合无缺报且所有有效检测点都连不上才确认不可达。对照站点全部失败、零有效结果、缺报或执行错误均不能确认不可达。
- **自动切换**：确认不可达后，重新使用票 23 的按组就绪和国内证据门禁，按入口组成员顺序选择第一个候选。与手动操作保持 `entryMu → controlMu` 锁序，动作及期望版本在同一事务经 `submitEntryActionTx` 提交现有协调器，DNS 写入、超时读回及恢复继续沿用票 21/22。提交事务复核当前事故、活动入口、期望版本、地址、端口、配置与维护状态；动作提交前再次检查候选采样、国内证据及控制活性期限，任何失效都回滚动作、版本和事件。手动操作、节点恢复、地址往返变化、配置变化、进入维护都会令未完成旧确认失效。故障切换不受自动回切暂停或驻留保护约束，恢复后不会自动回切。
- **保留解析与通知**：没有可用检测点/有效确认时只通知；没有候选时停止本次切换，保留最后的受管记录，不删除记录。每个事故、入口组和期望版本合并通知，相同原因不重复刷屏；后台最多每 60 秒用新一轮确认重新评估。切换完成记录 `entry_failover`，等待原因记录 `entry_failover_waiting`，另保留协调器原有的全部 `entry_action` 阶段。通知由持久化决策和动作重新构造，经已有 Telegram 队列异步投递；外部发送失败或通知队列写入失败不阻塞切换，队列失败也不遮蔽切换事件，恢复后可续投。
- **只读证据**：新增认证后的 `GET /api/entry-groups/{id}/offline-checks`，返回最近 20 次确认的目标、版本、截止时间、固定检测点原始结果、决策和动作 ID。HTTP 读取不发起检测、不制造候选成功样本、不触发切换。沿用既有页面显示发布阶段、候选状态和事件日志，本票不新增界面。
- **验收对应与 TDD**：新增 10 个 HTTP 测试台顶层场景及 1 个迁移物理场景。`TestEntryOfflineConfirmedFailureSwitchesAndNotifies` 对应第 1 项并验证事件/通知与无重复切换；`TestEntryOfflineReachableFromCheckerDoesNotSwitch` 对应第 2 项（成功优先于失败）；`TestEntryOfflineNoCoverageOrNoCandidatePreservesRecordAndNotifies` 的无检测点、对照失败、执行错误和无候选子场景对应第 3/4 项；`TestEntryOfflineTelegramFailureDoesNotBlockSwitch` 对应第 5 项。全部业务操作与断言只通过面板 HTTP API，DNS 最终值与写入次数由假 DNSPod 验证，节点使用真实 TLS/gRPC/转发/检测代码，符合第 6 项。另覆盖通知队列故障、缺报、手动操作与恢复等旧结果失效、候选维护、90 秒精确边界、面板重启宽限及维护结束重新观察。首次 API 404、通知队列失败时事件缺失、提交期间证据恰好过期仍切换均先观察 RED，再修正至 GREEN；没有放宽生产期限或业务断言。
- **歧义决定**：故障切换相关的“无有效确认/无候选”通知在决策形成时入队，独立于票 16 的普通节点离线两分钟通知。沿用已有“恰好 90 秒仍在观察，超过才离线”的边界。无候选意味着停止本次动作；后续一分钟可以用新证据重评，旧失败证据不无限复用。活动入口检测目标使用已确认发布的单个公网 IPv4；若当前节点地址与发布地址不一致，本票保守暂停自动切换，地址协调仍由后续票处理。没有其他规格行为偏离或阻塞实施的开放问题。
