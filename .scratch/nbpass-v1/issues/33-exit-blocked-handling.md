## Comments

2026-11-09 实施记录（分支 `ticket/33`，仅在指定工作目录实施；未创建工作树，未修改 docs/ 或其他票）：

- **实现与接口**：新增 `GET/PUT /api/nodes/{id}/exit-blocked`，写入 `{enabled:true|false}`；出口处理默认关闭。开启后仍须配置节点换 IP 接口、自测与节点自动换 IP 总授权。出口与入口组用途共同申请原有 `authorizeRotation`，共用节点级串行许可、小时/日额度、冷却、维护、风险限制、复检、无改善暂停与结果未确认冻结，不新增商家调用通道。
- **地址更新**：首次确认公网 IP 变化时，同一事务更新出口端点、持久化本次地址版本（换 IP 动作 ID）、编译全部相关入口快照，提交后立即推送。手动换 IP 或入口组用途引发的换 IP 也会更新该节点的出口地址，避免角色之间留旧地址；关闭出口自动处理只禁止新的出口用途申请，不取消已授权动作。沿用稳定证书身份、逐规则授权门禁和证书/凭据轮换，不直接写 DNS；入口用途的受管记录仍走原有协调器。
- **逐入口进度**：`exit_address_progress` 独立保存“已应用”和“已握手”。应用只由当前认证会话、进程、精确期望 revision/摘要、完整应用且撤销检查点落盘成功的配置报告确认；握手只消费真实 WSS/节点对认证/yamux 探测成功、地址版本匹配且十秒内的新鲜探针。两类确认独立，其他独立报告无法代为推进。离线参与者保留待确认，重连依靠完整快照收敛；已确认记录为本次地址更新的历史进度，控制连接状态另列，不声称当前链路实时健康。
- **参与者与兼容**：配置编译按最终快照登记相关入口，解除最后一条关联时撤出当前进度，重新关联须重新取得两类确认。手工编辑出口地址/端口时清除旧地址进度标识。旧节点可以应用新地址，但未携带地址版本的旧探针不会误报已握手；升级后若 JSON 缓存遗漏未知 protobuf 字段而保留旧摘要，新节点会重新验证并应用相同版本快照以补齐地址版本，不重复换 IP。
- **界面**：新增“出口组 → 出口配置 → 被墙处理与地址进度”，提供独立开关、当前地址与动作、逐入口控制连接/已应用/已握手/握手确认时间，三秒刷新；复用节点页的接口配置、自动总授权、额度与冻结操作。界面明确已有 TCP 可能在换 IP 时中断，其他出口仍可接新连接。
- **验收映射**：`TestExitBlockedRotationRestoresTunnelAndConvergesOfflineEntry` 覆盖被墙→真实节点调用假 HTTPS 商家→确认新 IP→在线入口应用与真实 TCP 隧道恢复，离线入口保留待确认、面板重建后持久化、重连收敛，且同时验证后备出口接新连接和证书/凭据轮换并行。`TestExitBlockedSharesEntryRotationQuotaAndOptIn` 覆盖默认关闭、双用途单动作/互斥、共享小时额度及释放后出口用途继续执行。另有管理员/严格布尔值边界和旧缓存升级的测试台回归；业务断言均走面板 HTTP API，网络故障与公网地址仅在外部依赖边界注入。包内物理测试覆盖版本 24 升级、独立报告隔离、旧/错/未来/过期证据、手工端点编辑及移除再关联。
