# 09: 授权代次与逐流授权

**What to build:** 每条隧道规则有独立的授权代次；出口按"规则 ID + 授权代次"核对每个新业务流的入口身份和授权目标，只拨该规则的那个目标。入口启用新规则或新授权代次之前，必须先收到出口已应用对应授权的确认。删除或停用规则后出口不再接受新流，已有流每秒复查，撤销后断开。

**Blocked by:** 04, 08

**Status:** ready-for-human

**Refs:** 规格用户故事 34（隧道部分）、44、45；必测场景 10（越权目标、撤销后已有流、离线删除不复活）、14；规格「配置编译器·授权代次」；ADR 0006

- [x] 出口尚未确认新授权代次时，入口不把它作为该规则的候选，新规则上线没有"全部被拒"的窗口
- [x] 入口请求非授权目标或冒用其他入口身份时被出口拒绝
- [x] 删除规则后，出口在 1 秒复查内断开该规则的已有流
- [x] 无关的配置版本变化不撤销未变更规则的授权，已有流不受影响
- [x] 入口离线期间删除的隧道规则：出口在线时拦住新流，入口重连后规则不复活
- [x] 以上行为由测试台通过面板 HTTP API 与真实 TCP 验证

2026-11-09 实施记录（分支 `ticket/09`，基线 `1a49228`；仅修改当前工作目录，未创建工作树，未修改 docs/ 或其他票）：

- **独立授权代次**：新增 `rule_authorizations`，每条规则保存单调递增的代次及授权内容指纹。目标地址/地址族/端口、私网许可、入口组/出口组及其成员、规则类型与启停变化才换代；名称、监听端口、其他规则和节点 revision 的变化不换代。停用或改为直连仍保存代次高水位，恢复隧道不能重用旧授权；删除规则通过外键级联清理代次和确认。授权代次只用于跨节点规则授权，不替代节点配置版本。
- **出口确认与入口门禁**：新增 `tunnel_authorization_confirmations`，按出口、入口、规则保存已确认代次。出口先收到 grants；面板只接受当前已鉴权会话、当前进程、当前期望版本及精确摘要的独立配置成功报告，并要求完整快照和撤销检查点均已应用。确认记录与重新编译的入口快照在同一事务提交，提交后才通知控制连接。新规则或新代次未确认时不下发入口监听，规则同步显示未同步；同节点兼任入口/出口也先应用仅含 grants 的快照，再生成入口规则。迟到/超前版本、错误摘要、失败、旧会话/旧进程、探针、事件和活性均不能打开授权门禁。重复确认不制造 revision。
- **逐流授权**：WSS/yamux 每个新流携带规则 ID、授权代次、入口身份和目标地址/端口/地址族；出口同时核对会话认证身份、当前节点对凭据、规则归属、代次及目标。目标拨号始终使用出口自身的授权配置，拒绝自选目标、冒用身份和旧代次，不接受入口指定解析 IP。域名解析与具体 IPv4 私网检查继续沿用票 08/03。控制、隧道认证及逐流帧的协议版本保持 1，既有消息长度上限不变。
- **持续撤销**：逐流复查使用注入的节点时钟，每秒重新核对当前凭据和授权；删除、停用、改目标或换代后，下一次复查取消该流，关闭目标及业务方向。目标尚在 DNS/拨号阶段也可取消，拨号返回后、交付成功之前再次核对授权。撤销只影响对应流，共享同一 WSS/yamux 会话的其他获授权规则继续转发。沿用票 04 的两阶段加密缓存、实际状态恢复和高水位；不设置离线授权到期，双方控制离线 48 小时仍可转发，入口离线时由在线出口拦住已撤销规则。
- **滚动兼容**：节点首报告声明 `tunnel_authorization_version=1`，面板将能力绑定到已认证节点及进程接续；旧节点缺字段按 0 处理。只从上一份完整快照识别“入口已有规则、出口已有匹配零代次 grant”的既有授权，在任一端未升级且授权内容未变时保留零代次，当前版和上一版仍可互通。新规则和变化授权不走兼容路径；旧授权撤销后再改回不能复活。双端均升级后先准备非零代次出口授权，再等待确认启用入口。出口换进程清理其确认；节点能力变化还清理以该节点为入口的远端确认，防止降级撤权后再升级复用旧确认。
