# 02: 添加节点、安装票据兑换与控制流在线

**What to build:** 管理员在面板添加节点，得到一条只带一次性安装票据的安装命令；节点程序用票据换取长期节点 token，经 TLS 验证的 gRPC 双向流连接面板，节点列表显示在线。测试台加入真实节点核心、真实 gRPC/TLS，以及可断开节点到面板控制链路的模拟网络。

**Blocked by:** 01

**Status:** ready-for-human

**Refs:** 规格用户故事 5、14、15、17（在线部分）；必测场景 13（安装票据部分）；规格「控制服务」「节点模块·控制客户端」

- [x] 安装命令只含 30 分钟有效的一次性安装票据；过期票据被拒，并发重复兑换只有一次成功
- [x] 面板只存节点 token 的哈希；同一节点同一时刻只允许一个控制会话，每轮交换重新核对 token
- [x] 节点只经 TLS 校验通过的地址连接控制端口，证书校验失败绝不降级为明文
- [x] 节点每 10 秒发送活性，节点列表显示在线与最近活性时间
- [x] 上报身份只取自已认证的控制会话，消息里自带的节点身份字段不能覆盖它
- [x] 测试台可在进程内启动多个节点核心，并断开、恢复某个节点到面板的控制链路
- [x] 以上行为由测试台通过面板 HTTP API 验证
- [ ] 节点列表与添加节点页面（人工验收）

## Comments

2026-11-08 实施记录（当前 main 工作树，未创建 worktree，未提交 Git；未修改 docs/、票 01 或其他票）：

- **入口与协议**：沿用 `panel.Open(ctx, Config, Dependencies)`，新增 `Panel.RegisterControl(grpc.ServiceRegistrar)`。`cmd/nbpass` 的占位监听已替换为明文 gRPC 服务；面板核心继续不终结 TLS。新增 `-control-url https://control.example.com`，未指定时沿用 `public-origin`；控制端口的非回环监听仍要求显式 `-trust-control-network`。协议位于 `api/control/v1/control.proto`，包含票据兑换 unary RPC 和节点主动建立的双向控制流；控制协议版本为 1，独立于软件版本 `0.1.0`。
- **生成与产物**：`make proto` 使用固定版本 Buf v1.47.2、protoc-gen-go v1.36.11、protoc-gen-go-grpc v1.6.1，不依赖预装 protoc；生成的 `internal/controlpb/*.go` 已留在工作树，两次生成 SHA-256 完全一致。`make node-bundle` 构建并压缩同版本 Linux amd64 节点程序，`internal/nodebundle` 将其内嵌供安装下载；压缩产物也已留在工作树。`make build` 构建本机面板与节点；`make linux-amd64` 构建两个 Linux amd64 二进制。
- **凭据与存储**：迁移版本为 2，新增节点、安装票据及已被替代进程实例记录。票据和节点 token 均为随机 256 位值，仅 SHA-256 摘要入面板数据库；票据在 30 分钟边界即失效，消费票据与保存 token 在同一事务完成，并发兑换只有一个成功。长期 token 只在 TLS 兑换响应中交给节点，安装命令、systemd unit、管理列表均不包含它。节点 `FileStore` 通过本机密钥与 AES-GCM 加密持久化凭据，目录 0700、密钥与 `credentials.enc` 0600；拒绝不安全权限和符号链接。凭据写失败时节点不建立控制流。
- **节点与安装**：新增独立 `cmd/nbpass-node` 和可注入时钟、存储、随机源、根证书及拨号依赖的 `internal/node.Run`。节点仅接受 HTTPS 控制地址，使用系统根或显式 CA 文件进行完整 TLS 校验，不提供跳过校验或明文降级选项。面板公开提供 `/install-node.sh` 与 `/downloads/nbpass-node-linux-amd64`，命令仅携带一次性票据。脚本在 Linux amd64 上下载内嵌程序，经 `-enroll-only` 兑换并保存凭据后注册 systemd 服务，unit 不保存票据；重置 token 后的新命令可替换旧凭据。脚本只做本票安装，不包含升级任务、更新器或回滚流程。
- **控制流隔离与撤销**：每轮报告和回包前都重验 token；认证身份来自 token，忽略消息自带的节点 ID。首报告校验通过后，新会话替代旧会话；持久记录已被替代的进程实例，拒绝其再次建流覆盖新状态。token 重置/吊销事务成功后，同时取消活动流及已鉴权、等待首报告的流；阻塞的 Recv/Send 也能结束。失效凭据或已被替代实例停止重连，普通网络故障按注入时钟持续重试；恢复网络及节点重启可复用已保存凭据。
- **状态与歧义决定**：节点立即报告一次，此后每 10 秒报告活性。可观察到断链时从断链时刻计时；静默丢包从最后活性计时，满 90 秒判离线，避免活性超时后再额外等待 90 秒。面板启动前 90 秒不判离线。未接入节点显示“待接入”，启动宽限内无法确认的旧状态显示“待确认”，不伪造为在线；断链不足 90 秒保留在线标签，但 `connected=false`，配置状态立即显示“待确认”。维护期限固定为规格默认的 10 分钟，期满或提前结束后重新观察 90 秒，不复用维护期累计失联时间。以上期限都由注入时钟驱动。
- **管理 API 与界面**：新增 `GET/POST /api/nodes`、`POST /api/nodes/{id}/token/reset`、`POST /api/nodes/{id}/token/revoke`、`PUT /api/nodes/{id}/maintenance`（`{"enabled":true/false}`）。沿用已有管理员会话、同源写入及 JSON 错误约定。列表返回节点状态、连接标记、最近活性、维护期限、软件版本、期望/已应用配置版本、配置状态。React + AntD 页面支持添加节点、复制安装命令、查看状态与版本、维护、重置及吊销；状态逻辑来自 API，前端不自行推算。
