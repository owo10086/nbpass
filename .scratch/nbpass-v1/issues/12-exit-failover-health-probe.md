# 12: 出口组主备与出口健康探测

**What to build:** 出口组可按主备顺序排列多个出口。入口每 5 秒用真实隧道握手探测各出口，连续 3 次失败或一次真实拨号失败即判故障，故障出口连续成功 60 秒后才重新作为主出口接新连接。出口切换只影响新连接，全部不可用时新连接失败、不直连。故障归属分为入口→出口、出口→目标、本地资源、配置/授权四类，只有入口→出口故障影响出口健康。节点与面板失联时这一切照常运行。

**Blocked by:** 09

**Status:** ready-for-agent

**Refs:** 规格用户故事 46–54、134；规格「转发引擎（入口）」与关键参数表

- [ ] 主出口链路断开后新连接走备出口，已有连接不迁移
- [ ] 主出口恢复不足 60 秒时仍走备出口，满 60 秒后新连接回到主出口
- [ ] 出口到不了目标时不把出口判为故障，其他规则不受影响
- [ ] 业务数据已发出后的失败直接结束连接，不换出口重放
- [ ] 每个新连接最多尝试 3 个不同出口、总计 10 秒；全部不可用时失败，不直连
- [ ] 节点与面板失联时出口探测和出口切换照常
- [ ] 探测周期带 ±10% 抖动，每节点探测并发 8，"未完成"不计为失败
- [ ] 未确认授权的出口不进入候选
- [ ] 以上行为由测试台通过面板 HTTP API 与真实 TCP 验证
- [ ] 各出口健康状态展示（人工验收）
