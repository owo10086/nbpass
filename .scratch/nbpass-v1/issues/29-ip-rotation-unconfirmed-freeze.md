# 29: 换 IP 结果未确认、动作去重与冻结

**What to build:** 节点调用换 IP 接口前持久化"动作已开始"，同一动作 ID 只调用一次接口，重复投递只恢复观察。接口超时、两个查询源结果不一致、或观察到期仍无法确定时，动作为"结果未确认"：先查 IP 核对，不立即重发；该节点后续的自动换 IP 冻结，直到核对清楚或管理员手动解除。调用后与面板失联只继续观察和记录。手动换 IP 与进行中或结果未确认的换 IP 互斥。

**Blocked by:** 04, 28

**Status:** ready-for-human

**Refs:** 规格用户故事 91、98（互斥部分）、98a（解除冻结部分）；必测场景 2、16（许可、持久化失败、互斥部分）

- [x] 接口超时后节点重建或控制断开：同一动作不再调用接口，重连后恢复对同一动作的观察
- [x] "动作已开始"持久化失败时不调用接口（测试台注入写失败）
- [x] 同一许可重复投递时不再调用接口
- [x] 结果无法确定时冻结，界面显示原因；管理员手动解除后恢复
- [x] 进行中或结果未确认时再次手动触发被拒
- [x] 以上行为由测试台通过面板 HTTP API 与假换 IP 接口验证
- [ ] 冻结状态与解除按钮（人工验收）

- **解除语义与安全边界**：手动解除明确表示管理员接受原结果未知；节点持久化 released 并补报后，面板才解除冻结与互斥。released 不等于 changed 或 cancelled，不改写原动作 IP、五次观察及调用事实，不删除动作、防重放水位或已用额度。节点落盘失败、面板进度提交失败或确认前断线均保留冻结，重连/双方重建后通过同一控制代次收敛。旧代次进度直接忽略，不能消费新管理命令或中断其控制流；迟到动作、序号与已完成动作仍沿用票 28 的隔离。控制报告继续独立，不推进配置、活性、探针或事件确认。
