# 转发规则

<a id="_2"></a>
## 批量规则

批量规则都是一行一个。

<a id="_3"></a>
### 旧格式

> 只可导入，只支持单个落地。

`名称#监听端口#目标地址#目标端口`

如果需要随机产生端口：

`名称##目标地址#目标端口`

<a id="_4"></a>
### 新格式

> 支持导入和导出，包含转发规则的详细设置。

点击批量导出，自动生成的 JSON 格式。

如果需要随机产生端口：请将 `listen_port` 改为 0 (版本 20260124+)

<a id="_5"></a>
## 同步过程

转发规则由入口和出口分别同步，同步间隔为 20s 。

单个规则创建或更新时，面板会尝试通过 grpc 立即推送给节点端，但不保证成功，可能仍需要等同步。

转发规则创建时初始状态为“未同步”，待入口节点同步后，状态会变为“正常”或“同步失败”。

如果规则长期处于“未同步”状态，则可能是以下原因：

- 规则不在可同步的范围内，如用户过期、流量不足
- 入口节点掉线

如果遇到规则“同步失败”，则很有可能是因为端口被占用。请看“节点端常见疑难问题”。

<a id="_6"></a>
## 倍率说明

- 流量为单向统计。
- 「转发规则」的流量是实际使用的流量，由入口节点上报，出口数据不计。
- 「设备组」的流量是实际使用的流量。
- 用户流量扣除的计算方式: `入口实际流量*入口倍率 + 出口实际流量*出口倍率`

举例：用户 A 今日使用转发规则下载了 500M，上传了 100M 数据。入口倍率是 1.5x，出口倍率是 0.5x。

1. 此条规则流量会增加 600M 已用流量（由入口上报）
2. 用户 A 已消耗流量会增加 `600*1.5 + 600*0.5 = 1200 MB` （由入口、出口分别上报）
3. 统计中，用户 A 今日使用的流量是: 600M （由入口上报）
4. 入口组和出口组的已用流量，均增加 600M (注1)
5. 入口和出口服务器的网卡统计数据， 上传、下载 均增加 600M (注1)

注1: 由于统计方式不同，可能存在少量差距，属于正常现象。
