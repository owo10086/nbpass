# 动态多级转发链

用端点组组织多层路径，配置保存的转发链、智能选择与固定前后跳数。

动态多级转发链把中转与落地按层组织：每层可以是一组候选，层与层之间按拓扑连接。

```text
客户端 → 入口 worker → IX 候选组 → 落地候选组 → 目标
```

**端点组是一层候选，转发链是多层顺序。** 把两个端点加入同一组，不表示流量依次经过这两个端点。

## 第一步：准备节点和端点组

先部署入口 worker 与各层 forwarder，验证每一跳能访问下一层的地址和服务端口。创建记录并不代表机器已经在线。

进入 **端口管理 → 端点组管理 → 创建组**：

1. 填显示名称，按需填写描述。
2. 从可选端点添加成员到右侧。
3. 拖拽已选成员排序；需要时使用序号定位或多选。
4. 核对成员属于同一个逻辑层，再点击 **创建**。

![端点组的可选成员、已选成员和排序入口](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-endpoint-group-5019d01db2e6.png)

为 IX 层和落地层分别建组；不要把所有层的机器混进同一组。

## 第二步：创建可复用的转发链

进入 **转发链管理 → 创建转发链**，填写名称，将所需端点组加入右侧，拖拽为实际路径顺序，例如 `IX 组 → 落地组`。

![创建转发链并排列端点组层次](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-saved-chain-de5d4211c24e.png)

确认链处于启用状态后保存。组成员顺序和链层次是不同设置，最终选路还受使用该链时的策略影响。

## 第三步：选择服务器默认传输或端口路径

| 配置位置 | 操作 |
| --- | --- |
| 服务器 → 转发配置 | 选 **链式转发**，使用已保存的转发链，或临时配置端点与顺序 |
| 端口 → 转发配置 | 选 **链式转发**，添加端点或端点组，并在转发顺序中调整层次 |

服务器默认链还需判断 **使用转发端点作为传输**：关闭时用于服务器连接控制器；开启时端口业务也默认沿用。端口另选路径和分流规则可能改变最终行为，见[配置说明](../config/index.md)。

## 第四步：设置智能选择和必经层

![端口链式模式的转发顺序、智能选择和固定跳数](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-chain-316e0f9fa2d4.png)

- **开启智能选择**：未锁定层可能被跨层优化或跳过，不能据此认为每层都会经过。
- **固定前 N 跳**：锁定开头 N 层，适合入口侧必须先经过某条 IX 的情况。
- **固定后 N 跳**：锁定末尾 N 层，适合落地前必须经过专线 / 内网的情况。
- 两者之和不能超过总层数。要求严格逐层经过时，关闭智能选择或锁定全部层次。

强制经过的层全部不可达时，不应指望系统自动绕过该层。可以另配一条可达路径作为 [Fallback 备用](../multi-fallback-line/index.md)。

## 第五步：保存并验证真实路径

需要对单个端口调整节点、边、权重或定时禁用时，进入更多操作中的[网络规划](../network-planning/index.md)。图中的校验、配置保存和真实路径验证分别完成。

1. 保存规则，确认入口和各端点在线、配置已同步。
2. 从入口逐层检查下一跳可达性与 TCP / UDP 放行。
3. 用实际业务访问目标，结合连接诊断查看路径。
4. 在测试线路上分别验证组内候选故障、整层故障及恢复。

求和探测把分段测量组合起来；管道探测沿路径测量，资源开销不同。两者都不能替代应用访问，也不能保证已建立连接在故障时无中断。

## 常见配置错误

| 错误 | 修正 |
| --- | --- |
| 同时选择一个组及它的成员 | 移除重复成员，避免重复参与候选、权重和计费 |
| 开智能选择后专线被跳过 | 固定必经的前 / 后层，或关闭智能选择 |
| 看不到链式模式 | 检查服务器的启用转发链权限和订阅授权 |
| 节点在线但链不通 | 在线只说明管理连接可达，还需逐跳检查业务地址和端口 |
| 把组内多选当成多跳 | 每个逻辑层分别组织，核对转发顺序 |
