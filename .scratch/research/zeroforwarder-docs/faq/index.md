# 常见问题

排查安装、离线、转发与 UDP 问题，核对当前配置路径和迁移方式。

## 购买与授权

### 如何自助购买和续费

[购买许可证](https://www.zeroforwarder.com/buy/)无需邮箱或注册。先保存恢复码并下载备份，再选择 USDT 网络创建订单。
付款后凭订单号和恢复码领取 `ZFC_INSTANCE_ID`、`ZFC_API_KEY` 和安装命令。
恢复码与 Key 同样重要；丢失本机数据后，可输入订单号/恢复码或导入备份恢复购买记录。

续费和工单优先在已安装面板的许可证页操作，不需要额外登录。
面板无法启动时，可在[许可证中心](https://www.zeroforwarder.com/account/)同时提供实例 ID 和 Key 续费或联系支持。
过期超过 7 天或许可证已吊销时，续费可能需要人工审核。页面会在付款前提示；
请先联系支持，付款后需要审核通过才能恢复。

如果 Key、订单恢复信息都丢失，可以[提交匿名协助工单](https://www.zeroforwarder.com/support/)，保存新的工单恢复码跟进回复。
交易哈希、收款地址和金额是公开信息，不能单独证明购买归属，需要进一步核实。
工单中不要提供钱包私钥、助记词或 API Key。

### 有免费版吗

Zero Forwarder 使用付费授权，套餐以[首页定价](https://www.zeroforwarder.com/#pricing)与购买时说明为准。安装需要的 `ZFC_INSTANCE_ID`、`ZFC_API_KEY`由授权提供，一份授权对应相应面板实例。

### 个人 tier 支持商城、支付和兑换码吗

不支持。商城与套餐销售、支付接入、余额与订单、兑换码发行与兑换、推广与佣金等运营功能**仅商用 tier 支持**。个人 tier 不包含这些功能；需要时请联系咨询商用授权与报价，使用流程见[商城与运营](../operations/index.md)。

## 安装与登录

### 安装脚本失败怎么办

先保留错误码和日志，检查域名、网络、端口占用、Docker / Compose 版本和授权。已有安装在原目录诊断：

```bash
cd /root/zfc
bash install.sh --doctor --json
docker compose ps
```

退出码和非交互预检见[用 AI 助手安装](../agent-install/index.md)。`--force` / `--clean-install`是重建或清空式重装，不用于保数据更新。

### 管理员 Token 在哪里

查看原安装目录的 `.admin_token`，或使用安装脚本的 **查看管理员密码**菜单。安装的人类可读输出不再打印明文 Token；非交互结果文件与普通日志的内容也不同。

不要把 `.env`、Token 或完整结果文件发送到公开渠道。刷新 Token 后，重新核对登录和已有接入配置。

## 节点离线与配置路径

### 服务器一直离线

1. 检查该节点到控制器实际域名和端口的 DNS、路由与防火墙，核对反向代理是否支持长连接。
2. 检查相应 systemd 服务和日志；服务名以实际安装为准。
3. 检查系统时间与证书。不要仅以控制器域名返回网页就判断管理连接正常。
4. 需经中转连接控制器时，核对服务器转发配置与 **使用转发端点作为传输**开关。

```bash
systemctl status zf.service --no-pager
journalctl -u zf.service -n 100 --no-pager
timedatectl status
```

默认 worker 示例使用 `zf.service`；多实例需使用实际的实例单元。入口管理连接配置见[国内机器最佳实践](../china-server/index.md)。

### 配置文件在哪里

| 类型 | 常见路径 / 查找方式 |
| --- | --- |
| 默认单实例 worker | `/root/zf/config.json` |
| 已迁移的 worker 多实例 | 安装目录下 `instances/<实例 ID>/config.json`，以服务的 `--config-path`为准 |
| 自定义或共享 worker | 查实际单元的 `WorkingDirectory`与 `ExecStart` |
| forwarder | `/opt/fwd_server_<编号>/config_<编号>.json`，以实际服务启动参数为准 |

```bash
# 替换成实际服务名
systemctl show zf.service -p FragmentPath -p WorkingDirectory -p ExecStart
```

先在面板修改受管理的转发配置，避免本地手改后被同步覆盖。输出中可能有路径、身份或凭据，分享前脱敏。

## 转发与 UDP

### 节点在线但转发不通

在线只说明管理连接存在。继续检查入口监听、规则同步、每一跳的业务地址、云安全组、系统防火墙与最终目标。

普通转发目标是 `host:port`；IPv6 使用 `[地址]:端口`。入站代理未配置额外出口代理时，顶部目标是探测目标，真实目标由客户端决定。

### UDP 不通要检查什么

| 环节 | 检查 |
| --- | --- |
| 普通转发入口 | 是否选择 UDP 或 TCP + UDP，节点是否支持相应监听 |
| 原生 UDP 入站 | WireGuard、Hysteria2、TUIC、Juicity 等需实际放行 UDP |
| 隧道内部 | 是否使用原生 UDP 或 UOT，取决于协议、链路与配置 |
| 目标与客户端 | 两端是否支持对应 UDP 业务，是否有请求也有响应 |

隧道里承载 UDP 不代表入口只需放行 TCP。不要把“端口 TCP 能连接”当成 UDP 已验证，也不要只依据链长就推断所有入站和出站组合的 UDP 行为。

### 链没有经过某一层

核对智能选择、固定前后跳数、服务器默认传输、端口覆盖与分流。必须经过的层应锁定，不能把“智能选择”理解为严格逐层转发。详见[动态多级转发链](../fwd-chain/index.md)。

### 备用线路要写 JSON 吗

当前可在 **转发配置 → Fallback 转发配置**添加 Hammer、TOT 或链式卡片。端口冷备与服务器候选合并的适用范围不同，操作和限制见[多备用线路](../multi-fallback-line/index.md)。

## 如何备份和迁移

当前在线“面板迁移”已停用；使用安装脚本的打包／恢复，完整流程见[备份、迁移与恢复](../backup-migration/index.md)。脚本一键打包只支持内置 PostgreSQL，外部数据库需独立安排备份与恢复。

在原安装目录运行当前安装脚本，选择 **6. 一键打包迁移文件**；在新机器使用 **7. 一键恢复迁移文件**。按菜单名称核对版本，旧教程的 5 / 6 已不对应打包 / 恢复。

1. 核对迁移包生成结果、源面板版本、域名、数据库类型和外部依赖。
2. 迁移包包含凭据与业务数据，安全传输并限制访问。
3. 切换时协调停止旧面板，避免两个控制面同时操作同一组节点。
4. 在新机器按恢复流程导入迁移包，不先做一遍全新安装覆盖。
5. 验证登录、数据、授权、节点在线、转发、订阅与证书。
6. 新机器验证完成前保留旧目录和迁移包；回退时先避免新旧面板同时运行，再启动旧环境。

默认备份会跳过部分诊断、审计、统计和任务队列的行数据，不等于完整保留所有历史记录。需要这些记录时，按当前脚本的完整备份选项处理。外部数据库、Redis、TDengine 等还需分别核对覆盖范围。

## 寻求帮助时提供什么

提供版本、系统、问题发生时间、资源 ID、症状、已做检查和必要的脱敏日志。不要直接发送完整配置、Token、私钥、二维码或可还原凭据的分享链接。

需要远程诊断时，参考[用 AI 助手定位问题](../agent-diagnose/index.md)。
