# 多备用线路

使用可视化表单配置 Hammer、链式和 TOT 备用路径，区分端口冷备与服务器级候选合并。

使用 **Fallback 转发配置**编辑器添加备用路径，无需手写 `fallback_fwder_configs`。

## 先选配置层次

| 位置 | 用途 | 运行方式 |
| --- | --- | --- |
| 端口管理 → 添加 / 编辑端口 → 转发配置 | 给一条业务规则配置备用出站路径 | 冷备：按健康状态切换活动路径，备用成员没有常驻业务连接 |
| 服务器管理 → 添加 / 编辑服务器 → 转发配置 | 给服务器级传输配置备用 | 服务器级候选合并；仅主路径及备用全为 Hammer 时适用 |

这两处使用相似表单，运行方式不同。服务器级配置还受 **使用转发端点作为传输**开关影响：关闭时主要用于连接控制器；开启后，端口业务也默认使用该传输。详见[配置说明](../config/index.md#控制通信与业务传输)。

一条路径内部的“备用”选择策略，与整条路径的 Fallback 也不同：前者在同一候选池里选节点，后者在主路径与另一套转发配置之间切换。

## 第一步：配置并验证主路径

1. 准备在线入口和可用端点，确认入口到端点、端点到目标的可达性。
2. 添加或编辑端口，选择线路、目标和服务端口。
3. 展开 **转发配置**，选择 **单跳转发**、**链式转发**或 **TOT 聚合**，完成主路径。
4. 先验证主路径的真实业务，再增加备用。

直连模式不显示 Fallback 编辑器。先按[转发指南](../fwd-guide/index.md)选择需要的转发模式。

## 第二步：添加第一条备用

展开 **Fallback 转发配置**，点击 **+ 添加 fallback**。卡片上的 `#1` 表示第一条备用，不包含上方的主路径。

![端口 Fallback 的冷备提示、Hammer 类型、端点与选择模式](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-fallback-hammer-c0a7bc761858.png)

### Hammer：一层候选

1. 类型选择 **Hammer**。
2. 在 **转发端点**选择可用端点或组。
3. 在 **选择模式**选择轮询、最佳延迟、备用、随机或动态加权轮询等可用策略。

新建 Hammer 备用默认显示 **轮询**。同一张卡片选择多个端点表示候选池，不会依次经过这些端点。若要求先用 A、A 不可用再用 B，应选择“备用”并核对候选顺序。

### 链式：另一条多跳路径

选择 **链式**，按路径顺序选择端点或组，再配置 **智能选路**、**固定前跳数**和**固定后跳数**。

![链式备用中的端点、智能选路和固定前后跳数](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-fallback-chain-ed754e782d23.png)

未锁定层可能被智能选择跳过。必须经过的 IX 或专线层应固定，或关闭智能选路；固定前后跳数之和不能超过总层数。组内是同层候选，组与组之间才是链路层次。

### TOT：备用聚合路径

选择 **TOT** 后，除转发端点外，还必须选择 **TOT 服务器**，核对端点选择模式、TOT 选择模式、延迟测试和发送模式。

![TOT 备用中的汇聚服务器、延迟测试和发送模式](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-fallback-tot-786c732ba48f.png)

这里的备用卡片使用自己的字段，不要把主路径的 TOT 子流表单参数直接照搬。只有端点、没有汇聚服务器的 TOT 备用不能保存。聚合原理见[单线程带宽聚合](../bw-merge/index.md)。

## 第三步：安排备用顺序并保存

- 继续点击 **+ 添加 fallback**可增加下一张卡片。
- 拖动卡片左侧的排序手柄，调整备用顺序；主路径仍在卡片列表之外。
- 删除不再需要的卡片，避免保留空卡片。
- 每张卡片至少选择一个端点；TOT 卡片还需汇聚服务器。
- 类型、端点序列及 TOT 服务器序列完全相同的重复备用会被校验拦截，应合并或改成不同路径。

例如：主路径为 IX 链，`#1` 为另一条专线链，`#2` 为公网 Hammer 路径。备用数量以界面上限为准；普通用户还受系统 / 订阅策略约束，管理员看到的数量不能代表普通用户权限。结构化编辑器最多支持 8 条。

完成后点击整个端口表单的 **添加 / 保存**，确认规则同步到在线 worker。编辑备用配置通常不需要重新安装节点程序。

## 服务器级备用如何配置

进入 **服务器管理 → 添加 / 编辑 → 转发配置**，同样展开 Fallback 并添加卡片。

![服务器 Fallback 的热备提示和使用转发端点作为传输开关](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-fallback-server-0ad34660b6fd.png)

界面保留热备提示，但当前服务器级传输仅支持主路径及备用全部为 Hammer 的候选合并。包含 TOT 或链式备用的混合配置在此处只保留主路径，不能据此认为这些备用会切换。需要 Hammer / TOT / 链式之间切换时，请在端口配置。

先判断保护的是服务器管理连接，还是默认业务传输，再设置传输开关。端口独立路径需单独验证。

## 已有 JSON 配置如何处理

已有合法 `fallback_fwder_configs` 会显示为卡片，表单会同步到自定义配置。无需把旧教程中的 JSON 再粘贴一份。

如果看到“自定义配置不是合法 JSON 对象”，结构化编辑器会禁用。先修正 **高级选项 → 自定义配置**中的格式；JSON 不接受 `//` 注释、末尾多余逗号或数组作为顶层对象。保留其他已有字段，不要为了启用表单而整段清空。

## 验证切换与恢复

在自己可控的测试线路上验证，不要直接关闭生产共用节点来做演示：

1. 先分别确认主路径和每条备用都能独立访问目标。
2. 建立真实业务连接，再模拟主路径不可达。
3. 观察同步状态、连接诊断和新连接是否转到备用。
4. 恢复主路径，持续观察健康探测和回切结果。
5. TCP、UDP 和长连接分别测试，记录实际中断与恢复时间。

端口 UI 的“约 30 秒切换、约 5 分钟回切”是提示性估算。实际取决于故障信号、探测、健康确认及建链，不能当作固定时限，也不能套用于服务器热备。切换或回切可能影响长连接，**不保证所有已建立连接无损迁移**。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 看不到 Fallback | 主模式是否为直连、线路权限是否允许自带转发 |
| 无法继续添加 | 数量已达上限，或普通用户策略禁用了备用 |
| 表单禁用 | 自定义配置是否为合法 JSON 对象；服务器是否为受限的导入资源 |
| 保存失败 | 空端点、TOT 缺汇聚服务器、重复卡片、端点权限 |
| 备用一直不通 | 从实际前一跳验证可达性，检查目标、防火墙和协议 |
| 配了服务器备用但业务没经过 | 使用转发端点作为传输开关、端口覆盖、分流规则 |
| 回切后长连接断开 | 客户端重连能力与业务容错；不能只用探测成功判断无中断 |
