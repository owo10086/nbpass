# 配置说明

理解服务器、转发端点、端口和分组的关系，查阅传输、监听、权限与流量设置。

首次使用建议先跟随[转发指南](../fwd-guide/index.md)完成一条规则，再回到这里查参数。

## 核心对象与配置层次

| 对象 | 用途 | 菜单入口 |
| --- | --- | --- |
| 服务器 | 部署 worker，接收客户端连接 | 服务器管理 |
| 转发端点 | 部署 forwarder，充当中转或落地 | 转发端点 |
| 端口 | 入口监听、目标、入站协议与出站路径 | 端口管理 |
| 服务器组 | 多个入口共用一条逻辑线路 | 服务器组管理 |
| 端点组 | 一层中转或落地的候选集合 | 端点组管理 |
| 转发链 | 按层组织中转与落地候选 | 转发链管理 |

这些入口位于侧栏 **端口管理**分组。服务器提供默认传输与使用限制，端口描述具体业务；在权限允许时，端口可自带转发配置。最终路径还可能受分流与出口代理影响。

管理员可绕过部分线路限制，不能用管理员界面推断普通用户也有相同权限。

## 服务器基本信息

点击 **添加服务器**，或编辑已有服务器。

![服务器的显示名称、入口地址、网卡与端口范围](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-basic-284dd04db0f4.png)

| 字段 | 含义 |
| --- | --- |
| 显示名称 | 面板识别与线路选择时显示的名称 |
| IP 地址 | 对外入口 IP 或域名，不附带端口；应与客户端可访问的入口一致 |
| 额外入站地址 | 其他入口 IP 或域名，每行一个 |
| 网卡名称 | 用于网速监控，例如 `eth0`、`ens3`；不负责配置机器网卡 |
| 端口范围 | 给普通用户分配监听端口的范围，仍需通过冲突与权限检查 |

可在节点执行 `ip a` 查看网卡。填写入口地址不会替你配置 DNS、安全组或系统防火墙。

## 服务器的转发配置

展开 **转发配置**，选择直连、单跳、链式或 TOT 聚合。

![服务器转发模式和“使用转发端点作为传输”开关](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-forward-be5426fded2c.png)

### 控制通信与业务传输

**使用转发端点作为传输**决定端口业务是否默认沿用服务器上的转发配置：

- **关闭**：配置的端点用于服务器连接面板控制器，端口业务不默认经过它们。
- **开启**：端口业务也默认经这里配置的端点传输。

允许自带转发端点时，端口可以选择其他路径覆盖默认设置。排查绕路应同时看服务器、端口和分流配置。

### 四种模式

| 模式 | 配置内容 | 关键区别 |
| --- | --- | --- |
| 直连 | 无额外端点 | 不建立这一级中转配置 |
| 单跳转发 | 端点或端点组 | 多选构成候选池，不是多跳 |
| 链式转发 | 按顺序排列的端点或组 | 每层有候选，智能选择可优化未锁定层次 |
| TOT 聚合 | TOT 服务器与聚合子流 | 多条子流传输，在 TOT 服务器汇聚 |

服务器的链式模式可选已保存的转发链或临时配置。端口表单则通过所选端点与顺序构造路径。

**固定前 N 跳 / 固定后 N 跳**锁定必须经过的层次，两者之和不能超过总层数。开启智能选择不等于每一层都必经。

TOT 子流支持多跳或端点候选，不能再按“仅支持传统模式”理解。若设置子流方向，必须为上下行都保留可承载流量的子流。

### 候选策略与 Fallback

最佳延迟、备用、轮询、随机、动态加权轮询、静态加权轮询适合不同需求。**手动权重用于静态加权轮询**；动态加权根据测量结果计算。

组会展开成成员，不要同时选一个组和它已有的成员，以免重复计入候选、权重与流量归属。

**Fallback 转发配置**已可通过卡片编辑。端口支持主路径失败后切换另一套路径；服务器级传输仅在主路径及备用均为 Hammer 时合并候选，包含 TOT / 链式备用的混合配置在服务器级只保留主路径。需要混合类型切换时在端口配置，见[多备用线路](../multi-fallback-line/index.md)。

## 服务器权限与限制

用户、套餐、角色和租户与服务器限制共同作用，配置顺序与验证方法见[用户与套餐](../users-packages/index.md)及[权限与租户](../access-control/index.md)。跨面板接入的资源还需满足[共享方限制](../cross-panel-sharing/index.md)。

展开 **高级选项**，按业务开放功能。

![转发权限、允许入站代理、入站协议策略和高级限制](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-advanced-2221b0c2e00c.png)

| 设置 | 影响 |
| --- | --- |
| 允许自带转发端点 | 允许用户在端口中选择自己的中转配置 |
| 强制使用转发端点 | 限制普通用户直连，应先准备可用端点与权限 |
| 启用转发链模式 | 允许用户配置多级路径 |
| 允许入站代理 | 开放普通用户的代理协议入口配置 |
| 入站协议策略 / 允许的入站协议 | 选择继承组或本机覆盖；覆盖时空名单表示不额外限定协议 |
| 强制使用入站代理 | 限制普通用户创建普通转发端口，要求使用允许的入站协议 |
| 允许延迟测试 | 控制相应延迟检测功能 |
| 允许测速 | 允许链路速度诊断，会产生真实流量，并受端口限速约束 |
| UDP 原进原出 | 使用接收 UDP 包的 IP 发送响应，多地址场景按需启用 |
| 协议过滤器 | 屏蔽指定协议，可能使相关入站选项隐藏或无法保存 |
| 最大 IP 数 / 每 IP 最大连接数 | 限制端口来源数量和并发连接 |

上述策略涉及组继承与管理员例外。普通用户看不到 AnyTLS、Reality 或 QUIC 协议时，先检查有效协议名单和 TLS 过滤器。

## 流量、限速与续费

服务器表单把 **流量控制**、**续费信息**和高级选项分开。端口也有独立的 **带宽设置**、**流量控制**与**端口限制**。

- **流量倍率**影响统计 / 计费，不改变实际传输字节。例如在相应计费层倍率为 1 时，下载 2 GB、上传 1 GB，合计为 3 GB。
- 路径上的转发端点也可能各自计费，不能只看入口倍率估算完整路径消耗。
- **带宽限制**约束速率，端口、用户、服务器等层次可能同时生效。
- **端口周期流量限制**约束周期用量，达到上限后暂停；配置重置周期后，到期处理会清零相应用量并解除流量超限暂停。
- 续费、自动续期和流量重置是不同机制，延长有效期不等于立即清零流量。

单位以界面为准，`Mbps` 和 `MB/s` 不能按同一数值理解。详情见[带宽限速](../bandwidth-speed-limit/index.md)。

## 转发端点

转发端点可单独使用，也可加入端点组或链。下面展示 Hammer 端点的配置，其他协议按对应字段填写。

![转发端点的地址、服务端口、绑定端口与高级设置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-endpoint-basic-277ef4dcc27c.png)

创建时重点核对：

1. **IP / 域名**：填写前一跳可访问的地址；自动 IP 模式下，检查上报地址是否符合实际路径。
2. **服务端口**：其他节点连接的对外端口。
3. **绑定端口 / 绑定 IP**：节点本机监听的端口与地址。NAT 公网端口与内网端口不同时，需分别填写并配置映射。
4. **公共可见**：控制普通用户能否看见和使用端点，不等同于防火墙规则。
5. **流量与带宽**：核对倍率、周期额度、暂停状态与限速。
6. **安装与在线状态**：按面板指引部署再检查连通性，仅创建记录不代表服务已上线。

“访问面板代理转发端点”只影响端点与面板的管理连接，不会替你改变业务转发路径。

## 端口基本信息

![端口的名称、线路、目标、服务端口与转发模式](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-basic-33afbae1bbab.png)

- **线路**：一台服务器或一个服务器组。
- **目标**：普通转发每行一个 `host:port`，IPv6 使用 `[地址]:端口`。
- **服务端口**：客户端连接的入口端口；留空自动分配，组线路需检查各成员。
- **多线路共同维护**：一份逻辑规则关联多条线路，共用业务配置和监听端口；保存前检查逐线路预检。新建、扩展和批量维护见[多线路共同维护](../multi-line-rule/index.md)。

普通目标支持 `# first`、`# last`、`# pause`，见[转发指南](../fwd-guide/index.md#多个目标与临时暂停)。

## 端口高级选项

![目标策略、测试方法、Proxy Protocol 和监听协议](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-advanced-04cbe4c47197.png)

### 目标选择与测试方法

策略作用随业务场景变化：

- **普通转发**：目标选择模式通常选择最终目标；单跳且只有一个目标时，出口端点由转发配置的均衡策略决定，目标选择模式不生效。
- **入站代理**：目标选择模式（出口级）选择最终出口；单跳入站的出口不由转发配置均衡策略决定。
- **链式转发**：中间级均衡策略与出口级目标选择分别配置。

并非所有策略都选择最低延迟，优先级、候选状态和分流也会影响结果。

TCP Ping 检查目标 TCP 端口；ICMP 依赖节点权限和目标响应。探测结果不能替代应用层验证。

### 监听协议与端口占用

普通转发可选 TCP、UDP、TCP + UDP。TCP-only 与 UDP-only 规则在满足检查条件时可使用相同数字端口；已有规则占用 TCP + UDP 时，不能再按“另一协议空闲”分配。

入站协议的监听方式由协议推导。WireGuard、Hysteria2、TUIC、Juicity 等原生 UDP 入站还有专用占用限制，以实际预检结果为准。

### Proxy Protocol、分流和防火墙

- **接受代理协议**：仅在上游确实发送 Proxy Protocol 头时开启。
- **发送代理协议**：目标程序必须支持对应格式。`V2 + UDP` 是 V2 的 UDP 形式，不是独立的 Proxy Protocol V3 标准。
- **分流规则集**：改变出站选择，见[解锁服务与分流](../unlock-traffic-routing-guide/index.md)。
- **入站防火墙规则集**：控制进入本端口的连接，与出站分流方向不同。
- **自定义配置**：填写合法 JSON，不包含注释；优先使用已有表单，避免重复维护转发或备用配置。

### 入站代理和出口代理

平台证书的申请、绑定与续期见[证书管理](../certificates/index.md)。面向客户端生成配置的[订阅链接与模板](../client-subscriptions/index.md)是另一项独立功能。

当前在 **入站配置 → 启用入站代理 → 协议**中操作，不再依赖手写旧式 `{"Ss":{}}`。

开启入站且未使用额外出口代理时，原目标栏变为 **连通性测试目标**，真实目标由客户端协议逐流携带。配置 **出口代理（落地出口协议）**后，目标栏还可能变为上游代理地址或引用地址覆盖，以当前标题为准。

完整步骤见[入站代理](../inbound-proxy/index.md)和[出口代理](../outbound-proxy/index.md)；连接与测速的排查入口见[连接诊断与测速](../diagnostics-speed-test/index.md)。

## 服务器组、端点组与转发链

### 服务器组：多个入口

组线路的端口需要部署到各成员，统一端口必须满足所有相关成员的监听检查，各入口的防火墙也要分别放行。

统一域名可手动配置 DNS，或使用 DNS API 和服务器组自动更新；**智能 DNS**通过调度节点池提供权威调度，属于另一套入口管理机制。DNS 更新影响后续解析，已有连接不会自动搬到另一入口。

完整操作见[服务器组](../server-groups/index.md)、[动态域名与 DDNS](../dynamic-dns/index.md)和[智能 DNS](../smart-dns/index.md)。三篇分别说明端口同步、节点地址更新和权威调度的配置与验证。

### 端点组：一层候选

在链中选择一个端点组，代表这一层有多个候选，不代表依次经过全部组成员。

### 转发链：多个层次

按网络可达性排列层次，再设置智能选择与固定前后跳数。把多个节点加入同一组，不会生成多级链路。

更多示例见[动态多级转发链](../fwd-chain/index.md)和[入站代理](../inbound-proxy/index.md)。
