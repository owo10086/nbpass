# 转发指南

从第一条端口转发开始，理解直连、单跳、转发链与 TOT 聚合，并检查实际连通性。

按“准备节点 → 添加端口 → 选择路径 → 验证”的顺序配置，示例域名和端口请替换为自己的配置。

## 先分清入口、端点和目标

| 对象 | 作用 |
| --- | --- |
| 服务器（worker） | 客户端连接的入口，端口规则部署在这里 |
| 转发端点（forwarder） | 可选的中转或落地节点 |
| 目标 | 普通转发最终连接的服务，填写 `地址:端口` |
| 线路 | 添加端口时选择的服务器或服务器组 |

例如，把入口的 `32000` 端口转到网站的 `443` 端口：

```text
客户端 → entry.example.com:32000 → web.example.com:443
```

普通端口转发不负责替目标网站签发 HTTPS 证书。访问 HTTPS 时，客户端仍需使用目标服务认可的域名和 SNI。

## 第一步：准备在线节点

1. 管理员进入 **端口管理 → 服务器管理**，添加入口服务器。
2. 按面板安装指引在入口机器部署 worker，确认机器在线。
3. 如需中转，在 **转发端点** 页面添加节点，并按指引部署 forwarder。
4. 检查入口、端点和目标之间的可达性，以及云安全组和系统防火墙。

只做直连时，不必先部署转发端点。节点字段、权限和服务器级默认传输见[配置说明](../config/index.md)。

## 第二步：添加第一条转发

进入 **端口管理 → 端口管理**，点击 **添加端口转发**。

![添加端口转发：名称、线路、目标、服务端口与转发模式](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-basic-33afbae1bbab.png)

| 字段 | 示例 | 填写方法 |
| --- | --- | --- |
| 名称 | 教程示例 · Web 转发 | 便于搜索和区分用途 |
| 线路 | 自己的入口服务器 | 先选线路，后续选项受线路权限约束 |
| 目标 | `web.example.com:443` | 每行一个，支持域名、IPv4、带方括号的 IPv6 |
| 服务端口 | `32000` | 客户端连接的端口；留空由系统分配 |
| 转发模式 | 直连 | 第一条规则先用简单路径验证 |

IPv6 目标格式为 `[2001:db8::10]:443`。普通转发必须有有效目标，不要把入口自己的同一监听端口又填成目标，造成循环。

展开 **高级选项**，设置 **监听协议**：

- **TCP**：例如网页、SSH 等 TCP 服务。
- **UDP**：例如 DNS、游戏等 UDP 服务，需要节点支持 UDP-only 转发。
- **TCP + UDP**：同时监听两个传输协议。

![高级选项中的目标策略、测试方法、Proxy Protocol 与监听协议](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-advanced-04cbe4c47197.png)

点击 **添加**保存，再核对列表中的实际入口地址、分配端口和同步状态。手动指定端口也必须通过可用性和权限检查。

同一服务需要多个入口、希望统一修改端口和业务配置时，使用[多线路共同维护](../multi-line-rule/index.md)，无需逐条重复创建和编辑。

> 要验证完全直连，还应确认服务器未启用默认业务隧道，且没有分流规则改变出站路径。服务器上“使用转发端点作为传输”的含义见[配置说明](../config/index.md#控制通信与业务传输)。

## 第三步：按场景选择路径

| 模式 | 路径 | 适用情况 |
| --- | --- | --- |
| 直连 | 入口 → 目标 | 入口可直接访问目标 |
| 单跳转发 | 入口 → 一个候选端点 → 目标 | 一级中转，或多个落地之间选路 |
| 链式转发 | 入口 → 按层组织的端点 → 目标 | IX、专线、跨地域多跳 |
| TOT 聚合 | 入口 → 多条子流 → TOT 服务器 → 目标 | 多条链路共同承载单连接流量 |

### 单跳转发：多选的是候选池

展开 **转发配置**，选择 **单跳转发**，添加转发端点或端点组，再设置均衡策略。

![单跳转发的端点、优先级顺序、均衡策略和 Fallback 设置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-relay-465254c149ca.png)

选择多个端点表示从候选中选择中转，**不会自动串成多跳**。常见策略包括：

- **最佳延迟**：根据探测结果优选可用候选。
- **备用**：按配置顺序优先使用可用候选。
- **轮询 / 随机**：在可用候选间轮换或随机选择。
- **静态加权轮询**：使用手动权重；动态加权轮询则根据测量结果计算权重。

不要同时选择一个端点组及其已有成员，否则组展开后可能重复计入候选、权重和计费。

### 链式转发：按层组织路径

选择 **链式转发**，添加端点或端点组，在 **转发顺序**中调整层次。例如：`入口 → IX 中转组 → 落地组 → 目标`。组内成员是同一层的候选，不是依次经过的下一跳。

![链式转发的顺序、智能选择与固定前后跳数](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-chain-316e0f9fa2d4.png)

开启 **转发链智能选择**后，未锁定的中间层可能被跳过。如果业务必须经过指定中转：

- 用 **固定前 N 跳**锁定开头的层次。
- 用 **固定后 N 跳**锁定末尾的层次。
- 两者之和不能超过总层数。
- 要求严格逐层通过时，关闭智能选择，或按需锁定全部层次。

按实际拓扑补齐多跳路径的各层。组链示例见[动态多级转发链](../fwd-chain/index.md)。

### TOT 聚合：配置汇聚点和子流

选择 **TOT 聚合**，先选择 TOT 服务器，再配置聚合子流。子流可以使用端点候选，也可以经过多跳链路。

![TOT 聚合模式与服务器选择入口](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-tot-c97fa5e36f61.png)

TOT 服务器是汇聚点，不能只选几个普通候选端点就视为已开启聚合。入口和汇聚点需要足够带宽；实际效果还受共享瓶颈、时延和丢包影响。

详细说明见[单线程带宽聚合](../bw-merge/index.md)。

### Fallback：主路径失败后的备用配置

单跳、链式和 TOT 中可展开 **Fallback 转发配置**，为主路径配置备用。它与同一候选池的“备用”均衡策略属于不同层次，见[多备用线路](../multi-fallback-line/index.md)。

切换影响后续连接或重试，不保证已建立的所有连接都能无损迁移。

## 第四步：验证实际业务

已有路径可通过[网络规划图](../network-planning/index.md)查看并细调。要接出无公网入口机器上的服务，使用[NAT 穿透](../nat-traversal/index.md)；要组织设备和服务器的虚拟网络，使用[WireGuard 组网](../wireguard-network/index.md)。

1. 确认 worker 和所选端点在线，端口规则已同步。
2. 在入口云安全组和系统防火墙中放行对应的 TCP / UDP 端口。
3. 从客户端连接列表中显示的**入口地址和服务端口**。
4. 用实际应用验证 TCP 连接或 UDP 请求与响应。
5. 配合面板的延迟、丢包和连接诊断核对路径。

例如检查 TCP 端口能否建立连接：

```bash
nc -vz entry.example.com 32000
```

这不能证明 UDP、HTTPS 证书或完整应用协议都正常。面板探测成功后，也应再做一次实际业务访问。

## 多个目标与临时暂停

普通转发可每行填写一个目标，多目标时由 **目标选择模式**选择最终目标。单跳且只有一个目标时，出口端点由转发配置的均衡策略决定，目标选择模式不生效；入站代理的出口选择另见[配置说明](../config/index.md#目标选择与测试方法)。

```text
primary.example.com:443 # first
secondary.example.com:443
maintenance.example.com:443 # pause=2h
last-resort.example.com:443 # last
```

- `# first`：目标可用时优先使用。
- `# last`：其他目标都不可用时兜底。
- `# pause=2h`：暂停两小时；支持 `min`、`h`、`d`，最长 365 天。
- `# pause`：无限期暂停。

至少保留一个生效目标。这些行内规则用于普通转发目标，不用于入站代理探测目标或出口代理地址。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 看不到线路或转发选项 | 订阅授权、服务器权限、线路是否暂停 |
| 保存时提示端口冲突 | 监听协议、已有规则、其他程序占用、组内各成员可用性 |
| TCP 正常、UDP 不通 | UDP 监听、两层防火墙和目标的 UDP 支持 |
| 探测正常、应用打不开 | 实际目标端口、应用协议、HTTPS 域名与 SNI |
| 路径没有经过某层 | 智能选择、固定前后跳数、服务器默认传输和分流 |
| 需要 SS / VLESS 等客户端协议 | 按[入站代理](../inbound-proxy/index.md)配置，普通转发端口不等于代理协议端口 |

实际请求路径、拦截记录和吞吐量问题，按[连接诊断与测速](../diagnostics-speed-test/index.md)进一步检查。
