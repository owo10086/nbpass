# 入站代理

在入口启用 SS、VLESS、Reality、AnyTLS 等协议，配置证书、转发路径与客户端连接。

入站代理在入口 worker 接收客户端协议，再经直连、转发端点、转发链或 TOT 访问真实目标。使用 forwarder 落地时，无需为同一条代理服务在每台落地机器再部署一份 SS 或 VLESS 服务。

```text
客户端（SS / VLESS / …）
  → 入口 worker（处理入站协议）
  → 可选的中转 / 转发链 / TOT
  → 落地出口
  → 客户端请求的真实目标
```

示例域名和端口请按实际环境替换。

## 第一步：确认线路权限和网络条件

1. 入口服务器已部署 worker 并在线。
2. 如需中转或落地，先部署相应端点，确认各跳可达。
3. 管理员在 **服务器管理 → 编辑 → 高级选项**检查 **允许入站代理**、入站协议名单及继承策略。
4. 根据协议放行入口 TCP / UDP 端口，确认客户端支持相应协议和版本。

![服务器中的入站代理开关和协议策略](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-advanced-2221b0c2e00c.png)

管理员可绕过部分线路限制。普通用户缺少某些选项时，先检查订阅、线路权限和协议过滤器，尤其是 TLS 过滤。

## 第二步：添加端口，开启入站

进入 **端口管理 → 端口管理 → 添加端口转发**：

1. 填写名称，选择入口线路，设置服务端口或留空自动分配。
2. 展开 **入站配置**，打开 **启用入站代理**。
3. 选择协议，填写认证与传输参数。
4. 在 **转发配置**中选择直连、单跳、链式或 TOT 路径。

![Shadowsocks 示例中的探测目标、服务端口和入站配置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-inbound-ss-e696b23951e1.png)

### 探测目标不是真实访问目标

没有额外出口代理时，目标栏显示 **连通性测试目标**，仅用于探测和选路，不会把所有网页流量固定发往这个地址。留空保存时，系统会填入：

```text
1.1.1.1:53
8.8.8.8:53
```

真实目标由客户端代理请求决定。自定义探测地址时，应选择从预期出口可达、支持当前探测方法的服务；探测成功仍需再验证实际业务。

## 当前可选协议

![入站协议选择菜单，列表可向下滚动查看其余协议](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-inbound-protocols-05213a666a63.png)

| 协议 | 认证与主要配置 | 入口监听 |
| --- | --- | --- |
| Shadowsocks | 加密方式、密码；可配置 TLS 外层 | TCP，按设置启用 UDP |
| VLESS | UUID、安全层、可选 Flow / Enc | TCP |
| AnyTLS | 密码、TLS、可选填充方案 | TCP |
| Reality | dest、SNI 白名单、UUID、公钥和 Short ID 等 | TCP |
| SOCKS5 | 用户列表；空列表表示无认证 | TCP |
| Hammer | 协议版本、PSK 等，与客户端匹配 | TCP |
| SSH | 用户认证、主机密钥、高级选项 | TCP |
| WireGuard | 服务端与 Peer 配置 | UDP |
| Snell | 版本、PSK、复用等选项 | TCP |
| Hysteria2 | 密码、TLS、混淆与伪装设置 | UDP，可附加同端口 TCP 伪装 |
| TUIC | UUID、密码、TLS、拥塞控制等 | UDP |
| Juicity | UUID、密码、TLS、拥塞控制等 | UDP |

“入口监听”指客户端接入 worker 的传输，不等于只能承载同一种业务。例如 TCP 代理内部也可能承载 UDP 请求，具体取决于协议和客户端支持。

入站的监听方式由协议推导。不要为 QUIC 或 WireGuard 入站只放行 TCP，也不要把协议内的 UDP 业务开关当成独立 UDP 监听。

## Shadowsocks：先完成一个简单示例

1. 协议选择 **Shadowsocks**。
2. 选择客户端支持的加密方式。
3. 输入密码，或留空让系统在保存时生成。
4. 不需要 TLS 外层时先保持关闭，确认基本连接后再增加传输层。
5. 选择出站路径并保存。
6. 从端口连接信息或订阅链接取得实际入口、端口、加密方式和密码，再配置客户端。

不需要再手写旧教程里的 `{"Ss":{}}`。如果启用 SS 的 UDP，同时检查入口 UDP 放行和客户端 UDP 支持。

## VLESS：UUID 与安全层分别匹配

选择 **VLESS** 后，填写 UUID 或让系统在保存时生成，再按客户端支持选择安全层，例如无外层、TLS 或 Enc。Vision / Flow、Enc 参数与客户端配置必须对应，不要把不同安全层的参数混用。

需要 Reality 时，直接在协议列表选择 **Reality**，按下文配置其 dest 和 SNI；不能只把普通 VLESS 的服务器名称换成一个网站域名。

## TLS：证书、服务器名称与校验

AnyTLS、Hysteria2、TUIC、Juicity 等需要 TLS；部分协议允许附加 TLS 外层。

![AnyTLS 的证书来源、服务器名称和 ALPN 配置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-inbound-tls-cfb43c3b2791.png)

证书来源包括：

- **SSL 证书**：选择面板证书管理中的证书，可先在 **系统设置 → SSL 证书**准备。
- **手动 PEM**：填写证书链和对应私钥。
- **自签名**：客户端需要相应信任配置，仅填写一个域名不能自动通过证书校验。

**服务器名称（SNI）**应与证书和客户端配置匹配。ALPN 等参数按协议要求填写，不要在不同协议之间原样复制。

ShadowTLS 外层需要兼容的客户端、版本、口令与握手目标，不能当作普通 TLS 证书模式。Hysteria2 不支持 ShadowTLS。

## Reality：dest、SNI 与身份参数

![Reality 的拟态目标、SNI 白名单和 Short ID 配置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-inbound-reality-70ecde377e9e.png)

1. **拟态目标（dest）**填写入口可访问的真实 TLS 站点，要求支持 TLS 1.3 和 HTTP/2。未指定端口时默认 443，需按自己的网络验证可达性。
2. 填写 dest 后，界面会把 host 加入 **SNI 白名单**。客户端 SNI 应与白名单精确匹配，至少保留一个名称。
3. 设置 UUID 或保存时生成；使用客户端需要的公钥和 Short ID，不把服务端私钥交给客户端。
4. 按客户端支持设置 **Vision 流控**与 UDP。
5. 核对客户端和服务器时间；配置时间漂移限制后，时钟偏差会影响认证。

不要把 dest 指回本入口的同一监听端口。如果提示 dest 指向共享 CDN，应先阅读回落流量风险说明，不要只为保存成功而忽略提示。

## Hysteria2、TUIC 与 Juicity

![Hysteria2 的密码、混淆与 TLS 设置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-inbound-hysteria2-8bbfd9ae7812.png)

三者都通过 QUIC / UDP 接入，需分别核对：

| 项目 | Hysteria2 | TUIC / Juicity |
| --- | --- | --- |
| 认证 | 密码 | UUID 与密码 |
| TLS | 必须配置，Hysteria2 强制 TLS 1.3 | 必须配置，与客户端校验要求一致 |
| 扩展参数 | 混淆、伪装页面、同端口 TCP 伪装等 | 拥塞控制、认证与空闲超时等 |
| 客户端匹配 | 混淆方式和口令一致 | 协议版本、ALPN 等按客户端要求匹配 |

Hysteria2 开启 **同端口 TCP 伪装**时，还要检查 TCP 端口占用和放行；关闭后，不能继续按同时监听 TCP 的配置判断冲突。

TUIC 的 0-RTT 是协议行为设置，不是带宽开关。初次配置保持默认值，先验证认证、TLS 和 UDP 链路，再调优。

## WireGuard、SOCKS5 与其他协议

- **WireGuard 入站**需要正确的 Peer、公钥、地址和路由配置。它与侧栏 **WireGuard 组网**属于不同使用入口。
- **SOCKS5**用户列表为空时是无认证入口，对外使用前应配置相应用户与入站限制。
- **SSH 入站**使用协议内的用户认证与主机密钥，客户端应核对主机指纹；它不等于直接登录 worker 宿主机的系统 SSH。
- **Snell**需要兼容对应版本的客户端，匹配 PSK、复用和版本选项。
- **Hammer**需要兼容客户端，入站协议和内部转发路径分别配置。

## 选择出站路径与入口冗余

**直连**用于入口直接访问真实目标；**单跳**从候选落地中选择出口；**链式**组织多级路径；**TOT**聚合子流。

![链式模式中的转发顺序、智能选择和固定跳数](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-chain-316e0f9fa2d4.png)

入站代理的最终出口由 **高级选项 → 目标选择模式（出口级）**控制。单跳时不要用转发配置中的均衡策略代替出口策略；链式中间级与最终出口也分别配置。

需要冗余时，可分别为入口配置服务器组、为中转 / 落地配置端点组，再按可达性组织转发链。多入口共用域名仍需配置 DNS，创建组不会自动迁移已有客户端连接。

入口扩容与组 DNS 切换见[服务器组](../server-groups/index.md)；公网地址变化见[动态域名与 DDNS](../dynamic-dns/index.md)；独立权威调度见[智能 DNS](../smart-dns/index.md)。

智能选择可能跳过未锁定层次。必须经过 IX 或专线的层，应固定前 / 后 N 跳，或关闭智能选择。故障切换也不保证既有连接无中断。

## 可选：再经过上游出口代理

**入站协议**决定客户端如何连接入口；**出口代理（落地出口协议）**决定落地如何再连接上游，两者独立。

出口可选择 SOCKS5、Hysteria2、TUIC、Juicity，或引用已有端口 / 共同规则的入站配置。

- 手动配置上游时，顶部目标栏变为上游代理地址，不能继续填普通探测目标。
- 引用时，配置和地址按引用对象展开，注意地址覆盖与引用权限。
- 分享链接导入会替换当前出口配置与上游地址，保存前重新核对。
- 启用出口代理的端口存在 WireGuard 原生 UDP 分流限制，不能默认任意组合都支持。

第一次配置建议先不增加额外上游，验证基本路径后再添加这一层。手动参数、分享链接导入、引用条件和证书校验步骤见[出口代理](../outbound-proxy/index.md)。

## 保存、导入客户端与验证

需要统一给客户端分发多个节点时，使用[订阅链接与模板](../client-subscriptions/index.md)。平台 TLS 证书的申请与自动续期见[证书管理](../certificates/index.md)；这里的 WireGuard 入站与[WireGuard 组网](../wireguard-network/index.md)分别配置。

1. 保存后确认端口已同步到在线 worker。
2. 从连接信息或订阅链接取得客户端参数，使用实际生成值。
3. 核对入口、服务端口、协议、认证、SNI、公钥 / 证书和 ALPN。
4. 用实际网页或应用验证 TCP，需要 UDP 时再验证经代理发送 UDP 的请求与响应。
5. 查看端口流量和连接诊断，确认请求走预期出口。

分享链接与二维码通常包含认证信息，应与密码一样保管。截图需同时遮挡凭据文本、二维码及可还原凭据的链接。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 看不到入站配置或某种协议 | 线路权限、有效协议名单、TLS / SOCKS5 过滤、账号角色 |
| TCP 能连但认证失败 | 客户端与入口协议、密码 / UUID / PSK、版本 |
| TLS 握手失败 | 证书链、域名 / SNI、有效期、ALPN、信任方式 |
| Reality 连接失败 | dest、SNI 白名单、公钥、UUID、Short ID、时钟 |
| QUIC 协议连不上 | UDP 监听、云安全组、系统防火墙、链路 UDP 支持、认证与 TLS |
| 探测成功但业务失败 | 客户端参数、真实目标、分流和上游出口配置 |
| 路径未经过全部中转 | 智能选择与固定前后跳数 |
