# 用户、套餐与计费

配置用户订阅、套餐线路、流量重置、续费和自动补流量，区分各层权限与额度。

运营前先准备服务器／组线路，再通过 **套餐管理**设置可复用规格，或在 **订阅管理**直接创建自定义用户订阅。客户端获取节点用的链接另见[客户端订阅](../client-subscriptions/index.md)。

## 先创建一份套餐

进入 **订阅管理 → 套餐管理 → 创建套餐**。

![套餐名称、额度、价格、计费周期与流量重置策略](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-package-form-4b1dcac02f52.png)

1. 填写内部名称、显示名称、总流量和每服务器最大端口数。
2. 设置计费类型、周期类型与周期数值，例如“按月、1”。“按月”与“按天、30”是不同周期。
3. 设置初始价格和续费价格模式：相同、固定价格或比例折扣。
4. 选择流量重置策略：跟随订阅计费边界，或每 N 天独立重置。
5. 添加至少一条 **套餐线路**，逐条核对带宽、流量额度、倍率及端口数。
6. 按需配置自带转发端点、监控、入站协议和客户端订阅权限。

**总端口数上限**限制所有线路合计；**每服务器最大端口数**是另一层限制。不要只调大总数却忽略每线路上限。

## 线路与能力设置

![套餐中的访问控制、协议权限、订阅链接和商城配置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-package-permissions-f30546eadc94.png)

- **流量倍率**影响扣量，倍率高低与用户实际传输字节分开核对。
- **允许入站代理**与**允许的入站协议**分别控制能力和协议集合；最终还需与服务器／组能力取交集。
- **默认端口入站防火墙**用于新端口预填；**强制入站防火墙**要求用户新建／编辑时选择规则集。
- **允许自带转发端点**决定用户能否接入自己的端点，不会自动部署机器。
- **商城可见（仅商用 tier）**决定用户能否在商城看到并购买，套餐状态、库存和用户资格也需满足。个人 tier 不支持商城销售。

库存表示总可售份数，售出不会自动回补。补货要调整库存；空值与数字 `0`按该字段提示处理，不把所有数字字段的 `0`都理解为“不限制”。

修改套餐后应查看受影响用户的实际配置与线路，不把修改模板当成所有存量订阅已经同步。以用户详情、生效配置和实际访问为准。

## 创建或调整用户订阅

进入 **订阅管理 → 添加订阅**，填写邮箱并选择套餐；套餐留空表示完全自定义配置。

![创建用户订阅：身份、激活、带宽、额度和计费](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-user-subscription-form-b0d3dea6bcd3.png)

选择套餐后核对带入的线路和计费信息。自定义订阅需自己填写带宽、流量、重置策略、周期、价格、访问控制及可用线路。确认 **立即激活**是否符合需求，再保存。

用户级“跟随套餐／系统”的选项与明确启用、禁用不同；填写覆盖值前先确认是否希望脱离上级设置。普通用户的协议、线路和资源限制仍须同时满足节点侧限制。

保存后用普通用户账号验证能看到的线路、可建端口数、入站协议和客户端订阅。超级管理员可绕过部分业务限制，不能用管理员测试结果代替用户验收。

## 到期、重置与续费

| 项目 | 影响 |
| --- | --- |
| 有效期 / 计费周期 | 什么时候到期、续费和计算下一周期 |
| 流量重置策略 | 什么时候刷新当期用量；可与计费周期分离 |
| 一次性计费 | 一种计费类型，不能据此推断“永不到期” |
| 延期 / 快速续费 | 使用对应操作核对新有效期、金额和流量处理，不只改一个显示日期 |
| 暂停 | 可能阻止业务运行；与欠费、流量超额、服务器暂停等原因分开排查 |

续费前看清价格来源和新的周期边界。手工重置流量、修改额度、延期、续费具有不同账务含义，不能相互替代。

用户流量异常时，结合端口、线路和服务器统计核对方向与倍率；测速产生的流量也可能计入订阅，见[诊断与测速](../diagnostics-speed-test/index.md)。

## 自动补流量

使用余额购买补充流量属于商用 tier 的余额与订单功能，个人 tier 不支持。套餐可配置 **单次补充流量、单次价格、每周期次数上限**。用户还需主动开启“用完自动补流量”；当期用量耗尽时，系统按该规格使用余额补充当期额度。

补充额度不延长有效期，重置边界到来后补充额度一并清零。未配置规格、余额不足或达到次数上限时，不能承诺持续自动补充。先核对订单、余额和补流量结果，再判断是否应该恢复业务。

付款、兑换码和推广仅商用 tier 支持，个人 tier 不支持，操作入口见[商城与运营](../operations/index.md)。多人管理和租户配额见[权限与租户管理](../access-control/index.md)。
