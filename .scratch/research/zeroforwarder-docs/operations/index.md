# 商城与运营

商城、支付、余额订单、兑换码和推广佣金仅商用 tier 支持；另介绍工单与公告操作。

面板的运营流程包括套餐销售、用户余额、订单、兑换码、推广、工单和公告。先按[用户与套餐](../users-packages/index.md)准备可用线路及规格，再逐项开放需要的功能。

配置时，支付密钥、用户邮箱、兑换码、收款账户和工单内容均应保密。

> **商用 tier 专属**：商城与套餐销售、支付接入、余额与订单、兑换码发行与兑换、推广与佣金等运营功能仅商用 tier 支持，个人 tier 不支持。购买前请按[首页定价](https://www.zeroforwarder.com/#pricing)咨询商用授权。

## 套餐上架与支付接入（仅商用 tier）

1. 在 **套餐管理**核对价格、周期、线路、权限、激活状态和库存，再开启 **商城可见**。
2. 在 **系统设置 → 注册与支付 → 支付方式**新增需要的方式，按类型填写 API 地址、商户信息、密钥、手续费、通知与返回地址。
3. 核对支付方式启用、排序，以及面板外部访问地址是否正确。
4. 用普通用户账号检查商城能看到的套餐、价格与购买提示。

商户密钥只填入自己的面板。回调地址应由实际支付服务能访问；用户浏览器返回成功页不能代替服务端付款状态确认。

商城通常先充值余额，再用余额购买套餐。已有订阅用户购买新套餐时，阅读界面对覆盖现有配置的提示，不把购买自动理解为只延长原套餐。

## 订单、续费与退款（仅商用 tier）

用户在 **订单中心**查看自己的订单与支付状态；管理员在 **订单管理**核对用户、订单类型、金额、支付渠道和状态。

处理异常付款时，对齐订单号、渠道交易结果与面板记录，再使用界面提供的操作。避免因重复刷新或重复回调人工加两次余额。

退款会影响余额和可能已经确认的推广佣金。先阅读退款窗口、余额不足和佣金回滚提示，再确认业务处理；“面板退款完成”不能脱离所用渠道与订单类型，被当作一定已经原路到账。

续费、延期和补流量是不同操作，效果见[到期、重置与续费](../users-packages/index.md#到期重置与续费)。

## 发行兑换码（仅商用 tier）

进入 **商城 → 兑换码管理**，选择创建或批量创建。

![兑换码类型、金额、前缀与有效期](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-redeem-code-create-67a94b3e7d80.png)

按用途选择余额充值、订阅延期或套餐兑换，填写相应金额／天数／套餐、前缀、有效期及批量数量。前缀用于分类，不是保密措施。

生成后只把代码交给对应用户。批量导出文件含可兑换材料，应限制访问；先核对未使用、已使用、已过期状态，再做作废或删除。

用户在对应兑换入口查看代码类型和确认信息后兑换。套餐码与延期码效果不同，不能把它们都描述为“增加余额”。租户未获允许分发能力时，相关创建入口可能不可用。

## 推广与佣金（仅商用 tier）

用户在 **推广中心**查看邀请链接、推广余额、佣金和提现记录。管理员在 **推广管理**配置推广规则、查看关系和佣金、处理提现申请。

1. 核对推广功能、奖励规格、确认条件与是否允许提现。
2. 区分待确认、已确认、已回滚佣金，以及主余额和推广余额。
3. 处理提现前核对申请人、金额与收款账户；审批记录和外部支付结果分别留存。
4. 订单退款或调整推广关系时，查看是否会回滚历史已确认佣金。

佣金已提现或转入主余额后，回滚可能产生 **未追回差额**。该项是对账记录，不会自动从未来佣金扣回；“核销差额”也不会自动转账或扣款，需要先完成实际账务处理再记录说明。

## 工单支持

超级管理员在 **工单设置**开启系统，设置自动关闭天数和用户未关闭工单上限，再创建、排序并启用工单主题。有工单管理权限的账号可维护其有权处理的主题与工单，平台基础开关仍需相应权限。

![工单主题的名称、描述、用户填写提示与状态](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-ticket-topic-20f07bcb25f2.png)

主题提示可以要求用户提供故障时间、端口 ID、错误信息和脱敏截图，避免索要密码、完整订阅链接或私钥。

用户在 **工单支持**选择主题、填写内容后提交；管理员在 **工单管理**打开工单、回复并更新状态。关闭工单不会修复业务；需要用户补充时给出具体所需信息。

关闭工单系统会阻止创建新工单，已有工单仍可查看。自动关闭根据最后活动时间计算，不能当作回复时限或已修复保证。

## 公告与维护通知

在 **系统设置 → 公告管理 → 创建公告**填写标题、Markdown / HTML 内容、生效和过期时间，并核对可见、置顶、排序与租户发布范围。

![公告的可见性、置顶、租户发布范围和时间设置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-announcement-create-492136cf06fa.png)

平台公告的 **下发到租户**开启后相应租户用户也能看到；关闭时只在平台侧可见。发布前使用预览检查格式和外链，尤其避免把内部机器地址或用户数据写进公告。

发布后用目标用户账号核对 **历史公告**和实际展示，不只看管理员列表。需要主动送达的告警或生命周期通知，另按[告警与通知](../alerts-notifications/index.md)配置渠道；公告可见不等于已发邮件或 Telegram。
