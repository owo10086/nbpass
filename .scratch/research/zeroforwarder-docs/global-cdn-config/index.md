# 一机拉全球

以一台入口接入多个地区落地，用端点组、链式路径和规则分流管理出口。

一台入口 worker 可以连接多个地区的落地端点。客户端统一连接入口，再由转发策略与分流规则决定出口。**选择最低延迟不等于按目标国家自动选择同国出口**；需要指定地区或服务解锁时，应明确配置规则。

## 第一步：部署并组织落地端点

在各地区部署 forwarder，确认入口能访问它们的业务地址和端口。在 **端点组管理**把可替换的落地放入同一候选组。

![端点组的成员与顺序管理](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-endpoint-group-5019d01db2e6.png)

这里创建的是 **端点组**，不是入口服务器组。入口组用于多个 worker，落地候选组用于多个 forwarder。

## 第二步：创建入站代理端口

在 **端口管理 → 添加端口转发**选择入口线路，展开 **入站配置 → 启用入站代理**，选择 Shadowsocks、VLESS、Reality 等客户端支持的协议。

![入站代理的协议、认证和连通性测试目标](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-inbound-ss-e696b23951e1.png)

通过表单填写认证和传输参数，不再手写旧式 `{"Ss":{}}`。没有额外出口代理时，顶部是连通性测试目标，真实访问目标由客户端请求携带。

## 第三步：选择出站路径

- 入口能直达各落地时，选择 **单跳转发**并加入落地候选。
- 需要 IX / 专线中转时，选择 **链式转发**，按 `中转组 → 落地组`组织。
- 需要末层必须保留为指定落地池时，锁定 **固定后 N 跳**；若整条链必须逐层经过，关闭智能选择或锁定全部层。

![链式路径的智能选择和固定前后跳数](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-port-chain-316e0f9fa2d4.png)

入站代理端口的最终出口由 **高级选项 → 目标选择模式（出口级）**控制；链中间级的均衡策略不等于出口策略。普通转发的策略作用范围另见[配置说明](../config/index.md#目标选择与测试方法)。

## 第四步：用规则指定地区或解锁出口

若希望特定域名走特定国家、标签或解锁节点，在 **路由配置 → 分流管理**配置：

1. 匹配规则：指定域名、IP、GeoIP 或其他条件。
2. 出口选择器：按标签、端点组、固定端点或解锁服务选择出口。
3. 分流规则：关联匹配与选择器。
4. 规则集：组织顺序和默认行为，再绑定到该端口。

![匹配规则已经支持直接逐行填写域名后缀](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-routing-match-4202789d3861.png)

对于地区限定的业务，兜底策略也要保留相应地区要求；使用 Auto 兜底可能离开指定出口池。操作步骤见[解锁服务与分流](../unlock-traffic-routing-guide/index.md)。

## 第五步：验证真实出口与故障行为

用客户端分别访问匹配和不匹配的目标，核对实际出口 IP、地区、解锁结果与连接诊断。更换出口不会让所有已建立连接自动迁移。

在测试线路上验证候选故障、恢复和全部候选不可用的情况。需要另一套完整路径时配置 [Fallback](../multi-fallback-line/index.md)，不要承诺固定 20 秒切换或零中断。

这套配置提供多出口接入能力；并不会仅凭“全球落地组”的名称自动保证地理匹配、最低延迟或持续可用。
