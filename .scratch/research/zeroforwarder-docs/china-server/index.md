# 国内机器最佳实践

为入口 worker 配置可达的控制通信路径，并独立选择业务是否走隧道。

当入口 worker 到面板控制器的直连不稳定时，可以通过一个可达的转发端点建立管理连接。先确认实际故障位于控制通信，避免把业务转发路径也一起改动。

## 只为管理连接配置中转

1. 准备一个入口可达、也能访问控制器的 forwarder，例如已验证可用的 IX 或优化线路节点。
2. 进入 **服务器管理 → 添加 / 编辑服务器 → 转发配置**。
3. 选择 **单跳转发**或合适的链式路径，加入该端点。
4. **使用转发端点作为传输**保持关闭：这里的端点用于管理连接，端口业务不默认沿用。
5. 保存后，在目标机器按该服务器记录提供的安装指引部署 worker，观察在线与同步状态。

![服务器的转发模式及“使用转发端点作为传输”开关](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-forward-be5426fded2c.png)

选择可达的端点并保存。不要复制其他节点的安装命令或 Token。

## 业务路径单独配置

若业务也需要经过 IX，可开启服务器默认传输，或在具体端口选择中转。是否开启取决于业务拓扑，不应对所有机器统一套用“永远关闭”或“永远开启”。

同机第二个 worker 也要检查自己的配置、服务名、目录和控制器可达性，不能因为第一个实例在线就省略检查。

## 验证与排查

- 检查控制器域名、实际监听端口、DNS、系统时间和防火墙。
- 从入口检查所选端点，再从端点检查控制器。
- 节点在线后，另用实际业务验证端口路径；管理在线不等于目标可达。
- 只有管理连接需要备用时，参考服务器级 [Fallback](../multi-fallback-line/index.md)。

字段说明见[配置说明](../config/index.md#控制通信与业务传输)。
