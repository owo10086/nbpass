# 连接诊断与测速

用实时连接、拦截记录、延迟监控和速度诊断定位问题，区分测速范围、限速影响与流量计费。

端口连不上、访问绕路和吞吐量偏低，需要看不同证据。先确认配置同步与实际连接，再对需要的路径做测速，通常比直接调整协议或增大并发更容易定位问题。

## 按问题选择工具

| 要确认什么 | 使用入口 | 结果的范围 |
| --- | --- | --- |
| 配置是否到达节点 | 端口列表同步状态、节点在线状态 | 配置下发与在线情况 |
| 当前请求去了哪里 | 端口的 **连接统计** | 当前已列出的连接、目标和转发器 |
| 是否被规则阻止 | 连接统计的 **拦截记录** | 已记录的拦截事件与命中规则 |
| 延迟和丢包何时变化 | 端口延迟详情、**延迟监控总览** | 指定探测目标和时间范围 |
| 端口内部转发路径有多快 | 端口 **更多（…）→ 速度诊断** | 本次选定的 worker 到末跳 forwarder 路径 |
| 节点到公共测速服务或另一个节点有多快 | 管理员 **延迟监控总览 → 全球测速** | 所选节点之间或到公共服务的测试 |

延迟低不等于带宽大，TCP 端口探测成功也不等于认证、TLS 和应用请求成功。最终仍需使用真实客户端访问目标服务。

## 查看端口连接统计

进入 **端口管理 → 端口管理**，点击目标端口操作栏的 **显示器图标（连接统计）**。

![连接统计：实时连接、累计统计、转发器分布、拦截记录和探测采集](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-connection-stats-ff9ac671e813.png)

### 实时连接

保持客户端进行实际访问，再点击 **刷新**，重点核对：

- **客户端地址**：请求是否来自预期设备。
- **目标地址 / 真实目标**：请求目标及实际连接地址是否符合预期。
- **入口服务器 / 转发器**：业务是否经过预期节点。
- **规则、上传和下载**：是否命中预期分流，是否已经产生数据。

使用 **显示搜索**和 **列设置**缩小范围。过滤、排序及下拉选项只作用于已列出的连接，不代表搜索了节点上所有未加载连接。

上方累计统计与实时表格的时间范围不同：累计请求数、已关闭连接质量等是统计期间累积的数据，实时表格则可能已经没有连接。图中“累计请求数 1、实时 0”就是这种情况，不能据此判断业务异常。

### 拦截记录和探测采集

- **拦截记录**：按时间、来源、目标和命中规则检查拒绝原因。先确认规则作用层级，再修改对应防火墙或分流配置，避免只在一层放行后误以为全部生效。
- **探测采集**：查看已采集的来源、识别协议、样本长度和关闭原因，辅助判断端口扫描或异常请求。协议识别与样本只是线索，不等于成功建立了业务会话。

探测样本、来源 IP、目标地址、分享链接和认证信息都不适合直接公开。需要提交排障材料时，只保留与故障相关的字段并打码。

## 检查延迟与丢包

需要把节点测量与端口拓扑对照时，使用[网络规划图](../network-planning/index.md)。服务器详情另有监控、流量、延迟、连接、设备与日志页；选择同一故障时间和具体入口，区分当前值、历史样本与实际业务连接。

点击端口列表的延迟值查看详细统计；需要较长时间趋势时，进入 **端口管理 → 延迟监控总览**，按节点、探测目标和时间范围筛选。

比较时保持同一目标、同一探测方式和相近时段。先确认看的是哪一段路径，再结合客户端现象判断：

- 入站代理的连通性测试目标可以与真实业务目标不同。
- 节点到探测目标的延迟不包含用户设备到入口的全部体验。
- 路径切换、目标变化或测量缺失时，不应把图上不同阶段直接当成同一路径比较。

历史线路对照见[延迟测试记录](../latency-test/index.md)，该文章中的结果有自己的测试时间和环境。

## 端口速度诊断

在目标端口的 **更多（…）** 菜单中选择 **速度诊断**。

### 先确认权限与适用范围

服务器需要允许测速；导入的共享服务器还需要共享方允许。服务器组端口可以在诊断界面选择具备条件的物理成员，不能把一台成员的结果当成整个组的总带宽。

![服务器未允许测速时的权限提示](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-speed-diag-disabled-58e727a07763.png)

出现图中提示时，由有权限的管理员在对应服务器配置中核对 **允许测速**。共享方的上限也必须满足；普通用户无法通过本地按钮绕过限制。这个提示不表示线路已经测得速度为零。

当前速度诊断用于支持该能力的单跳转发和转发链，测量从端口所在 worker 到最后一个 forwarder 的生效路径，**不包含用户设备到入口、落地到最终业务目标的部分**。直连无转发路径、TOT、没有固定目标的入站代理、后端传输等场景可能提示不支持，以界面返回的原因和节点能力为准。

### 设置参数并核对扣量

权限和路径可用后：

1. 查看 **本次路径**和 **适用目标**，确认测到的是要排查的链路。
2. 选择上行（朝落地）、下行（朝入口服务器），可以分别测试。
3. 选择 **按时长**或 **按数据量**。时长范围为每方向 5–60 秒；按数据量时也是每个所选方向分别执行。
4. 设置并行流数，范围 1–8。比较单连接表现时可以使用 1 流；比较多流结果时应保持流数一致。
5. 阅读端口限速、动态限速、共享端点限速及流量提醒，再点击 **开始测速（计入订阅流量）**。

**端口速度诊断按正常业务规则计入该端口所属订阅流量，包含实际流量倍率。** 每方向约 2 秒预热、中途停止前已经产生的流量也会计入；按数据量选择的数值不是最终扣量上限，多流也可能增加消耗。

测速与正常业务共用端口带宽和限速额度，可能影响正在进行的业务；动态限速窗口也会计入这些流量，影响后续速度。

普通用户同一订阅每 30 分钟可发起一次，不按端口或线路分别计算。管理员权限及当前冷却时间以界面提示为准。

### 结果如何读

| 结果字段或提示 | 含义 |
| --- | --- |
| 均速、峰值（1 秒） | 正式测量期间的平均值与短时峰值，比较时保持方向、路径和参数一致 |
| 正式字节、正式时长 | 测量样本，不是含预热、倍率后的最终订阅扣量 |
| 已达限速 / 已达共享端点限速 | 已触及配置上限，不能据此断言物理线路只能达到这个速度 |
| 可能受动态限速约束 | 结果不足以判断链路自身瓶颈 |
| 历史测量 · N 分钟前 | 复用结果，需要与“本次实测”区分 |

开启 **复用 1 小时内结果**后，只匹配本端口、相同路径和参数、限速未变的缓存结果。实际复用时不产生新的测速流量；界面没有标为复用，就不能按“本次免费”理解。

需要中断时点击 **停止**。关闭对话框也会请求取消正在运行的任务，已经产生的流量仍照常统计。最后扣量以订阅流量统计为准。

## 管理员全球测速

平台管理员进入 **端口管理 → 延迟监控总览 → 全球测速**。这个工具适合分段定位，入口与普通用户的端口速度诊断不同。

![全球测速：选择服务器或端点、自定义 URL、时长和 TCP 流数量](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-global-speed-config-25fee6810a24.png)

1. 选择 **服务器 ↔ 公共服务器**、**服务器 ↔ 转发端点**或 **转发端点 ↔ 转发端点**模式。
2. 选择需要比较的少量在线节点，按当前模式填写另一端。
3. 对公共服务测试时，选择自定义 URL、Speedtest 服务器或 Cloudflare。
4. 核对方向、时长 / 数据量及 TCP 流数量，确认后开始。

**自定义 URL 当前只支持下行测试。** 需要上行或双向时，改用 **Speedtest 服务器**；可以留空服务器 ID 自动选择，也可填写指定 ID。

![Speedtest 服务器模式：测试方向、按时长或数据量以及并行流设置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-global-speed-speedtest-ee9e11bf1e2e.png)

可选节点资格随模式变化。例如公共服务模式下的转发端点，只能选择自有、非导入、非分组且在线的端点。不要把列表没有某个节点直接当成离线故障。

全球测速会消耗节点带宽和资源。共享服务器的此类测速不计入租户流量额度，而从端口发起的速度诊断按端口所属订阅扣量；两种工具的结果和计费口径不能混用。节点直测结果也不能替代经端口、分流和限速后的实际业务表现。

## 常见提示与排查顺序

| 提示或现象 | 下一步 |
| --- | --- |
| 端口尚未同步 / 节点不在线 | 先恢复管理连接和配置同步，再诊断业务 |
| 服务器或共享方未允许测速 | 核对对应权限层，不修改测试参数反复重试 |
| 节点版本过旧 | 升级提示列出的节点后再试 |
| 无固定目标 / 无转发路径 / 模式不支持 | 按实际场景改用连接统计、分段诊断或客户端测试 |
| 生效路径已变化 | 重新获取路径，按新路径开始，避免比较错对象 |
| 相关节点正在测速 | 等已有任务结束，避免并发争用 |
| 部分测速流失败 | 结果只包含成功的流，不代表完整多流能力 |
| 节点未确认测速流停止 | 稍后重试，不连续发起新任务 |
| 速度低但已达限速 | 先核对端口、订阅、共享资源和动态限速，再判断线路容量 |

建议按“在线与同步 → 实际连接 / 拦截 → 延迟趋势 → 限速与额度 → 必要的吞吐量测试”排查，保存故障时间、方向、路径和参数，便于复现。
