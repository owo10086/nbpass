# 解锁服务与分流

用可视化匹配、出口策略和规则集配置分流，结合解锁检测、防火墙与规则测试验证。

域名、IP、端口范围、GeoIP、ASN 和组合条件已有可视化编辑器，普通配置不必手写匹配 JSON。

## 入口与配置顺序

左侧 **路由配置**包含 **解锁服务配置**和 **分流管理**。当前分流管理有匹配规则、出口选择器、分流规则、规则集、防火墙规则、防火墙规则集、规则测试等入口。

| 对象 | 回答的问题 |
| --- | --- |
| 匹配规则 | 哪些流量命中，例如 `.example.com` 的域名后缀 |
| 出口选择器 | 命中后选择哪些出口 |
| 分流规则 | 把一个匹配规则与一个出口选择器关联 |
| 规则集 | 按顺序组织规则，定义未命中的默认行为 |

建议先做 **匹配 → 选择器 → 分流规则 → 规则集 → 端口绑定 → 测试**。只有需要按服务解锁状态选出口时，才需先创建解锁服务。

## 第一步：创建匹配规则

进入 **分流管理 → 匹配规则 → 创建**，填名称、显示名称和匹配类型。

![域名后缀使用逐行输入，不必填写 JSON](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-routing-match-4202789d3861.png)

选择 **域名后缀匹配**时，每行填写一个后缀，例如：

```text
.example.com
.example.net
```

其他类型按对应表单填写：

| 类型 | 表单内容 |
| --- | --- |
| 域名精确、后缀、关键词、正则 | 每行一项，遵循类型提示 |
| 目标 / 来源 IP CIDR | 每行一个地址或网段，区分目标与客户端来源 |
| 目标 / 来源端口 | 逐行端口，或添加起止端口范围 |
| 协议 | 按提示填写所需协议 |
| 目标 / 来源 GeoIP | 国家 / 地区与排除设置 |
| 目标 / 来源 ASN | ASN 条目与对应条件 |
| 组合条件 | 添加子条件与 AND / OR / NOT 关系；NOT 只取一个子条件 |
| 外部规则文件 | URL、格式与规则内容；可刷新导入 |

外部文件支持 Clash、Surge、Quantumult X、自定义等界面提供的格式。检查解析后的规则，不要仅因下载成功就认为条件正确。

右侧 **`{ }`**可切换到 JSON 编辑。它用于检查或高级维护；非法 JSON 会阻止切回可视化模式。切换匹配类型前先确认当前内容，保存时按对应类型校验。

## 第二步：创建出口选择器

进入 **出口选择器 → 创建**，填写名称与显示名称，通过 **添加策略**组织候选策略。

![出口选择器的策略字段和自动生成的 JSON 预览](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-routing-selector-4fa44045b806.png)

| 策略 | 需要填写 |
| --- | --- |
| 按标签 | 标签及“任意 / 全部”匹配方式 |
| 按解锁服务 | 已配置的解锁服务 |
| 按端点组 | 端点组 |
| 固定端点 | 指定端点列表 |
| 自动 | 返回自动策略，无需额外候选字段 |
| 拒绝 | 拒绝连接 |

策略按顺序尝试；无候选时尝试下一项，选出候选或遇到自动 / 拒绝时结束此策略链。JSON 预览由表单生成，无需复制到自定义配置。

例如解锁优先可配置 `按解锁服务 → 按备用标签 → 自动`。如果业务必须使用指定地区或解锁出口，应使用符合要求的兜底或拒绝，不能用 Auto 仍宣称强制解锁。

## 第三步：关联分流规则

进入 **分流规则 → 创建**，选择刚创建的 **匹配规则**和 **出口选择器**，填写名称并保存。确认相关对象启用，且当前账号有权使用。

“公开”控制资源可见 / 使用范围，不等于已经绑定端口，也不代替云防火墙或系统防火墙。

## 第四步：组织规则集并绑定端口

进入 **规则集 → 创建**，添加分流规则，调整顺序和默认行为。

![规则集的默认行为与添加规则入口](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-routing-ruleset-edfb93e52448.png)

- 优先级数字越小越先匹配；范围较窄的规则通常放在宽泛规则前。
- 同一规则集不应重复添加同一规则或重复优先级。
- **自动**：跟随默认策略。
- **拒绝**：未命中时拒绝。
- **使用指定选择器**：还需选择默认出口选择器。

保存后进入 **端口管理 → 编辑 → 高级选项 → 分流规则集**绑定。创建规则集不会自动作用到所有端口。

按顺序命中的规则决定分流结果；选择器、规则、规则集的启用状态和资源权限也会影响实际生效。

## 第五步：先做规则测试，再做真实访问

**分流管理 → 规则测试**可选择分流规则集、防火墙规则集或单条匹配规则，输入域名 / IP、目标端口和 TCP / UDP，按需展开来源、Geo / ASN 覆盖。

![规则测试的测试范围、目标、协议和来源字段](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-routing-test-0c9294fab30b.png)

1. 输入一个应命中的目标，检查命中规则与策略。
2. 输入一个不应命中的目标，核对默认行为。
3. 涉及来源、GeoIP 或 ASN 时，补齐相应测试上下文。
4. 绑定端口并确认同步后，用真实客户端访问，核对出口与目标服务结果。

规则测试用于解释条件和策略，不证明节点网络、脚本解锁或应用已可用。手动覆盖的 Geo / ASN 也不是实际查询结果。

## 可选：配置解锁服务

进入 **路由配置 → 解锁服务配置 → 创建**，填写以下字段。

![解锁检测的脚本来源、参数、超时和缓存设置](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-unlock-service-7a7cb1707875.png)

| 字段 | 填写方法 |
| --- | --- |
| 名称 / 显示名称 | 唯一标识与可读名称 |
| 脚本类型 | Bash 或 Python，与脚本内容一致 |
| 脚本 URL / 脚本内容 | 至少提供一种，URL 下载脚本体积上限为 1 MB |
| 脚本参数 | 每行一个参数，按顺序传给脚本 |
| 超时时间 / 缓存有效期 | 单位均为 **毫秒**，例如 30000 为 30 秒 |
| 目录 / 优先级顺序 / 状态 | 按服务分类、排序及是否参与使用配置 |

脚本在实际执行节点运行，应使用自己确认的脚本来源与依赖。保存后通过 **解锁服务即时测试**选择端点和服务，检查返回消息；该面板没有预置示例服务时，需要先创建自己的服务。

### 脚本结果判定

脚本应在最后一行单独输出 `Yes` 或 `No`。当前完整输出的判定顺序是：

1. 最后一行包含 `No` 或 `0`，判定未解锁。
2. 否则包含 `Yes`，判定已解锁。
3. 否则依据进程退出码，成功退出视为已解锁。

超时、输出超限被终止、输出未完整收集时会判定未解锁。因此不要让最后一行只是带数字的日志，也不要用“始终 exit 0”的脚本掩盖检查失败。

测试结果有缓存；更换脚本或出口后要结合缓存时长核对重新测试结果，不能把旧结果当作新配置已验证。

## 防火墙与分流分别配置

完整的创建、绑定、下发状态与协议过滤步骤见[防火墙与访问限制](../firewall/index.md)。

**防火墙规则 / 防火墙规则集**用于连接的允许或拒绝，分流用于出站选择。创建时核对方向：

- 入站规则集约束进入服务器 / 端口的连接，端口级限制在服务器放行后进一步收紧。
- 出站规则集约束对外访问；它不等于把流量导向某个出口。
- 端口的 **入站防火墙规则集**与 **分流规则集**是两个独立字段，不要混选。

先用规则测试核对方向、来源和目标，再绑定到对应资源并做真实访问。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 看不到刚创建的匹配 / 选择器 | 启用状态、公开范围、当前账号权限 |
| 保存匹配规则失败 | 逐行格式、范围端口、组合条件、JSON 是否匹配类型 |
| 默认使用选择器却不能保存 | 是否选择默认出口选择器 |
| 规则测试正确、客户端未分流 | 规则集是否绑定正确端口、是否同步、真实请求是否有相同域名 / IP 上下文 |
| 解锁测试超时或失败 | 脚本来源、依赖、外网、输出完整性、超时单位与缓存 |
| 多条策略未按预期兜底 | 策略顺序、候选范围、Auto / Reject 是否提前结束 |
| 删除对象失败 | 先检查引用它的上游资源并解除引用 |
