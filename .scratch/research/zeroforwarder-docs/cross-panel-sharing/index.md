# 跨面板资源共享

区分共享 worker 与共享转发端点的邀请方向，配置额度、安全限制、安装和退出流程。

跨面板共享让两个独立面板合作使用机器。先分清 **机器拥有方**和 **业务使用方**；同一面板里的[租户](../access-control/index.md#划分租户与配额)是另一种管理方式。

## 先选共享哪种资源

| 类型 | 提供什么 | 共享码由谁生成 | 谁安装节点 |
| --- | --- | --- | --- |
| 共享服务器 | worker 入口，使用方可在限制内建端口和经营业务 | **业务使用方**在服务器管理生成邀请 | 机器拥有方导入邀请后，在自己机器上安装独立共享 service |
| 共享转发端点 | forwarder 中转／落地，使用方纳入自己的转发路径 | **机器拥有方**从自有端点创建共享 | 拥有方维护原有 forwarder，使用方导入，无需重新安装它 |

共享依赖双方当前版本、授权和功能开关。页面提示功能未启用时，先由管理员核对能力，不通过改 URL 或复制另一种共享码绕过。

## 共享服务器：使用方先发邀请

在**业务使用方**面板进入 **服务器管理 → 共享邀请**：

1. 填写显示名称和 worker 管理 WebSocket 地址，例如 `wss://panel.example.com/worker_ws`。
2. 核对该地址从目标机器可达，并按需要填写最低 worker 版本。
3. 创建邀请，把仅展示一次的 `ZFCSRVSHARE1:`共享码安全交给机器拥有方。

不要把面板首页地址当作完整 worker WebSocket 地址，也不要把邀请的生成方向写反。

## 拥有方导入并设定限制

在**机器拥有方**面板进入 **端口管理 → 共享服务器 → 导入共享服务器**。

![拥有方导入共享服务器邀请，配置入口、配额与端口段](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-share-import-5c1cc5e61ef1.png)

填写共享码、服务器名称、入口 IP、可选的对端展示名称和本地备注，随后设置：

| 限制 | 操作要点 |
| --- | --- |
| 流量与有效期 | 一次性总额或周期重置；额度按对端全部端口的双向用户流量计算，控制和探测流量不计 |
| 端口段与数量 | 同一入口 IP 上的不同共享服务不能有重叠端口段；端口段在安装时固化 |
| 带宽与连接 | 总带宽／上下行独立，以及连接数和 IP 数上限 |
| 能力 | 是否允许入站代理、转发端点／链、测速、实时日志和调试导出 |
| 出向访问 | 核对私网、回环及本机访问基线，按需添加明确的允许／拒绝规则 |

拥有方的外层出向限制与使用方自己的出站规则串联，使用方不能放宽拥有方限制。不要为了某个私网服务直接放开整个私网范围。

导入可能先进入 **确认中**；等双方确认完成后再生成安装脚本，不把“已出现卡片”当成可以运营。

拥有方点击 **安装脚本**，核对目标机器与出口网卡，在自己的机器执行一次性安装命令。安装链接有效期为 30 分钟；过期后重新生成。使用方不能获取安装私钥或代替拥有方安装、升级该共享 service。

安装并上线后，使用方在自己的 **服务器管理**看到入口，在获准端口段内创建业务。先用一条测试端口核对监听、入站权限、传输路径及双方流量统计。

## 共享转发端点：拥有方先生成共享码

在**拥有方**面板的 **转发端点 → 更多操作 → 共享管理 → 新增共享**，配置流量总额／周期、有效期和入站 CIDR 白名单，然后把 `ZFCSHARE1:`共享码交给使用方。每条共享有独立密钥；共享码仅展示一次，成功导入后作废。

在**使用方**面板进入 **转发端点 → 导入共享端点**，填写共享码和展示名称。

![使用方导入共享转发端点；该共享码与服务器邀请不同](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-endpoint-share-import-5728de71bef8.png)

导入后检查 **共享信息**的状态、额度、最近同步及异常提示，再把端点加入单跳、端点组或转发链。拥有方维护实际节点，导入方不能将它当成自有节点执行安装升级。

拥有方会维护对端 worker 地址白名单，也可增加手动 CIDR。需要公网和内网出口限制时，检查该共享的出向规则；更换入口 worker 后确认白名单同步，不能只测试面板之间 HTTP 可达。

端点配额与双源对账各有口径；“对端上报”和 forwarder 按密钥计数不应直接当作同一项。同步失败、超额暂停、到期或吊销时，先查看共享状态和最近错误。

## 修改与退出

收紧资源限制前查看影响预览；节点离线而无法预览时，不能据此认定没有受影响端口。

- **暂停服务器共享**会停止对方端口监听并断开已有连接；恢复后重新起端口。
- **吊销／释放**属于退出流程。共享 service 的卸载由机器拥有方在对应机器完成。
- **删除记录**不等于已经卸载机器上的进程。离线、待清理或强制删除提示需要单独处理，不能把未知状态当成停止成功。
- 端点退出前先清理端口、组、链和分流引用，再核对节点侧共享密钥与访问限制已更新。

共享码、安装链接、Token、入口地址和对端识别信息都应脱敏后再公开。需要管理权限、API 接入和操作追溯时见[权限与租户管理](../access-control/index.md)。
