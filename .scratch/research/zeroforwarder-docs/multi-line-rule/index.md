# 多线路共同维护

把多条入口线路纳入同一规则，统一端口与业务配置，完成逐线路预检、扩展和批量维护。

同一个服务需要在多个入口提供时，可以用 **多线路共同维护**统一管理名称、监听端口、目标、转发路径和入站代理等配置。以后修改共同规则，就能同时更新所属线路。

## 先选对功能

| 需求 | 使用方式 |
| --- | --- |
| 多条入口线路提供同一个服务，统一修改配置 | 多线路共同维护 |
| 多台入口服务器作为一个组，成员随组增减 | 服务器组，也可以作为共同规则的一条线路 |
| 一条转发路径故障后换到另一条路径 | [多备用线路](../multi-fallback-line/index.md) |
| 一条 TCP 连接利用多条链路的带宽 | [TOT 带宽聚合](../bw-merge/index.md) |

共同规则中的入口仍是多个独立连接地址。客户端要连接哪个入口，由客户端配置、订阅或另行配置的 DNS 调度决定；创建共同规则本身不会完成入口故障切换，也不会聚合单连接带宽。

需要组内统一部署时，先配置[服务器组](../server-groups/index.md)；需要权威 DNS 调度时，继续阅读[智能 DNS](../smart-dns/index.md)。

## 新建一条共同规则

进入 **端口管理 → 端口管理**，点击列表上方的 **多线路共同维护**。

![共同规则表单：多选线路、统一监听端口、逐线路预检和端口额度](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-rule-create-4c1d4f63aa92.png)

1. 填写名称，例如 `教程示例 · 多入口`。
2. 在 **线路**中选择独立服务器或服务器组，可以多选。组内物理成员通过服务器组维护，不要再逐台重复选择。
3. 点击 **自动选号**，从所选线路的共同可用范围内选择端口；也可以手动输入，再点击 **检查**。
4. 查看预检摘要，确认每条线路的端口范围、可用性、额度和实际部署台数。
5. 普通转发填写共同目标，例如 `example.com:443`；入站代理按[入站代理教程](../inbound-proxy/index.md)设置，目标栏含义会随配置变化。
6. 配置共同的转发路径、协议、限速及流量控制，检查后点击 **添加**。

图中两条独立线路共同使用 `32194`，这个数字是当次自动选号的结果。自己的环境应重新选号或预检。

**预检不会预占端口。** 正式提交时还会重新检查；预检后其他程序或规则占用了同号端口，保存仍可能失败。

## 额度、带宽和组成员如何计算

- **端口额度按逻辑线路计算**：两条独立服务器线路消耗两个端口额度。服务器组按一条线路计额，组内物理部署台数另行展示。
- **组成员随服务器组同步**：组线路加入共同规则后，组内成员的增减沿用服务器组同步机制。
- **端口限速按每台服务器执行**：例如设置 `100 Mbps`，界面可能显示“100 Mbps/台，共 N 台（不合计）”。它不是所有入口共用的一份总带宽；实际速度还受订阅、套餐线路、共享资源及物理带宽约束。
- **流量按实际使用路径统计**：各线路的倍率和实际经过的端点会影响扣量。把线路纳入共同规则不等于只扣一次固定流量。

## 从已有端口扩展

在普通端口的 **更多（…）** 菜单中选择 **扩展为多线路共同维护**。

1. 核对来源端口带入的目标、转发方式和入站配置。
2. 保留原线路，增加需要提供同一服务的线路。
3. 尽量沿用原监听端口，对新增线路逐一预检。
4. 如必须换号，先安排客户端连接地址更新，再保存。

这个操作把来源端口纳入共同规则，并按共同配置扩展到新增线路；它不会自动把其他独立创建的同名端口合并进来。新增线路上已有同号规则时，需要先处理冲突。

## 编辑、增删线路与换号

创建后，列表显示 **共同规则 · N 条线路**，并列出多个入口地址，可以使用 **复制全部**取得这些地址。

编辑共同规则时，可以调整线路集合和共同字段。保存前重点检查：

| 操作 | 影响 |
| --- | --- |
| 修改目标、入站认证或转发配置 | 应用于共同规则的全部成员线路，客户端参数也可能需要更新 |
| 增加线路 | 按规则当前监听端口预检，并检查新增端口额度 |
| 移除线路 | 删除该线路上的成员端口；组线路还涉及对应物理副本 |
| 修改统一监听端口 | 各成员整体换号，**各线路当前流量统计会清零** |
| 出现“线路配置不一致” | 保存会把提示字段统一为当前表单值，先核对差异再确认 |

界面展示了第一条线路的部分配置提示，不代表其他线路都满足要求；以逐线路预检和保存返回的结果为准。

如果提示规则已被其他操作修改，重新打开表单读取当前配置，再应用自己的改动。

## 批量维护与暂停

使用 **多选 → 批量编辑**处理多条规则时，包含共同规则的选择会出现 **增加线路 / 移除线路**选项。默认“保持不变”；线路增删只作用于共同规则，普通端口不受这组操作影响。

每条共同规则分别执行字段修改与成员增删，不能移除一条规则的全部线路。批量结果可能包含成功和失败的不同规则，应逐项查看，不能把其中一条成功理解为整批成功。

**暂停、恢复和删除针对共同规则整体操作时，会影响其全部成员线路。** 部分线路已经暂停时，按界面的“暂停其余线路”等提示核对范围。删除规则会删除全部成员端口，操作前先检查列出的线路和端口。

## 保存后逐入口验证

1. 查看规则及组内成员同步状态，处理“待同步 / 同步失败”。
2. 分别核对每个入口的地址、统一端口、云安全组和系统防火墙。
3. 从客户端逐个连接入口，验证实际应用请求，而不只看探测延迟。
4. 查看各线路连接统计，确认业务使用了预期的目标和出口。

| 预检提示 | 处理方式 |
| --- | --- |
| 端口范围没有交集 | 调整所选线路，或检查允许端口范围；手填也必须满足实际约束 |
| 端口已被占用 / 服务器仍占用 | 换号或排查已有监听；刚删除同号规则时，等待旧监听释放后再检查 |
| 服务器离线或无法探测 | 恢复节点连接，再检查端口是否空闲 |
| 端口额度不足 | 减少新增线路或调整对应订阅额度 |
| 配置与线路不兼容 | 核对转发、入站协议、监听协议和线路权限 |
