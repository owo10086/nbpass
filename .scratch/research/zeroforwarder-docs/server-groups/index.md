# 服务器组

把多个 worker 组成入口线路，统一部署端口，配置自动加入、入站策略和 DNS 健康切换。

服务器组把多个入口 worker 作为一条逻辑线路使用。在组线路上创建端口后，面板向实际成员同步对应配置，客户端可以通过各入口或统一域名连接同一服务。

示例域名、端口范围和权限应按自己的环境填写。

## 服务器组与其他组有什么区别

| 对象 | 管理什么 | 适合的需求 |
| --- | --- | --- |
| 服务器组 | 多个入口 worker | 同一服务部署在多个入口，成员随组维护 |
| 端点组 | 多个 forwarder 候选 | 为转发路径的一层提供多个中转或落地候选 |
| [多线路共同规则](../multi-line-rule/index.md) | 多条独立线路或组线路 | 跨线路统一维护业务配置和监听端口 |
| [智能 DNS](../smart-dns/index.md) 节点池 | 独立的权威 DNS 调度节点 | 按业务组健康和权重调节后续解析 |

服务器组本身不聚合单条连接的带宽。统一入口域名还需要正确的 DNS 配置，已有客户端连接也不会因组成员变化自动迁移。

## 第一步：准备入口服务器

1. 在 **端口管理 → 服务器管理**添加并部署 worker，确认在线。
2. 核对准备使用的端口范围、TCP / UDP 支持，以及每台机器的安全组和防火墙。
3. 准备统一入口域名，例如 `entry.example.com`。使用手动 DNS 时，自行配置解析；使用组 DNS 自动切换时，还需要 DNS API 配置。

节点基础字段见[配置说明](../config/index.md)，DNS 凭据的创建步骤见[动态域名与 DDNS](../dynamic-dns/index.md#配置-dns-api)。

## 第二步：创建服务器组

进入 **端口管理 → 服务器组管理 → 创建组**。

![创建服务器组：名称、统一入口地址、端口范围与入站协议策略](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-group-basic-5c6c457e7288.png)

| 字段 | 填写方法 |
| --- | --- |
| 显示名称 | 便于识别用途，例如 `教程示例 · 多入口组` |
| 入口地址 | 客户端使用的统一域名，例如 `entry.example.com`；填写域名不会自行创建解析 |
| 端口范围 | 组线路允许分配的端口范围，需与实际成员监听条件一致 |
| 服务器 | 在下方双栏中搜索成员，添加到已选列表；支持 Shift 多选和双击快速添加 |
| 入站协议策略 | 限制订阅用户可用的入站协议；空白名单表示不限制协议 |
| 强制使用入站代理 | 需要仅提供代理协议端口时启用，先核对现有业务需求 |

手动建组且未开启自动添加时，需要选择成员。选择已有成员时，还应核对其现有组归属和端口占用，以保存时的检查结果为准。

入站协议策略是实时组策略，成员默认继承，也可在成员服务器上覆盖；管理员不受这组协议限制。它与“自动添加”模板中的权限开关用途不同。

## 第三步：在线路上创建端口

保存组后，进入 **端口管理 → 端口管理 → 添加端口转发**，在线路中选择该服务器组，再按[转发指南](../fwd-guide/index.md)或[入站代理](../inbound-proxy/index.md)设置业务。

组线路的端口会同步到物理成员。保存后检查各成员同步状态，并分别测试 `成员地址:统一端口`。组记录创建成功不代表所有机器已经完成监听。

不要把原先独立创建的同名端口直接当成组规则；应以组线路创建的规则及同步结果为准。组中某台机器已被其他程序占用端口时，也不能仅凭其余成员成功就判断全组可用。

## 使用自动加入扩容

组表单的 **允许自动添加**适合通过脚本链接把新服务器加入组。

![自动加入模板：转发与入站权限、测速权限、流量倍率、连接及带宽限制](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-group-auto-add-7fe4b65bc126.png)

1. 开启自动添加，配置新加入服务器的权限与限制。
2. 核对是否允许自备转发端点、入站代理、延迟测试和测速。
3. 按业务设置流量倍率、IP / 连接数限制、协议过滤及带宽限制。
4. 保存后，在组列表使用 **复制脚本链接**，按安装流程部署新机器。
5. 新成员上线后，检查组内设备、配置同步和实际端口连通性。

脚本链接含有自动加入所需的信息，按安装凭据保管，截图和公开排障材料中应遮挡完整链接。修改自动加入模板后，不要假定所有旧成员的单机设置都已随之更新；另行核对已有成员配置。

## 配置组 DNS 自动切换

这项功能通过外部 DNS 服务商维护组入口域名的记录。它与智能 DNS 的权威节点池是不同入口，前者在组表单配置，后者有独立控制台。

组 DNS 配置仅对具备权限的超级管理员和平台所属组开放。看不到该区域时，先核对账号与组归属。

![组 DNS 自动切换：观察模式、DNS 配置、TTL、最少保留数、入口互测与确认时长](https://img.coderluny.com:444/uploads/zfc-tutorial-20261018-server-group-dns-bec1f21d6f1c.png)

1. 创建并启用 DNS API 配置，核对受管区域与记录写权限。使用 Webhook 时按 [DNS Webhook 接入指南](../dns-webhook/index.md)部署和验收；其域名列表来自配置，面板不向接收端查询真实 DNS 状态。
2. 在组中填写该区域内的入口域名，开启 **DNS 自动切换**。
3. 选择 **DNS API 配置**与 **DNS 区域**，核对 TTL 和最少保留数。
4. 初次配置保留 **仅观测模式**，先查看健康判断；它只记录判断，不执行 DNS 变更。
5. 确认判断与实际网络情况一致后，再关闭观测模式并保存，允许执行记录调整。

DNS 配置的最低 TTL 会约束组记录，低于下限的输入可能被自动抬升。输入较短 TTL 不代表公共递归和客户端能在同样时间内全部刷新。

### 健康参数怎样理解

| 参数 | 含义 |
| --- | --- |
| DNS 最少保留数 | 限制继续摘除的范围，避免把某地址族的候选全部移除；保留下来不等于节点健康 |
| 确认时长 | 不通与恢复需持续达到该时长，劣化需持续两倍时长；范围 60–1800 秒 |
| 丢包率阈值 | 用于出口监控、转发探测和组内互测的相关判定 |
| 出口延迟阈值 | 只作用于出口延迟监控；入口互测使用各自历史基线 |
| 入口可用性检测 | 组内互相检测入口服务，和出口探测分别提供证据 |

入口互测会连接组内服务端口，建立后立即关闭；没有 TCP 端口时改用 ICMP，ICMP 不通不直接视为异常。核对成员之间的安全组和防火墙，避免正常探测被当作扫描。

关闭入口互测会保留出口检测与控制连接判定，但入口状态未知时，不会自动恢复此前因入口异常摘除的地址。直接连接面板的成员也不会仅因控制连接断开就被摘除，还需结合独立健康证据。

## 查看状态与维护成员

组列表点击 **DNS 状态**，查看评估时间、观测标记、入口互测、出口证据及当前 DNS 决策。

| 状态或提示 | 处理方式 |
| --- | --- |
| 本组未开启 DNS 自动切换 | 回到组配置核对开关；自动加入启用不等于 DNS 切换启用 |
| 尚无评估 / 评估过期 / 读取失败 | 检查控制器与节点上报，不能按“健康”处理 |
| 互测学习中或证据不足 | 等待有效样本，检查成员数量、版本和互通性 |
| 多数成员同时异常，暂停摘除 | 排查共同网络原因，避免把面板链路异常当成所有业务入口故障 |
| 已达最少保留数 | 处理故障节点，保留数不能替代健康入口 |
| 创建组成功但出现 DNS 警告 | 重新打开组确认 DNS 是否实际启用，处理记录占用或配置问题 |

成员增减会触发组端口同步与清理。移除成员后，核对其组副本是否清理完成，并检查统一域名的解析结果。

删除组时注意“删除服务器 / 删除端口”等选项的范围。关闭 DNS 自动切换也涉及记录恢复与归属释放；遇到未知写入或交接阻塞时，按状态页核实，不能只看开关已关闭就认为外部 DNS 已处理完毕。
