# 弹窗禁止点击空白处关闭

## Problem Statement

运维人员在面板里填写表单（添加端口转发、编辑端点组、创建转发链等）或查看详情（安装脚本、DNS 状态、服务器详情等）时，鼠标稍一偏出弹窗点到遮罩，弹窗就直接关掉了：已填写的内容丢失，正在看的信息也要重新打开。现在只有少数编辑类弹窗在"保存中"才禁止点遮罩关闭，平时仍然一点就关；其余弹窗和业务抽屉完全没有防护。

## Solution

面板内所有弹窗（Modal，包括表单弹窗、只读详情弹窗、确认框）和业务抽屉，点击遮罩（空白处）一律不再关闭。关闭只能通过：右上角 ×、取消 / 完成等按钮、Esc 键。保存中这些关闭方式仍按现状禁用。移动端主导航抽屉是唯一例外，保持可点遮罩关闭。

## User Stories

1. 作为运维人员，我在"添加端口转发"弹窗里填了一半时误点到弹窗外的遮罩，希望弹窗不关闭，这样已填写的内容不会丢失。
2. 作为运维人员，我在编辑服务器组、端点、端点组、转发链时误点遮罩，希望弹窗保持打开，这样不用重新填写。
3. 作为运维人员，我在"批量导入端口转发"弹窗里粘贴了大段规则文本后误点遮罩，希望弹窗不关闭，这样粘贴的内容还在。
4. 作为运维人员，我在添加服务器、添加 DNSPod 账号、添加解析监控、解析器设置等弹窗中误点遮罩，希望弹窗不关闭。
5. 作为运维人员，我在查看安装脚本、DNS 状态、受管记录与地址、监听端口等只读弹窗时误点遮罩，希望弹窗不关闭，这样不用重新打开找位置。
6. 作为运维人员，我在换 IP / 自动轮换、地区与国内检测点、自检站点与参数、端点被墙处理、证书与凭据轮换等操作弹窗中误点遮罩，希望弹窗不关闭，这样操作进度和上下文不会中断。
7. 作为运维人员，我在删除服务器、删除转发链、吊销凭据、暂停端口等确认框弹出时误点遮罩，希望确认框不关闭，这样我必须明确选择确认或取消。
8. 作为运维人员，我在选择要绑定的 DNS 记录时误点遮罩，希望选择弹窗不关闭。
9. 作为运维人员，我在查看服务器详情、探针指标详情、自检与被墙认定、解析详情抽屉时误点遮罩，希望抽屉不关闭。
10. 作为运维人员，我想关闭弹窗时，希望点右上角 × 能关闭。
11. 作为运维人员，我想关闭弹窗时，希望点"取消""关闭""完成"等按钮能关闭。
12. 作为习惯用键盘的运维人员，我希望按 Esc 仍能关闭弹窗和业务抽屉，这样有意关闭时依然快捷。
13. 作为运维人员，在弹窗保存中，我希望 ×、Esc、取消按钮仍按现状禁用，这样不会在保存中途关掉弹窗。
14. 作为运维人员，在弹窗保存中，我希望点遮罩同样不会关闭弹窗（与平时一致）。
15. 作为移动端（≤860px）用户，我打开左侧主导航抽屉后，希望点遮罩仍能关闭它，这样导航体验符合常规移动端习惯。
16. 作为移动端用户，我希望主导航抽屉的其它关闭方式（关闭按钮、Escape、点菜单项、hash 变化、切换宽度）保持不变。
17. 作为面板开发者，以后新增的弹窗或抽屉默认就不能点遮罩关闭，这样不需要每次记得单独配置。
18. 作为面板开发者，我希望设计规范里写明这条交互规则，这样后续设计和评审有据可依。

## Implementation Decisions

- 在应用根部的 AntD 全局配置（ConfigProvider）上统一设定：Modal 与 Drawer 的遮罩不可点击关闭（`mask.closable = false`）。这是唯一的行为来源，新增弹窗自动继承。
- 删除各编辑类弹窗上现有的"保存中才禁止点遮罩关闭"的组件级设置（形如 `maskClosable={!saving}` / `maskClosable={!busy}` / `maskClosable={!removing}`），否则组件级设置会覆盖全局默认，使这些弹窗在非保存时仍可点遮罩关闭。涉及端口转发编辑、服务器组编辑、批量导入端口转发、端点编辑、端点组编辑、端点被墙处理、转发链编辑与删除确认、证书与凭据轮换。
- 保留这些弹窗上的 `closable={!saving}`、`keyboard={!saving}` 与取消按钮禁用逻辑，不改变保存中的现有行为。
- Esc 关闭行为不做全局修改：未设 `keyboard` 的弹窗维持 AntD 默认（Esc 可关闭）。
- 移动端主导航抽屉单独显式放开遮罩关闭（`mask={{ closable: true }}`），覆盖全局默认。
- `modal.confirm` / `modal.warning` 通过 App 上下文的 modal 实例调用，遵循同一全局配置；无需逐个修改。
- 在设计规范（DESIGN.md 的表单 / 弹窗规范处）增加一条交互规则："弹窗与业务抽屉不可点击遮罩关闭，只能通过 ×、取消/完成按钮和 Esc 关闭；保存中禁止关闭；移动端主导航抽屉除外。"
- 这是纯 UI 交互规则，不涉及领域术语，不更新 GLOSSARY.md；变更易于回退，不写 ADR。
- 不涉及后端、API 或数据结构变更。

## Testing Decisions

- 好的测试只验证外部可观察行为，不验证实现写法。本仓库前端只有基于 `node:test` 的纯数据测试（如 ChainsData、EndpointData、RulesData 的 `.test.mjs`），没有组件渲染或浏览器自动化基础设施；本需求不为此引入 jsdom / Playwright，也不新增源码扫描式测试。
- 用户决定本需求不做真实浏览器验收。
- 验证手段：前端类型检查与构建（`tsc -b && vite build`）通过，现有前端测试（`npm test` 及各 `.test.mjs`）保持通过。

## Out of Scope

- 关闭弹窗时对"未保存内容"做二次确认提示。
- 改变 Esc 键关闭行为（既不全局禁用，也不给目前未设的弹窗新增保存中禁用）。
- 改变移动端主导航抽屉的任何关闭方式。
- Popconfirm 气泡确认、Dropdown 菜单等非弹窗类浮层的点外部关闭行为。
- 新增前端组件测试或浏览器自动化测试基础设施。

## Further Notes

- AntD 版本为 6.7，`maskClosable` 在 v6 中由 `mask.closable` 取代；全局配置通过 ConfigProvider 的 `modal` / `drawer` 项的 `mask` 字段设置，组件级设置优先于全局。
- 工作区当前有与本需求无关的未提交改动（公网 IP 回退、规则文本导入）。本需求应在独立功能分支（如 `feat/modal-no-mask-close`）上实现，只包含本需求的改动，不推进 main。
- 实现交由 Codex 子代理编写。
