# 服务器组添加功能补齐与移除仅观测

Status: ready-for-agent

日期：2026-11-14

需求依据：本轮截图、需求访谈及用户“全部按推荐”的确认。本规格取代本轮原方案，作为本任务唯一正式规格。该状态表示规格已就绪，不代表用户已经授权修改代码。

## Problem Statement

管理员添加服务器组时，只能填写名称、发布模式和成员。截图中的 DNS 自动切换配置没有整合到添加流程：已有的 DNS 账号、域名和最少保留数需要在建组后另找入口配置；TTL 不能按组设置；入口互测、确认时长、探测失败比例及出口延迟阈值没有对应的完整实现。

服务器选择也缺少截图中的在线状态、双击快捷添加和拖拽排序等交互。管理员无法在添加时一次完成截图所示配置，也无法使用这些参数控制本组的 DNS 健康判断。

用户明确要求移除服务器组的仅观测功能，包括其已有入口和后台限制；其余需求严格限定在截图功能及这些功能实际生效所需的能力内。

## Solution

在服务器组添加表单中提供 DNS 自动切换、现有 DNSPod 账号与区域选择、必要的主机记录配置、TTL、最少保留数、入口互测、确认时长、探测失败比例及可选出口延迟判定，并补齐截图中的成员选择交互。

DNS 自动切换默认关闭，不配置 DNS 也能创建组。保存只持久化本地配置；管理员单独执行“首次发布”后才向 DNS 服务商写入。保留主备与全部发布两种模式，沿用受管记录和单一协调器的既有边界。

仅观测从服务器组界面、接口能力和后台限制中移除。新增检测证据只用于本组 DNS 判断，不增加自动换 IP 的触发条件。

| 配置 | 默认值及适用规则 |
| --- | --- |
| 发布模式 | 保留现有主备与全部发布选择，创建后不可更改 |
| DNS 自动切换 | 关闭 |
| 仅观测 | 移除，不提供开关或隐式限制 |
| DNS API 配置、DNS 区域 | 使用现有 DNSPod 账号和域名能力 |
| 记录 TTL | 60 秒，可配置 |
| DNS 最少保留数 | 1，仅全部发布模式显示并生效 |
| 入口可用性检测（组内互测） | 开启 DNS 自动切换后的默认配置为开启，可单独关闭 |
| 确认时长 | 180 秒 |
| 丢包率阈值 | 50%，含义为探测失败次数占总探测次数的比例 |
| 出口延迟判定 | 关闭；开启后默认填入 500 ms，可手动修改 |

## User Stories

1. 作为管理员，我希望在添加服务器组时看到截图中的相关配置，以便在同一流程内完成设置。
2. 作为管理员，我希望继续选择主备或全部发布模式，以便按现有方式组织入口。
3. 作为管理员，我希望界面说明发布模式创建后不可修改，以便在创建前作出正确选择。
4. 作为管理员，我希望 DNS 自动切换默认关闭，以便创建普通服务器组时不必配置 DNS。
5. 作为管理员，我希望只填写现有必填的名称、发布模式和成员即可创建组，以便不使用 DNS 的场景也能正常工作。
6. 作为管理员，我希望开启 DNS 自动切换后再校验必要的 DNS 配置，以便缺少配置时得到明确提示。
7. 作为管理员，我希望直接选择已有 DNSPod 账号，以便复用已有凭据配置。
8. 作为管理员，我希望选择账号可访问的 DNS 区域并填写必要的主机记录配置，以便明确管理哪个域名。
9. 作为管理员，我希望 DNS 列表读取失败时看到真实错误，以便区分读取失败与没有可选项。
10. 作为管理员，我希望记录 TTL 默认 60 秒并可修改，以便按组配置记录缓存时间。
11. 作为管理员，我希望首次发布及后续相关记录写入使用配置的 TTL，以便表单值实际生效。
12. 作为管理员，我希望仅在全部发布模式中配置最少保留数，以便不会把该参数误用于主备模式。
13. 作为管理员，我希望最少保留数默认 1 并遵循现有下限规则，以便自动摘除不会超出已约定的范围。
14. 作为管理员，我希望保存服务器组不写入外部 DNS，以便配置保存与实际发布清晰分开。
15. 作为管理员，我希望通过单独的首次发布操作开始写入 DNS，以便明确控制对外发布时机。
16. 作为管理员，我希望首次发布前不自动调整 DNS，以便未发布的配置不会提前影响真实记录。
17. 作为管理员，我希望首次发布失败或部分完成后保留组和配置，以便查看真实结果并继续处理。
18. 作为管理员，我希望 DNS 状态区分保存成功、服务商写入结果和实际解析观察，以便不会把保存成功误认为域名已经生效。
19. 作为管理员，我希望开启 DNS 自动切换后入口互测默认开启，以便获得组内入口服务的探测证据。
20. 作为管理员，我希望可以单独关闭入口互测，以便在不允许成员互相探测的网络环境中使用其他已有检测。
21. 作为管理员，我希望入口互测连接实际入口服务 TCP 端口并在连接建立后关闭，以便检测入口服务的可连接性。
22. 作为管理员，我希望没有 TCP 服务端口时使用 ICMP，且 ICMP 不通不能直接判为入口故障，以便不会把禁 ping 误认为服务异常。
23. 作为管理员，我希望开启入口互测时看到防火墙、安全组和探测注意事项，以便理解探测会产生什么网络连接。
24. 作为管理员，我希望确认时长默认 180 秒，以便短暂故障或短暂恢复不会立即改变确认状态。
25. 作为管理员，我希望持续不通和持续恢复各达到确认时长后才确认状态变化，以便避免 DNS 因瞬时结果反复调整。
26. 作为管理员，我希望丢包率阈值默认 50% 并可设置，以便指定探测失败比例的判定门槛。
27. 作为管理员，我希望帮助说明明确该比例是探测统计，以便不会把它误解为业务流量真实丢包率。
28. 作为管理员，我希望出口延迟判定默认关闭，以便未启用的延迟门槛不参与 DNS 判断。
29. 作为管理员，我希望开启出口延迟判定后自动填入 500 ms，以便不必先手动输入就能使用默认门槛。
30. 作为管理员，我希望可以手动修改已启用的出口延迟阈值，以便使用其他门槛。
31. 作为管理员，我希望关闭出口延迟判定后其他已启用检测仍有效，以便不同检测条件可以独立控制。
32. 作为管理员，我希望探测失败比例或已启用的出口延迟持续超标两倍确认时长后才确认劣化，以便短时网络波动不立即触发调整。
33. 作为管理员，我希望出口延迟阈值只用于出口检测，以便不会误作入口互测的固定延迟门槛。
34. 作为管理员，我希望缺失、过期或不足的检测证据显示为证据不足，以便不会把没测到当作健康或故障。
35. 作为管理员，我希望单成员组无法互测时不凭空产生故障结论，以便单成员组仍可使用。
36. 作为管理员，我希望多数成员同时异常时暂停依据这些结果调整 DNS，以便保留共同异常的含义。
37. 作为管理员，我希望证据不足时不自动恢复已摘除成员，以便不把未知结果当作恢复证据。
38. 作为管理员，我希望主备继续按现有活动入口方式切换，全部发布继续按成员摘除和加回，以便保留现有发布模式含义。
39. 作为管理员，我希望关闭 DNS 自动切换时保留记录和绑定并继续检测，以便暂停健康驱动的自动调整而不清空配置。
40. 作为管理员，我希望关闭 DNS 自动切换后仍能手动发布，以便保留明确的手动操作能力。
41. 作为管理员，我希望受控换 IP 成功后的地址同步继续执行，以便域名不会因为关闭健康自动切换而指向旧 IP。
42. 作为管理员，我希望新增检测参数不增加自动换 IP 的触发条件，以便本次功能只改变约定的 DNS 判断。
43. 作为管理员，我希望服务器组不再提供仅观测功能，以便添加表单、列表及 DNS 状态保持一致。
44. 作为管理员，我希望既有观测状态不再形成隐藏的后台限制，以便移除功能后不会继续抑制自动动作。
45. 作为管理员，我希望在双栏成员选择器中搜索、选择及查看在线状态，以便快速找到需要加入的服务器。
46. 作为管理员，我希望使用 Shift 多选及双击快捷添加，以便减少批量选择成员的操作次数。
47. 作为管理员，我希望通过上下移动和拖拽调整已选成员顺序，以便表达组内优先顺序。
48. 作为管理员，我希望反复选择不会生成重复成员且保存后顺序保留，以便显示顺序与实际主备顺序一致。

## Implementation Decisions

1. 界面“服务器组”继续对应领域模型“入口组”。沿用既有受管记录、发布模式、就绪和最少保留数定义，不另造一套 DNS 归属或发布模型。
2. 修改现有服务器组添加表单、成员选择组件、入口组保存与查询能力，以及本组 DNS 配置、检测采样上报和协调决策所需模块；仅观测移除涉及其已有列表与 DNS 状态入口。常规编辑流程不额外重设计。
3. 入口组配置持久化 DNS 自动切换状态、待绑定的 DNS 选择、TTL、入口互测状态、确认时长、失败比例阈值、出口延迟判定状态及阈值；最少保留数复用现有能力。保存与读取必须保留用户值，不允许前端展示可配置、后端实际忽略。
4. 创建接口接受添加表单中的配置，并在同一次本地保存中完成参数和成员校验。DNS 自动切换关闭时不要求完整 DNS 配置；开启时必须具备可用的必要选择。非法配置返回明确错误，不静默使用另一套值。
5. 保存阶段的 DNS 选择属于待绑定配置，不得显示成已确认的受管记录，也不得因保存而新建、接管、改类型、启用或修改外部记录。允许沿用已有只读列表和校验能力。
6. 首次发布时再执行必要的既有受管记录解析和绑定流程，然后执行发布。新建记录先暂停；类型不符时沿用管理员确认规则；不删除服务商记录。结果未知时沿用读回核对，不能盲目重复创建。
7. 保留 ADR 0008 的既有独立绑定语义：本次添加流程只是延后调用绑定，不把“已保存待绑定配置”改称“已绑定”。保存与外部首次发布不能承诺跨本地存储和 DNS 服务商原子完成；失败后保留真实的本地和远端进度。
8. 发布模式仍为创建时选择、以后不可更改。主备继续支持既有 A/CNAME 约束；全部发布使用成员 A 记录；CNAME 成员条件和受管记录唯一归属规则保持有效。
9. 组内受管记录的相关 DNS 写入采用已保存 TTL。最少保留数只对全部发布生效：默认及最小为 1，超过成员数按成员数处理，沿用自动摘除下限及手动操作的既有约束。
10. 所有发布、切换、回切、摘除、加回及地址同步继续通过面板的既有协调能力处理。遵守 ADR 0005、0007：持久化动作与版本、核对迟到结果、保持记录启停状态，并在适用时先确认目标记录启用再暂停最后一条原启用记录。
11. DNS 自动切换关闭后，停止健康异常触发的自动切换、回切、摘除与加回；保留已有记录及绑定，继续检测，允许既有手动发布。受控换 IP 后的地址同步继续，保持各记录原有启停状态。不能将其实现为保留仅观测功能但换一个名称。
12. 彻底移除服务器组的仅观测开关、可启用观测的接口能力及后台抑制逻辑；已有观测值不得继续阻止 DNS 自动动作或相关节点原有自动换 IP。保留其他权限、额度、冷却、维护、就绪和手动限制，不因移除观测而新增动作触发条件。
13. 入口互测是组内成员连接其他成员入口服务的检测，不等同于控制连接在线、国内检测点专用端口检测或已有就绪判断。TCP 建连成功后立即关闭，不发送业务数据；无 TCP 服务端口时回退 ICMP，ICMP 不通本身不能构成入口故障证据。
14. 实现真实采样、结果上报及组级判断。已有 TCP 成功和耗时数据形状可以复用，但不能把缺少组归属、样本窗口或出口耗时的旧上报直接当成完整能力。采样应能区分本组、被测成员、用途、当前地址及有效时间；过期或不适用于当前对象的结果不能参与当前判断。
15. 丢包率字段的业务口径是有效探测中失败次数占总次数的比例，界面保留截图用途并用帮助说明澄清含义。无有效探测时状态为未知，不能视作零失败或全部失败；未完成或无效的采样不能冒充已测得的连接失败。
16. 新检测的持续不通和持续恢复分别达到确认时长才确认；失败比例或已启用的出口延迟持续超标达到两倍确认时长才确认劣化。默认分别为 180 秒和 360 秒；连续性中断或有效证据不足时，不得仅凭时间经过跨过确认门槛。
17. 出口延迟判定是独立开关，默认关闭。开启时默认值为 500 ms，用户手动输入后使用其输入值；关闭时忽略该阈值。它只用于出口检测，不作为入口互测的固定延迟阈值。
18. 新检测的确认时长不机械替换既有控制离线时限、被墙自测轮数、就绪要求或回切驻留约束。新增证据通过现有发布模式消费，恢复和候选发布仍需满足对应的既有条件，不能绕过手动摘除锁或回切暂停。
19. 缺失、过期、单成员无互测证据等情况不得直接判健康或故障；多数成员同时异常时保留共同异常含义并暂停依据这些结果调整 DNS。该限制不将其他独立且有效的既有证据改判为成功或失败，也不能用未知证据自动恢复已摘除成员。
20. 新参数仅参与本组 DNS 健康判断。遵守 ADR 0004，保留自测为主的被墙判定及已有换 IP 授权流程，不能用高延迟或探测失败比例直接替代被墙证据。
21. 成员组件保留双栏、搜索、选择及上下移动，补齐在线状态、Shift 多选、双击快捷添加和拖拽排序。成员不重复，新增成员不意外替换现有首选入口，排序保存后保持一致；沿用既有端口冲突、引用和成员移除限制。
22. 现有配置版本与旧报告隔离遵守 ADR 0006。新检测状态不能把旧地址、旧配置或旧连接的报告冒充当前结果；在线状态也不能冒充入口就绪或业务目标可用。
23. 旧规格和术语中仅观测的保留描述与本次明确移除要求冲突，以本规格为准。实施时只同步必要的产品说明和既有领域文档，不生成额外规格、审查报告或日志。

## Testing Decisions

1. 主要复用现有 clusterharness 集成测试边界：通过面板管理 HTTP API 创建和读取组，让真实节点或可控节点报告提供证据，通过现有假 DNS 服务商观察外部记录变化。优先在这一条完整行为链上验证，不为每个内部判断函数新建测试接口。
2. 好的测试验证管理员可观察的结果：创建与校验是否成功、配置读取是否一致、发布和检测状态是什么、DNS 哪些记录被写入或保持不变。避免断言私有函数调用顺序、内部字段排列或仅复制实现条件。
3. 采样所需的可控网络结果优先通过现有节点依赖注入和网络测试能力提供；时间窗口通过现有可控时钟推进，避免真实等待 180 或 360 秒。若需补充依赖，只在节点网络探测的外部边界提供，不暴露内部评估器专供测试。
4. 创建与持久化测试覆盖两种发布模式、无 DNS 创建、默认值、自定义值、必要配置缺失、参数不合法、保存后重新读取及重启后保留。既有成员顺序持久化和必填、重复、冲突校验作为先例。
5. DNS 生命周期测试覆盖保存不产生外部写入、首次发布才绑定及写入、未首次发布不自动调整、按组 TTL 生效、只改受管记录、已有记录接管、类型确认、明确失败、部分完成和未知结果读回。先例包括现有受管 DNS 首次发布、丢失响应核对和重启恢复测试。
6. 使用可控时间和探测结果验证不通与恢复确认门槛、失败比例或延迟劣化门槛、连续性中断、延迟开关默认关闭、500 ms 默认阈值及用户自定义阈值。验证门槛前后可观察状态和 DNS 结果，不锁定内部调度次数。
7. 验证 TCP 探测建立后关闭、无 TCP 时 ICMP 回退、ICMP 不通不直接判故障、探测失败比例口径、无有效样本、过期及旧对象报告失效。已有出口健康测试中“未完成不算链路失败”和连续恢复窗口是相关先例。
8. 验证证据不足、单成员和多数成员共同异常不会依赖该类结果调整 DNS，未知结果也不会自动加回已摘除成员。两种发布模式均覆盖相关结果。
9. 验证自动切换关闭后停止约定的健康自动动作、保留记录及绑定、继续提供检测结果、手动发布仍可执行、受控换 IP 地址同步继续并保持记录启停状态。复用现有入口切换、回切、全部发布及换 IP 收尾集成用例。
10. 仅观测原有测试作为移除范围的清单：添加、列表和 DNS 状态不再提供该能力，接口不能再启用观测，旧观测值不再抑制组或共享节点已有合法自动动作。测试同时确认其他独立限制仍有效，而非删除整类自动动作回归覆盖。
11. 成员顺序和去重复用现有成员选择行为测试。在线标识、Shift 选择、双击添加、拖拽、上下移动及保存后顺序通过实际页面交互核对；现有前端测试主要覆盖选择函数，不能把函数测试声称为已覆盖全部浏览器交互。
12. 本次仅整理规格，不执行功能测试或声称实现已通过。实施时运行受影响的集成测试、必要前端测试及构建检查；文档检查仅证明本规格结构和范围已核对。

## Out of Scope

- 新 DNS 服务商、Webhook 接入及多服务商扩展。
- 独立延迟监控页面、监控平台或与截图无关的新菜单。
- 自动加入模板、安装脚本链接、权限与带宽配置等截图外功能。
- 常规编辑流程重设计、运行中切换发布模式及规则体系重构。
- 重新设计旧组的检测规则迁移；仅保留实施所必需的兼容处理及本次明确要求的仅观测清理。
- 改写被墙判定，或用本次失败比例、延迟、入口互测新增自动换 IP 触发条件。
- 将探测失败比例描述为真实业务流量丢包率，或把入口就绪描述为已验证最终目标可用。
- 删除 DNS 服务商记录，或保存组时自动向外部 DNS 写入。
- 本次直接实施、部署、推送远程、创建 Git worktree，或生成本规格之外的辅助报告、日志与重复方案。
