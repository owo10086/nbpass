# 列表排序与多选批量操作

Status: ready-for-agent

## 背景

规则、入口组、出口组按随机 id 排序，节点按添加时间排序且前端把离线节点排到最后，管理员无法自定顺序；规则页的多选只给导出用，启停/删除只能逐条操作，每条都会重新编译快照、涨一次配置版本。

## 范围

| 页面 | 点表头排序 | 拖拽排序（保存） | 多选批量 |
|---|---|---|---|
| 转发规则 | 名称、入口、监听端口、目标、状态、同步状态、流量、连接数 | ✓ | 启用 / 停用 / 删除 + 已有导出 |
| 节点 | 补名称、状态、地区、最近活性（保留现有 4 列） | ✓ | 维护 10 分钟 / 结束维护 |
| 入口组、出口组 | 名称 | ✓ | 不加 |
| 故障、事件 | 不加 | | |

节点批量不做删除/吊销/升级：删除有逐个校验流程，批量风险大、收益小。

## 约束

- 显示顺序只在列表视图里调整；`loadRules` / `loadExitGroups` / 快照编译路径的顺序不动，否则节点配置版本会无故递增。
- 保存顺序（`PUT /api/{rules|nodes|entry-groups|exit-groups}/order`）不碰快照和配置版本；ids 与当前全集不一致返回 409。
- 规则批量（`POST /api/rules/batch`）整批一次事务、只编译一次快照；任一 id 不存在或配置校验失败整批回滚。

## 验收

- 迁移后原有顺序等于插入顺序；保存顺序后 `GET` 按新顺序返回且节点 `desired_revision` 不变。
- 批量停用 3 条规则，节点期望配置版本只 +1。
- 列排序或筛选生效时拖拽手柄置灰；恢复自定义顺序后可拖。
- 节点多选批量维护，结果汇总成功/失败数。
