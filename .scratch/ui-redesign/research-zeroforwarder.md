## 表单写法（真实截图）

- 弹窗或抽屉内按区块分组，每块有图标加区块标题，例如「基本信息」「转发配置」；区块可以折叠。
- 标签右对齐，旁边带「?」提示；字段下方是灰色说明文字，例如「服务端口，留空表示自动分配」。
- 转发模式用分段按钮切换：「直连 / 单跳转发 / 链式转发 / TOT 聚合」，选中项填充强调色。
- 备用线路是一张张编号卡片（#1、#2），左边有拖动手柄，右上角是红色文字按钮「删除」，底部是「+ 添加 fallback」；区块标题旁用数字徽标显示卡片数量。
- 规则语义用醒目的提示条说明，例如琥珀色的「热备语义：成员常驻多客户端」；端口级显示「冷备」，并给出预估：约 30 秒切换、约 5 分钟回切。
- 组成员用左右两栏穿梭框选择：「可选 / 已选择的组」，栏头带计数，已选行带序号（01、02）和拖动手柄；右上角写着操作提示：「拖拽行排序 · 点击序号可跳转位置 · Shift+点击多选 · 双击快速添加」。
- 视觉上是深色底（接近黑的藏青），只有一个橙色强调色，用在主按钮、开关、选中项和计数上；数字用等宽字体。

## 可观测性（营销示意图，不是真实截图）

- 故障看板：
  - 顶部三个指标：「在线节点 42/43」「24 小时新增告警 3」「已自动恢复 2」。
  - 下面是事件流，每条事件后面跟着处理结果标签，例如「Telegram 已通知」「已切换线路」「自动恢复」。
- 连接监控：
  - 把链路按「客户端 → 入站 → 中转 → 中转 → 目标拨号 → 目标」逐段画出来，每段标注成功率；出故障的那一段高亮，并写明原因（例如「71.4% 建连超时」）。
  - 下方分两行：自动处理（「已切到 ix-b」）和手动操作入口（「暂停线路 · 查看异常明细」）。
- 服务器组 DNS：逐条列出 A 记录的 IP 和状态，例如「在线」「丢包，已摘除」。
- 实时日志：按节点滚动显示，带 INFO/WARN 级别，一行一条事件。

## 对 nbpass 的启发

1. 概览页可以做成「故障看板」：上面放几个关键指标，下面放最近自动动作流，每条写清「判定 → 动作 → 结果」。这和 PRODUCT.md 的「状态先于操作」「如实解释」两条原则一致。
2. 入口组页可以像服务器组 DNS 示意图那样，直接列出成员与受管记录：每个 IP 的状态，以及因何被摘除或切换。
3. 隧道规则可以按链路逐段展示：入口 → 出口组（主/备）→ 目标，并标出故障发生在哪一段。
4. 表单规范可以借用：区块分组、字段说明、模式用分段按钮；出口组的主备顺序用编号卡片加拖动来排。
5. 缺口：它的列表页没有任何公开证据，表格怎么组织要看其他参考面板。
