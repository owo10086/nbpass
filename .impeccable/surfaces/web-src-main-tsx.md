# nbpass 管理面板（应用外壳、概览、节点页，及其余页面）

模式：Operate。使用者：唯一管理员，桌面浏览器，10–50 节点、上百条规则；巡检与配置并重。约束：只改前端，不加 API；状态只取 API 给出的字段，前端不推算。

## Direction contract

THESIS：同类管理后台的标准做法，做到 Vercel / Linear 控制台的精度：白底、1px 细线、克制的字号阶梯、状态先于操作。拒绝 AntD 默认的大圆角卡片堆叠、深色菜单和空欢迎页。

OWN-WORLD：白色工作区，侧栏是比工作区略冷的浅灰，以 1px 线分隔；正文近黑，次级文字中性灰；唯一强调色是一种蓝，只用于主操作、选中项和链接。状态用小圆点加文字表示：绿色表示正常，琥珀色表示处理中或待定，红色表示需要人工，灰色表示离线或未知。圆角统一 6px，表格紧凑（行高约 40px），表头用浅灰小字。数字使用 tabular-nums；IP、端口、版本号用等宽字体。

STORY：打开面板即看清哪里异常、自动处理做了什么、结果如何；从异常一步进入对应节点或入口组处理；常用变更（加节点、建规则）在页面右上角一个主按钮内完成。

FIRST VIEWPORT：
- 外壳：左侧约 220px 浅色导航，分「转发、监控、设置」三组，带数量；顶栏约 56px，放页面标题、数据刷新时间和账户菜单。
  - 改编（已采用）：用户选定的 canon 方案没有独立顶栏，按 Linear 的做法实现——页面标题与刷新时间放在每页内容顶部的页头，账户菜单固定在侧栏底部。省掉一条常驻横条，内容区多出约 56px 纵向空间；窄屏时侧栏转为顶部横向导航，账户入口随之上移。
- 概览：顶部一行四个指标（节点在线、需要处理、配置未同步、转发规则），每项都可点击跳转；下面左侧是「需要关注」列表，每条为状态点、对象、API 给出的原因和跳转；右侧是最近事件。
- 节点页：工具栏（搜索、状态筛选、刷新、主按钮「添加节点」）加紧凑表格；低频操作收进行尾的「更多」菜单。
- 签名交互：从概览任一关注项或指标跳到对应页面，目标行短暂高亮。动效 150–200ms，只用于表达状态。
  - 实现：高亮是状态而非动画——目标行立即着色，保持约 2.4 秒以便在跳转滚动后被看见，随后在 150ms 内淡出。
