# 专线地址挂在服务器上，转发链是端点组的顺序

IX / 专线场景需要「A 经专线连 B，再由 B 连目标」，并可能多跳。Zero Forwarder 的做法是端点、端点组、转发链分层，再加智能选择、固定前/后 N 跳和服务器级「使用转发端点作为传输」开关：灵活，但端点地址可以填别的机器、哪些层必经要靠跳数锁定，管理员很难看懂。Forwardx 把地址挂在主机上（入口 IP + 内网地址），建隧道就是按顺序选主机、每跳选连对方哪个地址，概念少。nbpass 的转发端点本来就是「一台服务器上的隧道入口」，与 Forwardx 的主机模型同构，因此采用 Forwardx 的思路。

具体为：服务器除自动维护的公网地址外，可登记多条专线地址（IPv4 或域名，可带对外端口以表达 NAT / 专线端口映射）；端点组成员是「服务器 + 地址」；转发链是按顺序的端点组，单跳转发就是一跳的链。每一跳都必经，组内按主备选健康成员，每台服务器只对下一跳做健康检查与切换。另加服务器可选的出站源 IP，连最终目标时绑定——Forwardx 的「主 IP」并不约束出站源地址，我们显式做。

## Consequences

- 不做智能选择、固定跳数和服务器级默认传输；路径完全由端口所选的端点组 / 链决定，所见即所走。
- 专线地址由管理员维护，换 IP 只更新公网地址，不再覆盖手填地址（修正现有行为）。
- 端点地址支持域名后，由前一跳节点解析，地址变化不经面板确认；健康检查按实际连接结果判断。
- 一条完整路径里同一台服务器不能出现两次；新增校验按保存变更影响的规则范围执行，未受影响的历史规则按原语义编译，不阻塞无关保存、重连或授权确认。监听占用按实际监听者计算；单跳/链式目标回指按所有可能末跳展开。
- 新能力依赖新版节点，域名/对外端口拨号与成员地址身份分别检查能力。能力不足导致无完整可用路径时提示整条阻塞、需升级；仅备用不足时保留可运行状态和具体 blocker，升级后重新确认才纳入候选。
- 下游不可达保留真实失败边，上游在同一建流总预算内尝试同组下一个健康成员，本边健康不因下游失败判坏。控制离线或公网被墙不等于专线业务中断；各跳证据接入既有 operations/incidents，外部动作仍走 ADR 0005 协调者。
- 节点缓存回滚采用 A（2026-11-12 用户已定）：一次发布、不做过渡版，新写格式为 2，读取支持 1/2；同一 `config.enc` 的外层 `version: 2` 使真实旧读取器的严格格式 1 检查在 Restore 前拒绝。旧版拒绝后退出停转发，人工隔离不兼容缓存并空状态重启，直到重连取得能力内配置才恢复；跨格式升级经现有同身份重新安装流程替换节点及独立更新器，不假定旧在线更新器放行。接受离线回滚中断；只有一个生产面板、服务器少、降级罕见，未选 B。必须以真实旧读取代码/旧二进制验证 relay、源 IP 和撤销检查点不会越跳、丢绑定或复活；实现与验收细节见 `.scratch/ix/spec.md`「已定决策」7。
- 管理连接经中转、UDP、IPv6 不在本 ADR 范围。
