# 入口组发布模式建组时选定，全部发布用暂停启用现有记录

参考 ZeroForwarder 服务器组：它的组域名同时解析到所有健康成员，异常的摘除，设最少保留数。nbpass 原有的主备（单个活动入口、首选入口回切）能保证平时只走优质入口，全部发布则能让成员分摊流量，两者都有用，所以按入口组选择发布模式。模式只能在建组时选，之后不能更改：切换时记录数在 1 条和 N 条之间变化，还要和在途的入口动作、回切、被墙策略衔接，代价远大于"新建一个组再改规则入口"。全部发布时每个成员绑定一条管理员在 DNSPod 预先建好的同名记录，摘除就是暂停记录、加回就是启用；面板不新建也不删除记录。这样延续了"面板只改受管记录、不动其他记录"的权限边界，记录 ID 保持稳定。代价是每加一个成员就要先手动建一条记录，并且受 DNSPod 套餐对同名同线路同时启用记录条数的上限约束（启用时可能被拒绝）。

## Consequences

- ADR 0005 的协调器仍是唯一写入者，但动作的对象从"一个入口组"变成"一条受管记录"：每个动作锁定记录身份与绑定代次，旧值、新值、启用状态逐条持久化、逐条核对；组级期望版本保留，用来让过时的自动动作失效。
- DNSPod 改值的接口在不传状态时默认启用记录，因此单纯改值必须显式保持原启用状态；启用须由明确的首次发布或加回步骤完成，不得依赖改值接口的默认行为。
- 多条记录不能原子修改，所以发布和状态调整先启用、后暂停：确认至少一条目标记录已启用后，才暂停最后一条原有启用记录。

> 部分被 [ADR 0008](0008-panel-creates-records-and-cname.md) 取代：面板现在可以新建受管记录，全部发布成员不再要求预建记录。
